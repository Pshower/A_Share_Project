# 阶段四：PPO 智能体与训练框架实施计划

日期：2026-09-25

状态：规划完成，代码与训练待实施。本次仅编写实施前计划，不安装依赖、不启动训练、不评估测试集。下文模块、命令与参数均为拟实现设计，不代表已经可运行或已验证。

## 1. 目标与边界

在阶段三的离线研究闭环上接入 PPO，实现从标准化行情观测到组合目标权重的决策，复用已有成交模拟、账户记账和回测指标。

- 首版为日频、单智能体、仅做多、无杠杆、允许持有现金的组合配置策略。
- 使用本地 `research_v3`，不重新下载行情，不修改原始数据。
- 使用成熟 PPO 实现，首版共享 MLP，不引入循环网络、Transformer、多智能体或实盘下单。
- 实现训练入口不等于启动训练。首次参数更新、训练冒烟和正式训练都留待用户明确要求。
- 当前价格为 `hfq_research`，只能得到同假设下的研究结果，不能声称是真实交易收益。

## 2. 智能体的功能与行为

### 2.1 看什么

复用 `TradingEnv` 的字典观测：

| 字段 | 含义 | 首版用途 |
| --- | --- | --- |
| `stock_features` | `[股票数, lookback, 特征数]`，当前为 20 个相对特征 | 每只股票使用同一个 MLP 编码 |
| `portfolio` | 各股票当前权重和可用现金比例 | 感知持仓及资金占用 |
| `receivable_ratio` | 应收分红占净值比例 | 区分应收资产与可用现金 |
| `valid_mask` | 当前特征窗口有效性 | 禁止基于无效特征新增买入 |
| `buy_mask` / `sell_mask` | 当前已知的方向约束 | 决策输入及目标买入资格筛选 |

模型不读取下一日开盘价、收盘价或成交量，也不读取未来交易状态。特征缺失填零必须同时保留掩码，不能把缺失当成真实的零信号。

模型输入沿用训练区间拟合的标准化参数，不在验证、推理时重新拟合，不叠加另一套在线观测标准化。首版 `lookback=1`，已有动量、波动等特征包含历史信息。

入参用股票数 `N` 表示，不把 298 写死在网络中。以下形状不包含训练框架添加的 batch 维度：

```text
stock_features:   [N, lookback, 20]
portfolio:        [N + 1]            # N 个股票权重 + 可用现金比例
receivable_ratio: [1]
valid_mask:       [N]
buy_mask:         [N]
sell_mask:        [N]
```

当前数据对应 `N=298`，是数据配置而不是模型必须接收的股票数。原始股价、账户金额和持仓股数不直接进入首版模型，由交易环境保存并用于成交和记账。模型接收相对特征和账户比例，这有利于减少价格尺度差异，但无法完整感知绝对资金规模与整手交易造成的影响；该限制需保留在评估中。

### 2.2 做什么

每个交易日收盘生成下一交易日的目标股票权重和目标现金比例。由已有环境在下一日开盘尝试调仓，并在下一日收盘估值。

**动作的业务含义是“希望持有多少”，不是直接选择买入/卖出标签。买卖行为由目标与现有持仓的差额产生。** 网络先输出股票与现金分数，映射层生成合法权重，执行器再产生订单。

例如账户净值为 100 万元、股票 A 当前市值为 3 万元，暂不考虑隔夜价格变化和交易成本：

| 目标动作 | 交易意图 |
| --- | --- |
| A 的目标权重为 5% | 尝试买入约 2 万元 |
| A 的目标权重为 1% | 尝试卖出约 2 万元 |
| A 的目标权重为 0% | 尝试清仓 |

实际订单在下一日开盘根据当时的价格和账户重新计算，不能直接使用上述收盘差额作为确定的成交金额。环境接收 `N` 个股票目标权重，剩余比例为现金；例如两只股票的目标为 `[0.05, 0.03]`，则目标现金为 `0.92`。

“不下单、继续持有”与“恢复原来的权重比例”不同：后者在价格变化后仍可能触发买卖。首版没有独立的 PPO 不下单动作，只有外部调仓日程可以直接跳过订单。

- 可以增仓、减仓、换仓或提高现金占比；不输出股数、订单价格或直接修改账户。
- 默认每天决策。按日历跳过调仓时必须调用 `advance()`；重复提交当前权重并不等于不交易。
- 首版不额外学习离散的“不下单”动作。小额调仓可能因整手或资金约束不成交，必须在报告中区分主动决策与成交失败。
- 目标合法不保证实际持仓达到目标。T+1、整手、现金、涨跌停及成交量限制仍由 broker 执行。
- 当前买入掩码不保证下一日可成交，下一日开盘由环境重新检查，不能把下一日状态提前给模型。

### 2.3 提供哪些接口

| 拟实现接口 | 职责 |
| --- | --- |
| `act(observation, deterministic=True)` | 生成可交给现有环境的股票目标权重 |
| `inspect_action(observation)` | 返回潜在动作、映射后权重、现金比例及掩码诊断，不宣称解释了收益因果 |
| `validate_observation(observation)` | 核验形状、有限值、特征顺序和数据契约 |
| `save(path)` / `load(path)` | 保存和校验模型、配置及数据契约，拒绝不兼容加载 |
| `reset()` | 明确无循环状态的首版接口，支持统一回测调用 |

训练由独立入口负责，不允许 `act()`、加载模型或回测时隐式更新参数。

## 3. 动作如何变成合法权重

现有 `TargetWeightSpace` 虽然限制单票和权重和，但 PPO 的高斯采样不会因为空间自定义了 `sample()` 就自动满足这些限制。因此增加专用动作适配层，不放宽原环境的校验。

1. 策略输出 `N+1` 维潜在连续动作：每只股票一个分数，现金一个分数。
2. 对外声明有限的潜在动作 Box，拟定范围 `[-8, 8]`，使用框架一致的裁剪路径；记录裁剪比例以识别饱和。
3. 对 `valid_mask & buy_mask` 不满足的股票屏蔽分数，再与现金分数一起进行数值稳定的 softmax。
4. 将各股票 softmax 权重截到 broker 的 `max_weight`，超出部分保留为现金，不再反复分配。
5. 现金权重定义为 `1 - sum(stock_weights)`。全无效时输出全现金目标，所有结果必须有限、非负、单票不超限且总和不超过 1。

屏蔽不能买入的已持仓股票意味着请求减仓或退出，不表示已经卖出；若禁止卖出，实际持仓仍保留。目标现金和实际现金分别记录。首版接受这一保守映射，不将其描述为最优约束投影。

**PPO 概率计算约定：** rollout 保存采样的潜在动作及其原始 log probability；环境执行经框架裁剪和权重映射后的动作。更新仍针对同一潜在动作计算概率，不能把映射后的权重当成高斯动作重新计算 log probability。该映射不可逆，也无需求逆；策略熵是潜在动作熵，不是组合权重熵。

适配层只有一个权重映射实现，训练包装器和独立智能体推理共同调用，避免训练与回测映射不同。

## 4. 网络结构与跨股票泛化

采用 PyTorch 定义共享网络，Stable-Baselines3 提供 PPO 更新、rollout、GAE 和优化过程。具体依赖版本在实现时核验兼容性并锁定，不在本次计划中虚构已验证版本。

```text
每只股票：历史相对特征 + 当前权重 + 有效/买卖掩码
                  |
            共享股票 MLP（拟定 128 -> 64）
                  |
       股票嵌入 + 对股票集合的池化上下文
                  |
     +------------+------------------+
     |                               |
共享股票评分头                  组合上下文 + 现金/应收
每只股票一个均值                 现金评分头 / 价值网络
     |                               |
     +---- N+1 维连续动作分布 --------+
                  |
             合法目标权重映射
```

- actor 使用共享股票评分头，critic 使用池化后的组合上下文；不能仅替换特征提取器后继续使用固定槽位的全连接 actor。
- 不把股票代码作为特征，不为每只股票设置专属可学习参数。股票动作的 log standard deviation 也共享，现金可单独配置。
- 池化区分有效行情与持仓信息；即使某只股票行情无效，其冻结持仓也不能从账户上下文中消失。
- 编写自定义策略适配类，接入框架的前向、价值预测、动作分布和 `evaluate_actions` 契约，不自行重写 PPO 算法。
- 测试同一股票集合重排时，确定性股票动作随之重排，现金与价值预测不变。

### 4.1 股票数可变，网络参数共享

设计目标是：**训练期间固定股票池维度，网络参数不绑定股票身份；扩大股票池时复用参数，并单独验证效果。**

- 网络逐只处理股票，不将整个 `[N, lookback, 20]` 展平成绑定 N 的全连接输入；只展平单只股票的时间和特征维度。
- 股票编码器、股票评分头及股票探索方差共享；组合上下文使用固定维度的掩码均值池化，现金头与价值头也不依赖 N。
- 从 298 只扩大到 500 只时，同一编码器和评分头多处理 202 只股票，输出由 299 个潜在动作变为 501 个，不新增股票专属可学习参数。
- 股票代码仅用于输入对齐、订单归属和审计，不参与打分。每次运行仍须固定并记录股票顺序。

### 4.2 框架维度与股票池迁移

网络支持不同 N，不表示原训练对象能直接接受不同形状。首版每个 PPO 训练实例的观测空间、动作空间和 rollout 维度固定，当前配置为 298 只股票；不在单个 rollout 或 episode 中途改变股票数。

扩大股票池时按以下流程处理：

1. 准备新股票的同定义特征，沿用训练时的特征顺序、窗口和 scaler，检查数据口径与有效性。不为适应新股票而使用验证或测试数据重新拟合。
2. 按新股票池创建环境和策略对象，重建相应维度的动作分布与缓冲区。
3. 显式迁移共享编码器、股票评分头、共享方差、现金头和价值网络参数；核验参数形状不依赖股票数。普通 `load()` 仍严格校验原契约，不静默忽略股票池差异。
4. 单独保存迁移来源、新股票池及数据契约。推理检查不更新参数；若后续要求微调，使用新的优化器和 rollout，作为新实验记录。
5. 先进行无梯度接口与动作合法性检查，再在允许的验证区间评估。不能承诺直接将 500 只股票传给原 298 维对象即可运行。

### 4.3 能处理新股票不等于泛化有效

共享参数仅提供结构上的可迁移性。新股票可能具有不同的特征分布、流动性与交易限制；股票数扩大还会改变 softmax 的竞争和现金比例，同一只股票的分数不变也不保证权重不变。首版不承诺资金分配对股票池规模不敏感，需要报告不同股票池规模下的现金、集中度与成交率。

当前 scaler 配置使用全股票池的训练期数据，不构成“未见股票”实验。后续要验证跨股票泛化，必须预先划分训练股票与留出股票，重新构建仅用训练股票拟合的 scaler，并分别限制环境股票池；`train_codes` 只控制 scaler 拟合，不能替代环境筛选。

后续实验分别标识“已见股票的未来日期”“未见股票”和“扩大股票池”，不能混为一种泛化结果。留出股票若被用于选模，就属于验证股票，不再是独立测试股票。所有性能实验仍遵守不在本次启动训练或测试集评估的边界。

## 5. 训练框架

### 5.1 数据和环境

- 训练：2017-01-03 至 2022-08-05，仅在特征完成预热且有下一步行情时开始决策。
- 验证：以 2022-08-05 收盘初始化，成交区间为 2022-08-08 至 2023-10-20。
- 测试：2023-10-23 至 2024-12-31，本阶段默认入口不评估。
- 环境工厂在交付数据给 provider 前裁出所需日期边界，仅保留合法的历史预热；不能只依赖运行游标保证训练不接触未来数据。
- 首版完整训练区间作为 episode，结束后重置账户。随机短窗口训练暂不启用，避免首版额外引入窗口抽样与预热规则。
- 使用单进程 `DummyVecEnv` 和监控包装器；先用 CPU，避免 Windows 多进程和重复加载面板带来的复杂度。
- 明确自然终止与时间截断；截断要保留终止观测供价值 bootstrap，不能对重置后的新账户观测进行 bootstrap。

### 5.2 奖励和拟定初始参数

奖励沿用环境的净值单步收益，已包含手续费和滑点，不重复扣减成本。首版不叠加回撤、换手惩罚，也不增加在线奖励归一化。若之后因价值损失尺度调整固定奖励倍率，必须单独版本化，报告仍使用原始净值。

| 参数 | 首版拟定值 |
| --- | --- |
| `n_envs` / `lookback` | 1 / 1 |
| `n_steps` / `batch_size` | 256 / 64 |
| `learning_rate` / `n_epochs` | 0.0003 / 10 |
| `gamma` / `gae_lambda` | 0.99 / 0.95 |
| `clip_range` / `target_kl` | 0.2 / 0.03 |
| `ent_coef` / `vf_coef` | 0.0 / 0.5 |
| `max_grad_norm` / `seed` | 0.5 / 42 |

这些是待验证的起点，不是经过搜索的最优参数。训练总步数必须由明确的训练命令提供；检查入口不能设置隐式训练预算。未来短训练验收先检查数值稳定性和保存恢复，再决定正式预算。

记录原始净值奖励、价值损失、策略损失、KL、裁剪比例、潜在动作饱和率、目标/实际现金、换手、费用及订单拒绝原因。仅 `256 x 298 x 20` 个 float32 特征约占 6.1 MB，增加窗口会线性扩大 rollout 内存；首版不默认扩大窗口和并行数。

### 5.3 验证与模型选择

未来训练时，每 10 个 rollout 在独立验证环境做确定性评估，不更新参数，不共享可变账户。模型选择规则在训练前固定：优先验证 Sharpe，收益作为同分排序；无定义的 Sharpe 单独标记，不转成无穷值。若全部候选 Sharpe 无定义，不自动宣布最优模型。

限制并记录验证次数与参数尝试，避免反复调参后把验证结果当成独立样本外结论。训练结束和选模不自动触发测试集；测试须在配置冻结后另行授权。

PPO 与阶段三四条基线使用相同的股票池、日期、初始资金和 broker 参数。保留原有 20 日调仓结果，另外增加相同每日调仓频率的等权与动量对照，不能把调仓频率差异全部归因于学习效果。

## 6. 标准化与现实判断的分工

训练和推理读取相同的相对特征与训练期 scaler。模型直接输出目标权重，因此不需要将动作逆标准化后再交易。

环境始终从独立 `prices.parquet` 读取未标准化价格，计算股数、现金、成本和净值。特征逆标准化只用于检查或展示；例如还原 `close_ma_ratio_20` 得到的是比值，不是现实股价。

逆标准化不等于取消后复权。当前没有完整不复权行情和权威公司行为表，不能通过 scaler 恢复真实历史报价。PPO 不改变该数据边界，也不绕过已有 `hfq_research` 声明。

## 9. 仍需保留的限制

- 后复权报价和 100 股整手约束使目标与实际配置明显偏离，已有等权基线出现较高现金留存。必须联合查看现金与成交率，警惕模型只适应模拟器假设。
- 固定股票名单有选择偏差，当前缺少完整历史成分股、交易状态及公司行为，策略盈利不等于可实盘。
- 网络的股票重排性质不等于撮合结果重排不变：现有 broker 按股票顺序分配有限现金，需保持顺序并披露该假设。
- 本计划完成后，阶段四仍不得标记“训练完成”或“策略有效”；代码验收、训练验收和样本外性能验证分别记录。
