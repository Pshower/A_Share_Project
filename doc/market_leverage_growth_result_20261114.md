# 结果：市场级杠杆闸门（增速形式）—— `void`，**因为守卫是我自己定错的**

日期：2026-11-14。协议：[第二份预登记](market_leverage_growth_protocol_20261114.md)（提交 `391f354`，写在任何信号‑收益统计之前）。
工具 `tools/market_leverage.py --source both --signal growth --window long`，产物 `reports/runs/market_leverage/gate_both_long.json`。

## 0. 一句话

**判定是 `void`，不是通过也不是失败——守卫 G1 不成立，而不成立的原因是我把"2015 覆盖"这个守卫的阈值定在了数据分布之外。**
按协议 §7.1，这一轮既不算通过也不算失败，只能先修设计。但诊断显示四条判据离门槛都很远，所以我建议**关闭整族，不再写第三份预登记**（理由见 §4）。

## 1. 这一轮实际跑了什么

- 信号 `s20 = ln(balance_t / balance_{t-20})`，`balance` = 上交所 + 深交所融资余额（元），官方宏观口径 + 150 天补丁。
- 窗口 **2012-01-04 ~ 2026-06-30，3,462 个观测**（≈173 个独立 20 日块），P 段未读。
- 途中修掉一处自己的接线错误：增速信号本来不需要分母，但代码仍把它 join 到流通市值上，**窗口被悄悄截成 2017-2024**。修好后窗口才真的是 2012 起——这一步是协议第九行就写明的范围，属于「实现与协议不符，以协议为准」。

## 2. 守卫 G1 为什么不过：阈值定错了

协议写的是「窗口内 `s20 > 0.50` 的交易日 ≥ 20 天，且最大值落在 2014-06 ~ 2016-12」。实际：

| 事实 | 数值 |
| --- | ---: |
| `s20` 中位数 | **1.6%** |
| `s20` p90 / p99 | 13.3% / **24.6%** |
| 全样本最大值 | **62.3%，出现在 2024-09-05**（"924 行情"） |
| 2015 全年最大值 | **27.0%** |
| 2015 上半年中位数 | 13.0% |
| 满足 `s20 > 0.50` 的交易日 | **1 天** |

**两处都错：**

1. **量级错**：0.50（20 日涨 65%）高于全样本 p99（24.6%），除了 2024-09-05 没有任何一天能过。我凭直觉写了"20 日涨 65% 才算过热"，没有用分布校准。
2. **前提错**：我默认"2015 是最极端的加杠杆事件"，但在 **20 日增速**这个尺度上它不是——2015 是靠几个月累积翻倍，20 日增速最高只有 27%；全样本最猛的一次是 **2024-09**。所以"最大值必须落在 2015-2016"这条要求本身站不住。

守卫在 `gate_both_long.json` 里记的是 `episode_days: 1 / required 20`、`max_g20: 2024-09-05`、`episode_missing: true`。**G2（动量伪装）通过**：`corr(s20, 过去 20 日收益) = 0.585`，低于 0.85——融资余额确实跟涨，但没有退化成纯动量。

## 3. 诊断（**不是判定结果**）

守卫不过，所以下面这些数字按协议不能当作登记结果。写出来是因为藏起来更坏：

| 编号 | 实测 | 门槛 |
| --- | --- | --- |
| T1 未来 20 日收益 | 斜率 **+0.0250**，**t 0.450**，n 3,462 | t ≤ −2.5 |
| T2 两段符号 | 2012-2018 **+0.0442**（t 0.67）、2019-2026H1 **−0.0404**（t −0.59） | 两段都为负 |
| T3 未来 20 日回撤 | 斜率 **+0.00007**，**t 0.0017** | t ≥ +2.5 |
| T4 中证全指 | 斜率 **+0.0114**，**t 0.196** | t ≤ −2.5 |

5 日版 t 0.32、60 日版 t −0.29——不同持有期上都是零。
**换到 2015 这个样本并没有改变什么：四条判据连 0.7 都没到。**

## 4. 我的建议：关闭整族，不写第三份预登记

理由不是"再试一次很麻烦"，而是三条：

1. **可见的信息已经足够**：3,462 个观测、横跨 2015 与 2024 两次极端，t 分别是 0.45 / 0.67 / −0.59 / 0.00 / 0.20。这不是"临界未过"，是没有任何关系。
2. **修守卫的唯一诚实方式，是看数据**——而一旦看着数据去改"什么样算覆盖了 2015"，这份守卫就不再是守卫，只是把判据做成能通过的形状。
3. 这个族已经花掉两份预登记（比率形式 `failed`、增速形式 `void`）。第三份的边际价值低于它消耗的可信度。

如果将来仍要重开，正确的前提不是再写一份更宽松的守卫，而是**换问题**：比如"融资余额占成交额比"或"两融交易占比"这类**存量/流量**指标，和本文的"存量增速"不是同一个东西——那需要新的预登记，而不是在本文上继续拧。

## 5. 一条方法论上的教训

**守卫的阈值必须在写下来之前用预测变量自己的分布校准过。** 检查自变量的分布**不构成对结果的偷看**——它不含任何收益信息；我上一份协议（以及这一份）都是在没做这一步的情况下把阈值拍下来的，于是写出了两条永远无法满足的守卫。

正确做法，下一份协议起适用：先算 `s20` 的 p50/p90/p99 与分年最大值，再据此写下"覆盖"的定义，**写死之后才去看收益**。这次没做，代价是整轮作废。
