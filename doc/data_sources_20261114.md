# 全网可用的宏观 / 基本面 / 技术数据：一次可复现的普查

日期：2026-11-14。工具 `tools/data_catalog.py`，产物 `reports/runs/data_catalog/catalog.json`。
方法：**42 个接口逐个真调**，每个 18 秒硬超时，记录 `status / rows / last_date / columns / seconds`，
分三类（宏观、技术、基本面与基金）。复现一条命令：

```powershell
python -B -m tools.data_catalog --timeout 18
```

## 0. 结论

1. **42 个接口里 32 个当场答出了数据**（宏观 12/13、技术 9/14、基本面 11/15）。
2. **"可用"是网络位置的属性，不是接口的属性**：东方财富 `push2` 系列在这台机器上**时好时坏**
   （同一接口 20 分钟内一次 `blocked`、一次 `ok`），新浪系列稳定可用。
3. **新鲜度分四层**，混用会得出错误结论：实时（11-13/14）、周级滞后（两融 11-05）、
   月级（CPI/PPI/PMI/M2 到 2026-10）、年久失修（贸易差额 2025-09）。
4. **哪些是"有效信息"不由可得性决定**：这个仓库已经用预登记检验过十几族，下面按类别给出
   已关闭 / 未测 的判定；真正值得新开一轮的只有 **3 个方向**。

## 4. 哪些是"有效信息"：按本仓库的检验结果

| 数据 | 可得性 | 本仓库结论 |
| --- | --- | --- |
| 国债收益率 / LPR | ✅ 日频 | **有效且在用**：方案的 carry 就是它，`cppi_bond_sensitivity` 也基于它 |
| 两融余额 | ✅ 周滞后 | **已关闭两轮**：IC 显著（−0.0403, t −4.64）但组合检验不通过；市场级杠杆闸门两轮失败 |
| 龙虎榜 | ✅ | **已测，不通过** |
| 股东户数 | ✅ | **已测，不通过** |
| 业绩报表 / 预告 | ✅ | **已测，效应为零 / 未通过** |
| 限售解禁 | ✅ | **已测，不通过** |
| PE/PB（`bp`） | ✅ | **是风格暴露不是 alpha**（2019-21 t 1.09 vs 2022-24 t 6.09） |
| 价格 / 量 / 20 个技术特征 | ✅ | **整族关闭**（E2 失败；1 日反转被成本吃掉） |
| 分钟线 / 实时快照 / IOPV | ⚠️ 本机被拒 | **未测**；历史 IOPV 也拿不到（只能前向累积） |
| CPI / PPI / PMI / GDP / M2 / 社融 | ✅ 月/季 | **未测**；低频 vs 日频决策，机制上不匹配 |
| 指数 PE | ✅ 日频 | **未测**；有长期预期收益含义，可作风险预算而非择时 |
| 行业板块 / 基金持仓 | ⚠️ 部分 | **未测** |

**这就是"有效信息"的真实分布**：可得的东西里，绝大多数已经被证明无效；没被证明的，
要么低频（宏观），要么需要另一条研究设计（指数 PE、ETF 溢价），要么干脆拿不到（分钟线）。

## 5. 值得新开一轮的三个方向（按可执行性排序）

| 方向 | 数据 | 为什么可能有信息 | 判据建议 |
| --- | --- | --- | --- |
| **利率 regime → 方案参数** | `bond_zh_us_rate` 日频 | 方案的收益直接由 carry 决定，"当前该期待几个点"是可知的 | 分档后 129 起点的中位年化/最差回撤；**不调参数，只出刻度** |
| **指数 PE → 风险预算** | `stock_index_pe_lg` 日频 | 估值水平对**多年**收益有解释力，对**日频**没有；用于决定风险腿上限而非择时 | 以"未来 3 年收益"为因变量，而不是次日收益 |
| **ETF 折溢价（四腿全覆盖）** | 价格已有；IOPV 仅实时 | 已对 513500 做过（2024 年后中位 **4.00%**），其余三腿未查 | 用同一套 `tools/etf_premium.py` 扩展到 510300/510500/511010 |

**不建议再开**：两融、龙虎榜、股东户数、业绩类、限售解禁、价格特征族——这些不是"没测过"，
是**测过且关闭**。再测一遍只会消耗样本，不会改变结论。

## 6. 三个操作层面的发现

1. **东财 `push2` 会挑时间**：同一接口在相隔 20 分钟的两次探测中一次 `blocked`、一次 `ok`。
   所以任何依赖它的日频任务都必须**有新浪/其他 provider 的退路**，并把"这一轮被拒"记成数据缺口
   而不是策略信号——本仓库的 `fund_flow` 归档昨晚就遇到了同类问题（最新日期停在 11-06）。
2. **akshare 本身有坏接口**：`fund_etf_fund_info_em` 会内部遍历 18 个接口、必然超时；
   `stock_szse_summary` 与当前 pandas 版本不兼容；这些是**库的问题**，不是数据不存在。
3. **新鲜度必须逐接口测**：`macro_china_trade_balance` 停在 2025-09，而同一批的 CPI/PMI 到 2026-10。
   只看"接口名"会以为它们是同一批数据。

## 7. 复现与限制

- 复现：`python -B -m tools.data_catalog --timeout 18`（结果写 `reports/runs/data_catalog/catalog.json`）。
- 限制：一次探测只证明"这一刻这台机器能取到"；`status` 是**时点快照**，不是可用性保证。
- 未覆盖：付费源（Wind/聚源/同花顺 iFinD）、交易所原始文件、以及需要账号的接口——本项目不使用付费源，
  所以普查只覆盖免费公开接口。
