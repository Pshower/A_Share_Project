# 从方案到订单：`tools/plan_orders.py`

日期：2026-11-11
状态：**可用**。把[最终方案](final_plan_20261109.md)的 CPPI 规则接上真实收盘价，输出整手订单。
这不是新研究，是把已经定稿的规则做成能照着下单的东西。

---

## 1. 它算什么

方案里的全部参数都在代码顶部，一个都没改：

```text
缓冲垫 = 净值 − 0.90 × 峰值
风险腿 = clip(6 × 缓冲垫 / 净值, 0, 1)
若 |风险腿 − 当前风险腿| < 5%：不交易，保持当前暴露
510300 = 510500 = 0.25 × 风险腿        # A 股那一半五五开
513500 = 0.50 × 风险腿                 # 标普那一半
511010 = 1 − 风险腿                    # 安全腿
```

下单数量按 100 份整手**向下取整**，并给出相对当前持仓的差额（买/卖）。

## 2. 怎么用

```powershell
# 净值 300 万、历史峰值 310 万、当前空仓
python -B -m tools.plan_orders --nav 3000000 --peak 3100000

# 已经有持仓时，把持仓份数传进去，它会算出该买还是该卖
python -B -m tools.plan_orders --nav 3050000 --peak 3100000 --held '{\"510300\": 75900}'

# 用自己核对的收盘价，不联网
python -B -m tools.plan_orders --nav 3000000 --peak 3100000 `
  --prices '{\"510300\": 4.15, \"510500\": 6.748, \"513500\": 2.662, \"511010\": 141.34}'
```

实测输出（2026-11-11 收盘价，空仓）：

| 代码 | 权重 | 价格 | 目标份数 | 金额 |
| --- | ---: | ---: | ---: | ---: |
| 510300 | 10.5% | 4.150 | 75,900 | 314,985 |
| 510500 | 10.5% | 6.748 | 46,600 | 314,457 |
| 513500 | 21.0% | 2.662 | 236,600 | 629,829 |
| 511010 | 58.0% | 141.34 | 12,300 | 1,738,482 |

净值 300 万、峰值 310 万 → 缓冲垫 21 万 → 风险腿 6×21/300 = **42%**，与表一致；剩 2,247 元现金。

## 3. 踩到的两个坑（写在这里，省得下次再踩）

1. **仓库自己的新浪行情把基金代码发错了交易所。** `src/data/online.py` 用"以 6 开头 = 沪市、否则 = 深市"拼 `secid`，
   于是 `510300` 被发到 `sz510300`，新浪返回 **404**。基金代码需要自己的规则（`5` 开头 = `sh`，`1` 开头 = `sz`）。
   这个修正只放在本工具里，**没有去改共享的 provider**——那会影响所有研究线的价格口径。
2. **东财的 ETF 实时快照当时连不上**（`fund_etf_spot_em` 连接被重置）。所以取价走**新浪基金历史接口**，
   取**最新收盘价**——方案是月度再平衡，用收盘价决策本来就更合适。

## 4. 它不算什么

- **不预测收益。** 方案的预期是 +4.9%~+6.6%、回撤 ≤10%，那是机制的结论，不是这个工具的输出。
- **不算基金费率、QDII 溢价、汇率对冲成本。** 方案里写明这些还要再吃掉 0.5–1pp/年。
- **不自动维护峰值。** `--peak` 必须由你（或未来的账本）提供；用错的峰值会直接把风险腿算错，
  这是整个工具唯一一个"输入错了就全错"的地方。
- **不判断何时再平衡。** 它是"每次决策时算一次"，节奏由你定；方案建议月度。
