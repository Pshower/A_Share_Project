# 每日收盘股票池配置：交付计划

更新日期：2026-09-27

## 最终交付

用户选择股票池、可用资金和实际持仓，在每日收盘数据齐备后，得到模型版本、行情截止日期、逐股当前/目标权重、现金比例、调仓方向、参考金额及阻断原因。建议针对下一交易时段，不承诺下一开盘成交价，不自动下单。股票池变更必须通过显式迁移与兼容检查，不能只在界面隐藏股票。

## 实施顺序与验收

1. 收盘数据闸门：显式指定日期，逐股检查该日日线及采集时间；当天数据只有在保守等待时间后采集才允许使用。任何股票缺当日数据必须阻断，不静默回退。保留原有研究模式，不把供应商日线当作交易所终稿认证。
2. 数据与账户：审计本地 HFQ/不复权成对覆盖、复权变更与公司行为；补齐未复权成交、股数/购买力和公司行为记账。真实账户持仓不可直接套用 HFQ 报价。缺少资料时列出可手动下载的清单，不伪造事件、不自动补零。
3. 行为与奖励：分别实验明确不交易、调仓阈值、清仓；净日收益保留基线，对数收益及回撤惩罚独立消融。动作/奖励变更写入模型契约，旧模型不得默认为兼容。
4. 训练：GPU 候选，较低学习率、保留 KL 保护；比较窗口 1/20/60、网络容量及多种子。记录实际优化器步数，不能只比较环境步。先预登记实验，再训练；不复用已暴露最终测试区间选模。
5. 验证与发布：滚动时间验证、股票留出、等权/持有/现金基线、成本压力、失败输入测试。按预定风险/成本条件发布候选，未证明优势则保留基线，不强行宣布 PPO 优胜。
6. 日常使用：选池、录入账户、手动更新数据、运行收盘建议、保存每日不可变报告、导出审阅。不把次日日期简单加一天当作交易日；交易日历与当日可交易状态未验证时明确提示。

## 本轮边界

先落实第 1 项及测试。现有 `build_daily_plan` 是 HFQ 研究推理，不接受真实账户股数；`actionable` 仍为 false。接受指定收盘日只说明输入满足本地完整性规则，不表示模型通过实盘发布验收。真实持仓接口与最终模型尚未完成。

本地容量实验已证明大网络的 GPU 更新加速，但收益未证明改善，见 [容量报告](reports/ppo_capacity_20260927.md)。不直接将大模型晋升为默认。

## 提交约定

按研究证据、数据闸门、账户适配、训练方法、验证发布拆分提交。每次提交记录测试与未完成项，模型和数据保存在本地、不提交大体积产物。重大数据缺口先报告，训练自由探索不等于无限预算或自动使用最终测试集。
