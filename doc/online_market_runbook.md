## 1. 页面入口

打开工作台的 **联网行情**，分为五个标签页：

| 页面 | 已实现能力 |
| --- | --- |
| 行情与模型 | 最多选择三个模型，绑定同源完整 HFQ 批次和指定收盘日，进行对比预检与单日研究 |
| 联网历史 | 输入股票和日期、选择来源及后复权/未复权、明确允许联网后下载；审计、部分失败、按原请求重试；从完整 HFQ 批次构建训练版本 |
| 最新日线计划 | 选择模型与完整历史批次、沿用旧 scaler、检查原始历史锚点及修订、输入假设研究仓位，生成独立计划 |
| 报价与监控 | 选择新浪/东财实时来源抓取报价、查看旧快照、按固定计划检查时效和限制，开启/停止有限租约监控 |
| 扩展数据 | 个股资料、资金流、分钟、指数日线和分红记录独立采集、预览和导出，不自动进入训练 |

打开页面、查看快照列表或历史记录不会自动发起网络任务。报价页支持新浪和东方财富实时接口：选择与模型训练来源一致的来源，勾选授权后点击“刷新一次报价”或开启监控即可联网。页面只自动选择 2 分钟内且状态为 `ready` 的完整报价；旧快照和失败快照必须手动选择，并明确显示保存时间，不会把历史值标成“当前报价”。只读快照的时效会通过本地 API 重新计算，不会因为网页保持打开就永久显示为新鲜。

当前仍使用 `python -B -m src.web.serve --port 8765` 启动，默认访问 `http://127.0.0.1:8765`，端口占用时以程序打印值为准。新增页面为按需加载，不改变原训练、模型和历史回测入口。

## 2. 下载和存储

联网任务必须勾选授权并显式提交。历史日线默认新浪，也可显式选择东方财富。实时报价支持新浪 `hq.sinajs.cn` 和东方财富 `push2`；报价来源必须与模型训练来源一致，来源会写入快照和模型绑定，不自动切换供应商、价格口径或 IP。历史日线与实时报价是不同口径，实时报价不能回填训练数据。

新浪快照保存五档买卖盘、价差、以中间价为基准的价差 bp、五档深度不平衡和 VWAP；东方财富快照保存最新价、开高低、量额和 VWAP，但没有同等五档深度。字段缺失时留空，不用默认值填充。

快照不可覆盖，保存文件哈希、供应商、请求范围、实际日期、单位、成功/失败记录。构建中目录以点开头，不作为有效快照展示。失败批次保持 `partial`，不能生成模型计划或训练版本；任务“完成”只代表采集任务结束，不代表全部数据成功。

显式重试要求与原请求完全一致，复用校验通过的成功文件，仅重新请求失败项，产生新快照并保留原失败批次。成功项的原接收时间保留，不伪装成新抓取。没有静默使用陈旧缓存，也不会覆盖 `data/raw` 或 `research_v3`。

从在线 HFQ 快照构建新训练数据时，用户选择模板、版本、股票和时间切分，运行原预处理流程并拟合新的训练期 scaler。该流程与“旧模型推理复用旧 scaler”是两种操作，不可混用。

## 3. 日线研究计划

生成计划前需要：模型股票池的全部 HFQ 历史、完整批次、明确的研究用途确认及足够的原始历史。

原始历史锚点从原模型数据的来源审计确定，不简单使用研究区间起始日。原预处理可能先在更早的原始历史上计算指标，再裁剪研究日期；这是 MACD 等递推指标一致性的必要条件。

新输入通过原特征函数计算，再应用原模型 scaler，绝不重新拟合。重叠历史的有效性与标准化特征逐项比较；发现差异时默认阻止，只有用户明确接受修订的研究用途才允许继续，差异进入绑定记录。

实际返回数据若缺少原始历史起点，即使请求日期填得足够早也会被拒绝；“接受修订”不能绕过供应商截断历史的情况。

仍保留原 `PPOAgent.load` 及训练数据契约，新快照通过独立绑定引用模型、原 scaler、来源批次、历史锚点和特征实现。没有把新文件伪装为旧 manifest，也不把模型重新标记为已在新数据上训练。

收盘边界有两种显式政策：未填写 `close_as_of` 时，仍按每只股票文件的原接收日期排除捕获当日日线，跨日重试复用的旧文件不会因此升级为完整日线；填写 `close_as_of` 时，所有股票必须存在该日期，且逐文件采集时间不早于当日北京时间 16:00、不晚于当前时间，缺任一股不会退回较早日期。当前未接入独立交易所日历，页面明确显示实际特征日期，不能保证已补齐交易所最近一个交易日。

计划输入是 **假设研究仓位比例**，留空为全现金，可输入 `000001=0.10`。它不是股数，不是真实账户，也不做现实账户市值换算。输出当前研究权重、目标权重、买入/减仓/清仓/维持参考及目标现金。

## 4. 报价判断的边界

报价按未复权金额显示。东方财富 `f86` 按 Unix 秒解析；新浪使用响应中的日期和时间并按 Asia/Shanghai 解释。两者都标记为供应商时间，**不等同于交易所认证成交时间**。没有时间字段、未来时间或异常值时，不伪造一个当前时间。

当前检查包括：

- 报价缺失、批次不完整、接收时间/供方时间异常。
- 连续竞价时段内超过 120 秒未更新；非交易时段标记 `market_closed`，显示最近一次可得报价，不冒充盘中 tick。
- 日线计划日期过旧、模型池与报价池不一致。
- 供应商返回的涨跌停参考价（若有效）；未知字段不推测。
- 研究账户限制、交易日历与完整交易状态尚未核验。

状态分为“仅行情”“仅研究复核”“等待/过期”。现阶段所有结果均为 `actionable=false`，不返回真实可执行订单。休市时旧报价可能是合理的历史收盘值，但不能因此认定当前可以交易；日期较早本身也不证明供应商错误。周末判断依据本地时间，不替代交易所节假日日历。

刷新价格不会重新运行盘中 PPO、重训、改变固定日线计划或自动切换模型。真实股数绝不乘以后复权价格估值。真实账户参考适配仍需独立验证，目前未开放。

## 5. 监控、限流与退出

- 历史下载最多 500 只股票/请求；报价最多 50 只。绑定日线计划时要求提交完整有序模型池，因此当前 300 股计划不能直接用一次报价覆盖全池；先只做行情展示，后续需单独设计分批或分层计划报价。
- 历史下载、报价与原研究计算使用分开的受控执行槽，各类均保持一个执行槽；供应商请求共用本机限速。
- 请求有固定超时、默认最多 5 次尝试、连续失败熔断与总时限；拥有进程句柄的服务对超时网络 worker 执行终止，不操作其他程序。
- 自动监控必须显式启动，间隔至少 60 秒，时长最多 30 分钟，同一工作台最多一个活动会话。
- 页面每 15 秒续租，租约 45 秒。离开页面请求停止；异常断连后租约到期阻止后续请求，并取消未完成轮询。
- 已发出的 HTTP 请求可能需要等到自身超时才退出，不承诺瞬间取消。整个模型池的快照不完整时，不继续展示新的有效判断。

目前没有报价缓存加速或多供应商自动路由；历史重试仅显式复用成功项。供应商失败时保留审计并等待用户后续操作，不绕过访问控制、不关闭 TLS、不切换代理/IP 继续试探。

## 10. PIT 日历、财报与股东户数（2026-11-01）

`src.data.pit` 采集三类可审计参考数据，独立于个股 HFQ/未复权行情和实时报价：

- 交易日历：新浪 `tool_trade_date_hist_sina`，保存全部交易日，不推断交易状态。
- 季度财报：东财 `stock_yjbb_em`，保留供应商全字段，并添加 `period`、`code`、`announcement_date`。
- 业绩预告：东财 `stock_yjyg_em`，同一股票可有多个预测指标，按 `(code, 预测指标)` 去重并保留最新公告日。
- 股东户数：东财 `stock_zh_a_gdhs`，季度全市场表，添加 `period`、`code`、`announcement_date`。

PIT 规则：**只能使用公告日期，不能使用报告期末日期**；公告只有日期没有时分，因此应顺延到下一交易日使用。供应商返回的是抓取时点的最新修订值，原始历史版本未保存；不能把修订后的财务值无条件回填到更早公告日。

本次实测：

## 12. 可交易性账本（派生，2026-11-02）

研究环境在收盘决策、次日开盘成交，但它没有停牌、涨跌停和公司行为状态：停牌股照样能被“买入”，一字板开盘照样成交。供应商不提供这些历史字段，其中三类可以从**已经在盘上的数据**派生：

| 派生项 | 判定 | 说明 |
| --- | --- | --- |
| 停牌 | 在该股首末交易日之间、交易日历上有该日但无 K 线 | 上市前与退市后不算停牌 |
| 涨停 / 跌停 | 未复权收盘 == 交易所涨跌停价（昨收 × 1±比例，四舍五入到分） | 主板 10%、创业板/科创板 20%、北交所 30% |
| 一字板 | 开 = 高 = 低 = 收 = 涨停价 | 当日无流动性 |
| 次日不可买 / 不可卖 | 下一个**成交日**开盘价 ≥ 该收盘价推出的次日涨停价（或 ≤ 跌停价） | 对“收盘决策、次日开盘成交”这一执行方式直接有效 |
| 公司行为 | `hfq`/未复权收盘比值相对跳变 > 0.2% | 只记因子跳变，不区分分红与送转 |

```powershell
python -B -m tools.tradability_ledger --history h_13cd6e0169124b2e --calendar c_4e276f88d8ff4018 --output reports/runs/tradability_ledger_20261102
python -B -m tools.derive_pit_availability --snapshot f_2f8ef1efe22c430a --history h_13cd6e0169124b2e --output reports/runs/pit_availability_20261102
```

产物为 `ledger.parquet`（逐股逐日）、`corporate_actions.parquet` 和 `summary.json`，均在 gitignore 内。第一版实测（299 只、2017-01-03 至 2026-10-30、650,873 个股票日）：

| 指标 | 数值 |
| --- | ---: |
| 停牌股票日 | 4,342（129 只） |
| 涨停 / 跌停股票日 | 3,897 / 1,137 |
| 一字板（涨停） | 533 |
| 次日不可买 / 不可卖 | 732（0.113%）/ 572（0.089%） |
| 公司行为事件 | 3,450（299 只中 293 只有事件） |

规模上很小，但**分布极不均匀**：732 次不可买集中在 434 个交易日、222 只股票上，中位每日 1 只，而 2024-09-30 单日有 **157 只**（当日池内 296 只、82 只收在涨停）——那天是 2024 年三季度的最后一个交易日，次日开盘正是国庆后跳空日。也就是说“平均影响很小”不能外推为“任何一天影响都很小”，季度末调仓日恰好是这类事件的聚集点。

限制（因此 `model_ready=false`）：

- 涨跌停比例不含历史 ST 状态（ST 为 5%）与上市首日无涨跌幅限制，这类日子会被记成普通交易日而非涨停。
- 停牌以“缺 K 线”判定，供应商若整段缺失而非逐日缺失，边界会落在首末根上。
- 公司行为只记录比值跳变，没有分类、没有每股派息金额，不能直接当现金流用。
- 全部为派生量，不是交易所认证状态；真实撮合仍需独立的权威交易状态源。
- 尚未接入 `src/envs`：把它作为执行约束会改变既有回测口径，须另立协议并重新冻结，本轮不做。
