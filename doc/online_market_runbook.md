## 1. 页面入口

打开工作台的 **联网行情**，分为三个标签页：

| 页面 | 已实现能力 |
| --- | --- |
| 联网历史 | 输入股票和日期、选择后复权/未复权、明确允许联网后下载；审计、部分失败、按原请求重试；从完整 HFQ 批次构建训练版本 |
| 最新日线计划 | 选择模型与完整历史批次、沿用旧 scaler、检查原始历史锚点及修订、输入假设研究仓位，生成独立计划 |
| 报价与监控 | 显式抓取报价、查看旧快照、按固定计划检查时效和限制，开启/停止有限租约监控 |

打开页面、查看快照列表或历史记录不会联网。只读快照的时效会通过本地 API 重新计算，不会因为网页保持打开就永久显示为新鲜。

当前仍使用 `python -B -m src.web.serve --port 8765` 启动，默认访问 `http://127.0.0.1:8765`，端口占用时以程序打印值为准。新增页面为按需加载，不改变原训练、模型和历史回测入口。

## 2. 下载和存储

必须勾选网络授权并提交。当前接入东方财富：历史使用既有 `DataFetcher` 封装的 AKShare 日线接口，报价使用同一供应商的指定股票 JSON 接口，不自动切换其他来源或 IP。

历史下载将后复权与未复权分目录保存；标准化存储中的成交量单位是股，原东财日线的手数转换后保存。该接口的原始量额单位与复权参数见 [AKShare 官方文档的 stock_zh_a_hist 章节](https://akshare.akfamily.xyz/data/stock/stock.html)，精确使用的调用签名已核验本机 AKShare 1.18.64。

```text
data/online/history/h_<id>/
  hfq/<code>.csv、<code>.parquet
  unadjusted/<code>.csv、<code>.parquet
  requests.jsonl、manifest.json

data/online/quotes/q_<id>/
  quotes.json、provider_response.json、manifest.json

data/online/plans/p_<id>/
  features.parquet、binding.json、manifest.json
```

快照不可覆盖，保存文件哈希、供应商、请求范围、实际日期、单位、成功/失败记录。构建中目录以点开头，不作为有效快照展示。失败批次保持 `partial`，不能生成模型计划或训练版本；任务“完成”只代表采集任务结束，不代表全部数据成功。

显式重试要求与原请求完全一致，复用校验通过的成功文件，仅重新请求失败项，产生新快照并保留原失败批次。成功项的原接收时间保留，不伪装成新抓取。没有静默使用陈旧缓存，也不会覆盖 `data/raw` 或 `research_v3`。

从在线 HFQ 快照构建新训练数据时，用户选择模板、版本、股票和时间切分，运行原预处理流程并拟合新的训练期 scaler。该流程与“旧模型推理复用旧 scaler”是两种操作，不可混用。

## 3. 日线研究计划

生成计划前需要：模型股票池的全部 HFQ 历史、完整批次、明确的研究用途确认及足够的原始历史。

原始历史锚点从原模型数据的来源审计确定，不简单使用研究区间起始日。原预处理可能先在更早的原始历史上计算指标，再裁剪研究日期；这是 MACD 等递推指标一致性的必要条件。

新输入通过原特征函数计算，再应用原模型 scaler，绝不重新拟合。重叠历史的有效性与标准化特征逐项比较；发现差异时默认阻止，只有用户明确接受修订的研究用途才允许继续，差异进入绑定记录。

实际返回数据若缺少原始历史起点，即使请求日期填得足够早也会被拒绝；“接受修订”不能绕过供应商截断历史的情况。

仍保留原 `PPOAgent.load` 及训练数据契约，新快照通过独立绑定引用模型、原 scaler、来源批次、历史锚点和特征实现。没有把新文件伪装为旧 manifest，也不把模型重新标记为已在新数据上训练。

当日抓取的当日日线一律不进入计划；截止边界按每只股票文件的原接收日期计算，不采用新批次的发布时间。跨日重试复用的旧文件不会因此升级为完整日线。当前未接入独立交易所日历，使用所有模型股票共有的、捕获日以前的供应商日线，明确显示实际特征日期，不能保证已补齐交易所最近一个交易日。

计划输入是 **假设研究仓位比例**，留空为全现金，可输入 `000001=0.10`。它不是股数，不是真实账户，也不做现实账户市值换算。输出当前研究权重、目标权重、买入/减仓/清仓/维持参考及目标现金。

## 4. 报价判断的边界

报价按未复权金额显示。供方 `f86` 字段按 Unix 秒解析并保存，字段语义缺少充分的供应商文档核验，因此单独标记，**不等同于交易所认证成交时间**。没有时间字段、未来时间或异常值时，不伪造一个当前时间。

当前检查包括：

- 报价缺失、批次不完整、接收时间/供方时间异常或超过 120 秒。
- 日线计划日期过旧、模型池与报价池不一致。
- 供应商返回的涨跌停参考价（若有效）；未知字段不推测。
- 研究账户限制、交易日历与完整交易状态尚未核验。

状态分为“仅行情”“仅研究复核”“等待/过期”。现阶段所有结果均为 `actionable=false`，不返回真实可执行订单。休市时旧报价可能是合理的历史值，但不能因此认定当前可以交易；日期较早本身也不证明供应商错误。

刷新价格不会重新运行盘中 PPO、重训、改变固定日线计划或自动切换模型。真实股数绝不乘以后复权价格估值。真实账户参考适配仍需独立验证，目前未开放。

## 5. 监控、限流与退出

- 历史下载最多 100 只股票/请求；报价最多 50 只。
- 历史下载、报价与原研究计算使用分开的受控执行槽，各类均保持一个执行槽；供应商请求共用本机限速。
- 请求有固定超时、最多两次尝试、连续失败熔断与总时限；拥有进程句柄的服务对超时网络 worker 执行终止，不操作其他程序。
- 自动监控必须显式启动，间隔至少 60 秒，时长最多 30 分钟，同一工作台最多一个活动会话。
- 页面每 15 秒续租，租约 45 秒。离开页面请求停止；异常断连后租约到期阻止后续请求，并取消未完成轮询。
- 已发出的 HTTP 请求可能需要等到自身超时才退出，不承诺瞬间取消。整个模型池的快照不完整时，不继续展示新的有效判断。

目前没有报价缓存加速或多供应商自动路由；历史重试仅显式复用成功项。供应商失败时保留审计并等待用户后续操作，不绕过访问控制、不关闭 TLS、不切换代理/IP 继续试探。

## 6. 命令行和测试

下面的命令会真实联网，仅在明确需要时执行：

```powershell
conda activate Graduate
python -B -m src.data.online --kind history --codes 000001 --start 2017-01-01 --end 2026-09-25 --allow-network
python -B -m src.data.online --kind quotes --codes 000001 --allow-network
```

默认离线测试不包含真实网络访问：

```powershell
python -B -m pytest -q -p no:cacheprovider
npm --prefix web run build
npm --prefix web run test:e2e
```

联网浏览器用例把请求提交和监控响应显式模拟，另展示本地真实失败快照。mock 值不会发布到正式快照目录，不是实时行情验收证据。
