## 1. 总体形状

| 个股量价 | 日频 OHLCV + 成交额 + 换手率 | 300 只，2017-01-03 至 2026-10-30 | `data/online/history/*/{hfq,unadjusted}` |
| 个股量价（存档） | 同上，中文列名，三种命名副本 | 300 只，2017-01-03 至 2026-06-26 | `data/raw/*` |
| 个股基本面 | 12 个业绩字段 + 行业标签 + 公告日 | 299 只 × 39 个报告期 | `data/online/fundamentals/*/financials.parquet` |

## 3. 个股量价

### 3.1 长历史（唯一贯穿全程的数据）

| 来源 | 代码 | 区间 | 字段 |
| --- | ---: | --- | --- |
| `data/online/history/*/hfq` | 300 | 2017-01-03 至 2026-10-30 | date, code, open, close, high, low, volume, amount, turnover |
| `data/online/history/*/unadjusted` | 299 | 同上 | 同上 |
| `data/raw/{code}_data_*.csv` | 300 × 2 轨 | 2017-01-03 至 2026-06-26 | 日期、股票代码、开盘、收盘、最高、最低、成交量、成交额、振幅、涨跌幅、涨跌额、换手率 |
| `data/raw/stock_hist_*.parquet` | 600（300 只 × 2 轨） | 同上 | 同上，代码保留六位字符串 |
| `data/raw/stock_data*.csv` | 2 个全市场合并转储 | 同上 | 同上，代码存成整数 |

联网快照按批次重复下载过（904 个后复权文件 / 300 个代码），使用时按代码合并而不是拼接。`data/raw` 没有任何 manifest，同一只股票在目录里有**三份副本**（逐代码 CSV、哈希命名 Parquet、合并转储），版本目录实际引用的是逐代码 CSV（`raw_pattern = "{code}_data_2017_2024_hfq.csv"`）。合并转储与 CSV 的股票代码列存成整数，`000001` 写作 `1`，读取时必须补前导零。

### 3.2 送进模型的 20 个特征

全部是**相对量价**，没有原始价格：

| 组 | 特征 |
| --- | --- |
| 收益 | `return`、`log_return` |
| 形态 | `range_ratio`、`body_ratio` |
| 量能 | `volume_ratio`、`turnover` |
| 强度 | `rsi_14` |
| 趋势 | `macd_ratio`、`macd_signal_ratio` |
| 通道 | `bb_position` |
| 动量 | `momentum_5`、`momentum_10`、`momentum_20`、`momentum_60` |
| 均线比 | `close_ma_ratio_5`、`close_ma_ratio_10`、`close_ma_ratio_20`、`close_ma_ratio_60` |
| 波动 | `volatility_20`、`volatility_60` |

面板里的值是**按特征共享的 Z-score**（只用训练期拟合），价格另有独立的未标准化表 `prices.parquet`。逆标准化只能还原特征，不能还原真实股价。

### 3.3 市值与股本的三个来源

市值不是缺数据，而是有三条口径不同的来源：

| 来源 | 频率 | 口径 | 覆盖 |
| --- | --- | --- | --- |
| `shareholders.总市值` / `总股本` | 季度（随公告） | **总**市值，当期价 × 总股本 | 276 只 × 39 期 |
| `volume / (turnover / 100)` | 日 | **流通**股本，隐含 | 299 只 |
| 不复权收盘价 × 隐含流通股本 | 日 | 流通市值 | 299 只 |

隐含流通股本的实测精度：`600519` 得 12.56 亿股（与其总股本一致，变异系数 0.001）、`000001` 得 193 亿股、`300750` 从 2.2 亿增至 42.6 亿（对应真实增发与转增）。它是**逐日**的，所以补上了季度股本之间的空档；代价是依赖换手率口径，遇到增发、转增当日会跳，必须逐代码检查断点。

**目前没有任何研究使用过这三条中的任何一条。**

## 4. 个股基本面

299 只 × 39 个报告期（2017Q1 至 2026Q3），最新一期覆盖 298 只。

| 字段 | 含义 | 最新期缺失 |
| --- | --- | ---: |
| 每股收益 | EPS，**年内累计** | 0 |
| 营业总收入-营业总收入 / -同比增长 / -季度环比增长 | 营收与增速 | 0 |
| 净利润-净利润 / -同比增长 / -季度环比增长 | 净利润与增速 | 0 |
| 每股净资产 | BPS | 0 |
| 净资产收益率 | ROE，累计 | 0 |
| 每股经营现金流量 | 每股经营现金流 | 0 |
| 销售毛利率 | 毛利率 | **47（15.8%）** |
| 所处行业 | 申万二级 | 0 |
| announcement_date | 公告日 | 0 |

三点必须记住：

1. **是累计口径**。`600519` 2024 年 EPS 依次为 19.16 / 33.19 / 48.42 / 68.64，营收和净利润同样逐季累加。要单季数据必须自己差分，且跨年首季不能减上年 Q4。
2. **毛利率对金融股结构性缺失**，47 只全部是银行（24）、证券（18）、保险（5），不是随机缺失。
3. **时点用 `announcement_date`**，不是报告期末。字段值是供应商的**最新修订版**，不保留原始披露 vintage，所以严格 PIT 只能保证"公告日之后可见"，不能保证"当时看到的就是这个数"。

### 4.1 业绩预告（`forecasts.parquet`）

5987 行 / 272 只 / 38 期，带 `公告日期`。每条是一次业绩预告：`预告类型`（预增 2731、略增 1317、预减 492、略减 335、扭亏 299、首亏 230、不确定 226、减亏 120、增亏 112、续盈 108、续亏 17）、`预测指标`（净利润 2853、扣非净利润 1652、每股收益 734、营业收入 463）、`预测数值`、`业绩变动幅度`、`上年同期值`、`业绩变动原因`。

单期覆盖 33 至 363 只，**只有主动发预告的公司才有记录**，不是全样本。做事件研究时必须把"没发预告"当缺失而不是当零。

### 4.2 股东户数与股本（`shareholders.parquet`）

9381 行 / 276 只 / 39 期。`股东户数-本次`、`股东户数-增减比例`（筹码集中度）、`户均持股数量`、`户均持股市值`、`总股本`、`总市值`，都是**当期值**。

**时点陷阱**：同一张表里的 `最新价`、`涨跌幅`、`区间涨跌幅` 是抓取时点的快照，在所有历史行上是同一个值（`601988` 的 2017 年行也写 7.09）。这三列不能当历史价格用，`总市值` 却是按当期价算的正确值——两者混在同一行里。

## 5. 宏观

30 条序列，每条都有 `period`（数据所属期）和 `available_from`（可用日），可用日已按各序列的发布滞后推算，可以直接做 PIT 对齐。

| 块 | 序列 | 频率 |
| --- | --- | --- |
| 物价 | `cpi_yoy`、`cpi_mom`、`ppi_yoy` | 月 |
| 景气 | `pmi_manufacturing`、`pmi_non_manufacturing` | 月 |
| 货币信用 | `m1_yoy`、`m2_yoy`、`m2_level`、`new_rmb_loan`、`new_rmb_loan_yoy`、`social_financing`、`social_financing_rmb_loan` | 月 |
| 利率 | `cn_10y_yield`、`cn_10y_2y_slope`、`us_10y_yield`、`lpr_1y`、`lpr_5y`、`shibor_on/1w/3m` | 日 |
| 汇率 | `usdcny` | 日 |
| 实体 | `gdp_yoy`、`gdp_level`、`industrial_production_yoy/ytd`、`fixed_asset_investment_yoy`、`retail_yoy/ytd`、`exports_yoy`、`imports_yoy` | 月 / 季 |

两处需要注意：`social_financing` 与 `social_financing_rmb_loan` 只到 2026-04-30，比其余序列落后约 6 个月；`lpr_5y` 从 2019-08-20 起才有（LPR 改革），此前为空是制度原因不是缺数据。

**宏观目前没有进入任何模型。** 20 个特征全是量价，`pipeline.md` §2 也明确基本面、行业排名、市场宽度不是默认特征的一部分。宏观是已采集、未使用的资产。

## 9. 已知风险

1. **幸存者偏差最重**。股票池是 2026-06-29 的沪深 300 快照，被回填到 2017 年。这九年里被调出指数或退市的股票完全不在池内，任何横截面结论都带着这个上偏。
2. **行业标签是唯一的最新值**，没有历史行业变更记录，回测里用它会带轻微前视。
3. **财务是最新修订版**，不是披露时点的原始版本。
4. **宏观只有日期级滞后**（`lag_days`），没有真实公告时刻。
5. **宽度只有一天**，不能当历史横截面用。
6. `601059` 全字段缺失。
7. **代码会变**。`300114`（中航电测）已改为 `302132`（中航成飞），历史被回填到新代码，`300114` 在全市场快照里也已不存在。按代码与外部名单跨年 join 会错位，`302132` 的 2017 年数据属于同一法人主体而非拼接。
8. **`shareholders` 混了两种时点**：`最新价`/`涨跌幅`/`区间涨跌幅` 是抓取日快照，`总股本`/`总市值` 才是当期值。直接整表当面板用会把 2026 年的价格写进 2017 年。
9. **`data/raw` 没有 manifest**，三套命名副本共存且无版本标记，无法判断哪一份被哪次构建读取过；只有版本目录 manifest 里的 `sources[].sha256` 能反查。
10. `data/clean/` 顶层还留着一份 2026-07-01 的旧构建（301 个 `*_features.parquet`、`panel_data.parquet`），没有 `manifest.json`，数值口径与其他版本不一致；**它不是任何一个版本目录**，不要当数据集使用。

## 10. 维护规则

- 本文件只描述数据本身；研究的门槛、结论和下一步只在[实施进度](implementation_plan.md)。
- 新增数据源时，若生成器仍然存在则更新它的扫描分支并重跑；若不存在（当前分支），就手工改这张表并标注日期。
- 报告目录 `reports/runs/` 不随 Git 分发，其他机器须重跑生成器复现。
