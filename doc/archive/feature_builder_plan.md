# 数据管理特征构建规划

日期：2026-09-26。先记录设计后完成首版实现；实际验收见末节。

## 目标与边界

数据管理从仅查看现有特征，扩展为“定义追加特征、查看公式与窗口、预览、构建新版本、用于训练”。新特征不是改写现有数据表的一列，而是新数据版本契约的一部分。

第一版保留原有 20 列基础特征，在其后追加最多 12 列用户命名的参数化特征。暂不删除基础列，保证原有动量等基线仍可运行；不支持任意 Python、eval、SQL 或自由表达式。以后若需要组合公式，应另行设计受限语法和依赖图校验。

## 交互

数据管理“构建新版本”内新增特征定义区域。每条包含名称、指标类型和 2–250 条记录的窗口，提供新增、删除、清空追加项。已有自定义版本作为模板时带出原定义，可修改后另建版本。

当前版本显示完整特征清单，并区分基础与追加项。用户选择股票后可预览追加特征的原始值、缺失情况和末段序列；预览不拟合 scaler、不生成训练版本、不联网。最终构建的实际日历、缺失掩码与 scaler 以所选完整构建股票池为准。

## 计算契约

已支持窗口收益、均线偏离、对数收益波动率、窗口回撤、简单均值 ATR 比例、相对成交量、相对成交额、布林带宽。指标名称、公式版本、窗口和列顺序写入研究配置、manifest 与 scaler。

- 全部仅使用当前及过去记录；禁止未来 shift、居中窗口和全样本统计。
- 输入为未标准化的同口径价格 / 成交数据，先计算相对指标，再拟合训练期 scaler。
- 窗口不足和无效输入保留 null，零分母不产生无限值，不填充为可交易信号。
- 简单均值 ATR 明确采用 TR 的窗口算术均值，不冒充 Wilder ATR。
- 对数收益波动率不年化，ddof=0；相对量 / 额使用前 n 条均值，不包含当前条。
- 追加特征继承股票和日期隔离，不能把多只股票串在一起滚动。
- 重名、与基础特征冲突、无效窗口、未知类型、超出数量限制在提交与构建时都拒绝。

## 管线与兼容

数据预处理改为每个版本拥有显式特征列，不再要求全部版本都是全局 20 列。默认不传定义时计算结果与旧版保持一致。

新 scaler 只拟合新版本的训练日期和拟合股票池，保存列顺序及追加特征定义。数据有效日期、训练交集、观察空间和资源预算使用实际特征数。PPO 共享网络可按新输入维度初始化，但旧 checkpoint 不自动扩展输入层，也不复用新 scaler。

历史动作预测继续使用已保存面板；新日线计划使用与模型相同的特征定义重算，并保持原 scaler。不满足定义 / 列顺序契约时拒绝推理，不静默删列或填零。

构建仍复用持久任务队列、staging 发布和版本不可覆盖机制，不自动训练。模型或源码契约改变会影响旧冻结记录重跑，不能改写旧冻结记录来掩盖差异。

## 工作包

1. 指标注册与参数校验，追加特征计算及因果性测试。
2. 预处理、scaler、manifest、新日线推理和动态资源预算适配。
3. 本地预览 API、数据管理编辑器、特征清单及任务提交。
4. 小型离线数据构建、PPO 无训练检查、旧模型兼容拒绝和浏览器闭环验收。

## 验收标准

固定序列核对公式；改变未来数据不改变过去特征；测试短历史、零成交量、重复名称和非法参数。构建新版本后列数与定义一致，旧数据哈希不变，scaler 只用训练记录。

浏览器验收新增 / 删除 / 预览 / 构建 / 选择新版本，验证实际产物而非只拦截提交。使用小股票池和已有本地文件，不下载行情、不进行正式训练。

### 使用步骤

1. 打开数据管理，选择本地数据版本，点击“新建特征”。
2. 点击“添加特征”，填写唯一名称、选择指标类型和窗口。名称为小写字母开头的 3–40 位字母 / 数字 / 下划线，不能使用基础列或 code / date / close 等保留字段。
3. 在构建股票池中选择股票，在编辑区选择预览股票，点击“预览特征”。预览只显示已有版本日历上的原始值，末 120 条用于绘图，不拟合 scaler。
4. 填写新的版本标识及研究 / 训练 / 验证日期，点击“开始构建”。完成后在版本选择器中选择新版本，可查看完整特征清单。
5. 在训练工作台选择新数据版本并检查日期交集，再显式检查配置或训练。旧模型不会因新增列而自动升级。

预览基于模板版本的已存日历和建版前历史预热；用户改变构建日期或股票池后，最终掩码和有效记录数可能变化，以新版本构建审计为准。

### 接口与产物

- `GET /api/feature-types` 返回白名单、公式描述和保留名称。
- `POST /api/datasets/{id}/features/preview` 接收 code 和 extra_features，不创建任务或下载数据。
- 现有 `POST /api/datasets/build` 增加 extra_features；未提供时继承模板定义，显式空列表则仅构建基础列。
- 当前每版本最多 32 列。追加定义保存于 research_config.json、manifest.json、scaler_params.json；代码实现哈希记录于 manifest。
- 每个指标的具体定义在 `src/data/feature_definitions.py`，基础 20 列仍由原有预处理逻辑维护。公式不是任意可执行文本。
