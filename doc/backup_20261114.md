# 每日备份：把不能重算的东西放一份到仓库外

日期：2026-11-14。工具 `tools/backup.py`。

## 为什么

2026-11-14 我写错的一个裁剪脚本删掉了 `reports/runs` 的 **11.94 GB**，而那里从来不在 Git 里。
账本与影子记录因为入库才活下来，配置、股票池清单、研究产物则完全没有副本。

**一个备份工具只有在它拒绝"看起来完成了"的时候才有用**，所以这个工具做了三件事：
拒绝把压缩包写进项目内部、默认写到一个**实测可写**的外部目录、以及能用哈希验证压缩包没坏。

## 备什么

| 来源 | 内容 | 为什么不能重算 |
| --- | --- | --- |
| `reports/account` | 三本账的成交、快照、配置 | 真实成交不可重建 |
| `reports/shadow` | 影子记录与状态 | 只追加，删了就没了 |
| `configs` | 研究配置 | 小，但改动无痕 |
| `data/stock_list` | 股票池与名称清单 | 依赖抓取时点 |
| `reports/runs` | 当前研究的判定输出 | 可复跑，但复跑结果可能与当时不同 |

**实测 48 个文件、456 KB。** 刻意做小：一天 12 GB 的备份活不过一周。

## 落在哪：**能写的地方都写一份**

`E:` 是外置移动硬盘——它是最好的副本（唯一离开这台机器的），但大部分时间是拔掉的。
所以工具不选"一个"目标，而是**遍历所有可达目标各写一份**：

| 目标 | 什么时候有 | 能防什么 |
| --- | --- | --- |
| `E:/ F:/ G:/a_share_backups/a_share_project` | 外置盘插上时 | **整机损坏、磁盘故障** |
| `%OneDrive%\a_share_backups\...` | 一直在 | 误删、本机磁盘故障（有云端副本） |
| 项目同级 `_backups` | 一直在 | 仅误删 |

**拔掉的盘不是错误**，只是跳过；`--status` 会把每个目标单独列出来：

```
E:\...\a_share_project      reachable=False archives=0   age=None
C:\Users\...\OneDrive\...   reachable=True  archives=2   age=0
D:\...\_backups             reachable=True  archives=1   age=0
```

`reachable=False` 是常态（盘没插），**`reachable=True` 但 `age` 很大才是问题**——那说明盘插着却没在备份。

> **踩到的坑**：`Get-PSDrive` 会列出未挂载的盘符并报容量，`mkdir` 却报"系统找不到指定的文件"。
> 所以"盘符存在"不能当作"能写"，必须真的写一个探针文件；而 `status` 用的探针**不会创建目录**，
> 否则它会把"不存在的盘"探测成"可用"。

**建议**：外置盘每周插一次，让 `age` 归零；这比每天插拔更现实。

## 怎么用

```powershell
python -B -m tools.backup            # 打一个包，保留最近 30 个
python -B -m tools.backup --verify   # 用清单里的 sha256 逐个核对最新包
python -B -m tools.backup --status   # 落在哪、有几个包、最新一个的时间
```

压缩包里带 `manifest.json`：每个文件的相对路径、大小、sha256。`--verify` 会重新打开压缩包，
把每个文件重算一遍哈希再比对——**不信任"压缩成功"这个返回值**。

## 现在的状态

- 第一次备份已生成：OneDrive 与同级 `_backups` 各一份，48 个文件、456 KB
- `--verify` 结果：`ok: true`，48 个文件全部通过
- 保留策略：最近 **30** 个（约一个月，一周一个也够用）

## 还差一步：挂到每日任务上

现在它是**手动**的。要变成每天自动，需要把它加进 21:00 那条任务（或新建一条）。
**改定时任务需要你明确同意**——我没有动它。

如果加，建议形式是：21:00 任务末尾追加一次 `python -B -m tools.backup`，
失败时把错误写进当日输出（不要静默跳过，否则"备份失败"和"没备份"看起来一样）。
