# 数据与 PPO 实验工作区

首版日期：2026-09-26；说明更新：2026-10-24。对应[一体化设计](data_feature_ppo_integration_plan.md)与[PPO 改进规划](ppo_training_improvement_plan.md)。本文件记录已经实现的工程能力，不把研究建议全部标为完成；当前研究状态见[实施进度](implementation_plan.md)。

## 已实现

- “实验流程”页面：固定数据模板、股票池、日期、特征、完整 PPO 参数和最多五个种子；配置保存后不可原地修改，修改时复制为新修订。
- 来源绑定：记录模板及选定下载 manifest 哈希；源配置被修改时阻止继续执行旧批准。
- 本地预检：检查模板 / 下载来源、缺少股票、重复来源冲突、实际训练交集和按真实特征数估算的 rollout 内存。
- 分别批准缺项下载、数据准备、配置检查和训练，不因下载或构建完成就自动训练；没有自动最终测试入口。
- 跨下载批次按股票组合 HFQ 来源，保留原文件采集时间，重复来源内容不同则拒绝合并，不默认覆盖。
- 多种子配置检查和训练通过同一个研究任务槽串行执行；活跃或已成功的同阶段同指纹提交会复用，不重复启动。
- 任务、数据版本、模型配置中的 experiment_id / recipe 哈希与验证结果可追溯；可停止本实验未完成任务。
- 失败下载可显式重试；任务重启沿用既有恢复机制，不自动重训。相同种子多次尝试时汇总只展示最新尝试的已完成结果，不回退到更好看的旧成功结果。

## 使用顺序

1. 启动工作台后打开 `http://127.0.0.1:8765/#experiments`（端口以终端实际输出为准），新建实验配置。
2. 可直接使用已发布数据版本，也可勾选构建新版本，选择模板原始文件或 HFQ 下载快照组合，并配置追加特征。
3. 保存后查看缺项、冲突、预算与来源绑定。缺项下载需要单独勾选网络许可；只有历史来源模式才可下载。
4. 点击“准备数据”，成功后数据版本链接可跳转数据管理。实际训练日期由新版本及 lookback 的共同有效区间决定。
5. 点击“检查全部种子”，全部检查通过且输入指纹仍相同后，才能明确批准训练。
6. 训练完成后查看各个种子的验证收益、Sharpe、回撤、成本和等权对照；任务页可查看优化、组合行为与资源图表。

网络许可只覆盖当前固定配置的缺项；正式训练批准按完整 rollout 对齐后的总步数展示。前端限制之外，后端仍校验配置检查、资源预算、数据和源码指纹。

## PPO 补充能力

高级设置现已开放 gamma、GAE lambda、PPO clip、target KL、熵系数、价值系数、梯度上限、隐藏层尺寸及恒定 / 线性学习率。线性学习率对超出请求预算的完整 rollout 做边界截断，避免负学习率。

选模可增加验证回撤幅度、日均总换手和最低记录数门槛；通过门槛后仍以 Sharpe、累计收益排序，完全平局保留较早模型。每次验证记录候选是否合格及原因，旧选模规则不改写。

训练诊断现在包含实际优化器 step、最后一次裁剪后梯度范数、当前学习率、KL / clip、每维潜在动作熵、现金、实际换手、目标变化、仓位限制、订单原因、采样 / 更新墙钟时间和 CUDA 已分配显存。组合统计独立汇总，避免被 SB3 日志清空时遗漏；缺失诊断不补造为零。

回测指标增加 Sortino、Calmar 和最长水下记录数，并生成 PPO 与各基线的收益差、回撤幅度差、成本差、日收益相关和信息比率。空分母保持 null，旧报告未有新字段时显示为空，不伪造历史指标。

## 当前边界

- 来源组合是不同股票的完整单文件组合，不拼接同一股票的日期碎片。请求范围合格不代表每个交易日齐全，实际覆盖由构建与训练交集再次审计。
- 预热与实际特征质量仍主要在预览 / 构建阶段确认，尚未实现任意特征依赖图或自动推导所有补充数据下载需求。
- 资料、分钟、资金流、分红和指数扩展快照仍不自动进入 PPO。指数特征适配及真实时点型数据连接仍需独立研究。
- 多种子已经可编排；滚动时间窗口目前需建立独立数据版本与实验修订，没有自动多折搜索。
- 本轮没有引入 LSTM、Transformer、多环境采样、全训练耐心早停或新的奖励 / 调仓规则。target_kl 仅用于单次 PPO 更新控制。
- 不支持精确续训；OOM、数据契约失败或非有限参数不会通过自动改 batch / 改设备来掩盖。

## 首版验收与正式研究（2026-09-26）

工程离线回归 127 项通过、13 项外部联网测试排除。浏览器实际完成两股、两个种子的独立构建、配置检查和各 64 步训练；参数确实更新，新增诊断和多种子结果可见。这些烟雾运行不计入正式效果研究。

监控修复后的最终离线回归为 129 项通过、13 项外部联网测试排除，保留 3 条非失败警告；最终全量浏览器为 24 项通过。正式九次训练的模型和数值结果保持原样。

正式多种子训练已完成，协议在运行前登记于 [训练协议](ppo_multiseed_protocol_20260926.md)。19 股、3 配置 × 3 种子，共 73,728 步；见 [报告摘要](reports/ppo_multiseed_20260926_summary.md) 和 [详细报告](reports/ppo_multiseed_20260926.md)。工程通过不代表策略优于等权。

正式训练完成后，全量浏览器回归 24 项通过，包含旧训练、取消、预测、迁移、冻结但不执行最终测试，以及新实验与特征流程。旧端到端测试的训练池显式移除了在 2022 截止前无完整特征的 301165 / 603296，不通过关闭日期校验来让测试通过。

协议监控使用短连接，对 GET 网络异常有限重试，POST 不自动重发。需要恢复已有任务监控时使用 `--monitor-only`；它不提交检查、构建或训练。模型仍保留实际训练时的源码提交，后续监控修复不会改写旧模型元数据。
