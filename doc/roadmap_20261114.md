# 路线图：2026-11-14 之后值得做的事

日期：2026-11-14。这份文档回答一个问题：**在 alpha 已关闭、执行层已建成的前提下，接下来做什么还有价值。**
每条都写了"问题 / 数据 / 成本 / 产出 / 判据"，够直接开工。

## 0. 判断依据

先摆清楚为什么是这些方向，而不是别的：

1. **alpha 已关闭**：十几族横截面信号、事件类、市场杠杆两轮、PPO 十轮——全部关闭。再找 alpha 需要新数据（分钟线、另类数据），
   而不是新想法；而新数据的成本远高于本项目能承受的。
2. **框架是"接受 beta + 风控"**，所以价值的来源是：**降低回撤、减少执行损耗、提高安全腿收益、让测量可信**。
   这四件事都不需要新的收益来源，只需要把已有的东西做扎实。
3. **执行层已经从"纸面"变成"每天在跑"**，所以任何"跑起来才能发现"的问题，现在优先级最高。
4. **本仓库反复付出过代价的坑**（样本被污染、产物被误删、口径混淆），所以"测量基础设施"本身就是一个方向。

## 1. P0：有时间窗或防再次损失

### 1.1 影子的对照基准

- **问题**：链式净值现在只有一个绝对数。20 个交易日后（2026-12 上旬），怎么判断 S2 这条腿是好是坏？
- **没有它会怎样**：只能看到 "+2%" 或 "−3%"，无法区分"市场涨"与"规则有效"。
- **做法**：影子记录每天同时写两个基准——**沪深 300 收盘**与**同池 297 只等权**；页面画出三条线。
- **数据**：前向面板里已有（沪深300 走 `index` 面板或新浪；等权从面板 close 直接算）。
- **成本**：半天。**产出**：一张对照图 + 12 月评价时可直接引用的差。
- **判据**：预先写死"20 个交易日后 S2 相对同池等权的超额 ≤ 0 即关闭这条腿"，不做事后解释。

### 1.2 关键产物每日备份

- **问题**：`reports/runs` 误删过一次（11.94 GB，不可恢复）。账本与影子目前在 Git 里，但**配置、前向面板、研究产物**没有副本。
- **做法**：每日任务结束后，把 `reports/account`、`reports/shadow`、`configs`、`data/online/*/manifest` 打成一个带日期的 zip，
  存到仓库外（另一个盘或 OneDrive），保留最近 30 份。
- **成本**：2 小时。**产出**：`tools/backup.py` + 一个每日任务。
- **判据**：连续 7 天备份成功且能从一个 zip 完整恢复出一本账。

### 1.3 live 开账（只有你能决定）

- **问题**：执行层至今 **0 笔真实成交**，`slippage()` 永远返回空，滑点只是回测里的常数 0.05%。
- **不做的后果**：整套闸门、账本、月报都没被真实世界检验过。
- **成本**：你决定是否下单；我这边半小时把成交价记进 ledger。

## 2. P1：研究价值最高且现在就能做

### 2.1 安全腿的现金增强

- **问题**：安全腿占 40%，一直放 511010（5 年期国债 ETF）。它的 carry 随利率走，**当前 5 年期国债只有 1.33%**，
  而且有久期风险（利率上行 100bp，净值约 −4%）。
- **替代**：国债逆回购（GC001/204001）或货币基金——carry 更接近短端利率、**几乎没有久期**，但需要每天滚动（逆回购到期需手动）。
- **数据**：`bond_zh_us_rate`（已验证可用，日频 2/5/10/30 年，当前到 2026-11-13）；逆回购收益率需另取（东财/新浪）。
- **成本**：1–2 天（含一笔"滚动摩擦"的假设检验：每天手动续作的成本与漏作风险）。
- **产出**：三张对照——511010 / 逆回购 / 货基 在 2019-2026 的 carry、波动、以及接进 CPPI 后的组合年化与回撤。
- **判据**：只有在**同回撤**下年化提升 ≥ 0.3pp，且漏作一天的风险被量化后，才考虑替换；否则维持 511010。

### 2.2 利率环境的刻度表

- **问题**：`final_plan` 说"当前环境预期 +4.9%~+6.6%；7% 需要安全腿 carry 回到 2.5–3%"。这个地图现在只是两句话。
- **做法**：用 2019–2026 的 5Y 收益率分档（<1.5% / 1.5–2.5% / 2.5–3.5% / >3.5%），
  在每个利率档里跑同一套 CPPI（129 起点），得到"利率 → 中位年化 / 最差回撤"的表。
- **为什么值得**：它把"现在该期待几个点"变成一个可查的数，而不是一句提醒；也能量化"7% 目标需要什么环境"。
- **数据**：全部本地（债券收益率 + ETF 价格）。
- **成本**：1 天。**产出**：一张四行表 + 一段结论（当前 5Y=1.33% 落在哪一档、对应预期多少）。
- **判据**：这是描述性研究，不设"通过/不通过"，但**不得**据此调楼层或倍数。

### 2.3 数据健康监控

- **问题**：每天的前向面板与行情抓取，**没有任何质量检查**。缺几只、涨跌停几只、某个代码价格突然 ×2、成交量归零——
  现在都要人去看。
- **做法**：`tools/data_health.py` 每天落一行 JSON：面板覆盖只数、缺失代码、异常涨跌幅（>30%）、停牌数、
  与前一日的价格跳变、报价 asof 与今天的差。异常时在 21:30 那条 `tools.daily_ops` 的输出里标出来。
- **为什么值得**：这次 QDII 溢价研究里，一个 **1:2 拆分未回溯**就让某天算出 96% 的假溢价；这类问题应该被自动发现。
- **成本**：半天。**判据**：能在历史上把这 6 个已知假点（2022-03 拆分前后）标出来。

## 3. P2：等条件

### 3.1 执行质量度量（等 live 成交）

- 有了真实成交后，算：计划价 vs 成交价、计划权重 vs 实际权重、单笔冲击、漏单率。
- 现在的 `account_ledger slippage` 已经埋好位置，只缺数据。

### 3.2 溢价熔断落地（等你批准改执行代码）

- 见 [QDII 折溢价](etf_premium_20261114.md)：**不装硬闸门**，只做"≥ 95 分位拒绝加仓" + 每笔成交记录当时溢价。

### 3.3 P 段前向验证协议（等数据）

- P 段已被 `plan_backtest` 的四个起点与一次 topK 冒烟触碰，不再是"没读过"的样本。
- 唯一干净的做法是**前向**：从 2026-11 之后逐日累积，写一份预登记（判据、停止规则、评价日），到 3–6 个月后再看。

### 3.4 溢价的每日快照（如果想把样本拉长）

- 现在能做的是"历史回算"（净值序列 + 价格）。若要**实时记录**当时的可见溢价（含 IOPV），需要一个每日快照；
  历史 IOPV 拿不到，只能从现在开始积累。

## 4. 明确不做

| 方向 | 为什么不做 |
| --- | --- |
| 再找横截面 alpha | 十几族全关；新族需要新数据，成本高于本项目 |
| PPO / 任何 RL | 十轮全关，方法已提取进 [PPO 价值](ppo_value_20261114.md) |
| 市场杠杆闸门 | 两轮关闭；重开需要 SSE+SZSE 全市场合计并回溯到 2015 |
| 黄金替代标普 | 已测：收益 −0.2~−0.4pp，回撤只改善 −1.1~−1.5pp，Sharpe 不变 |
| 把保证金补到 2026 | 那条线已关，补数据没有读者 |
| 换更便宜的同标的 ETF | 费率差 <0.2pp/年 × 30% 仓位 = <0.06pp，不值得一个研究轮 |
| 调 K / 调楼层 / 调倍数 | 敏感性都做过：K 只是风险旋钮、楼层与倍数在 5–8 内已成平台；再调就是在已花样本上挑参数 |

## 5. 建议的执行顺序

```
第 1 周：1.1 影子对照基准   →  1.2 每日备份   →  2.3 数据健康
第 2 周：2.2 利率刻度表     →  2.1 安全腿现金增强
之后：   3.x 按条件触发（live 成交 / 你批准改代码 / 数据累积够）
```

**1.1 必须在 12 月之前完成**——它是这一期影子唯一的评价依据；其余都可以往后排。

## 6. 一句话

**接下来值得做的，没有一件是为了更高的收益，全部是为了"让已有的收益不被损耗、让已有的判断不被误读"。**
这也是这套框架（接受 beta + 风控）在 alpha 关闭之后，唯一还站得住的活法。
