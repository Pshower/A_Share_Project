# 研究工作台前端与服务端设计

日期：2026-09-25。

状态：**设计已完成，前端、Web API 与后台任务管理尚未实现。** 本次只编写设计，不安装依赖、不启动服务器、不训练模型。已有 Python 框架及轻量实验状态见 [实施进度](implementation_plan.md)，整体计算流程见 [Pipeline](../pipeline.md)。

## 1. 产品目标与边界

建立本地运行的中文研究工作台，让用户通过浏览器完成：

```text
选择/构建训练数据 -> 配置训练 -> 启动任务与观察进度
       -> 自动保存 checkpoint -> 选择已存模型
       -> 验证回测 / 冻结后的最终测试 -> 查看与导出报告
       -> 选择日期、账户与关注股票 -> 查看模型目标仓位及买卖意图
```

前端是现有研究框架的操作界面，不重写标准化、PPO、成交规则或绩效公式。第一版面向单机、单用户、Conda `Graduate`，只用已有本地数据，不自动联网下载行情，不接券商或实盘订单。

“预测动作”表示模型在给定日期和账户状态下的组合决策，不是股票价格预测、上涨概率或保证可成交的买卖建议。当前数据截止 2024-12-31，界面必须显示数据截止日，不能把历史结果标成实时行情。

## 2. 现有能力与待补接口

| 用户需求 | 可以复用的实现 | 前端接入前需补充 |
| --- | --- | --- |
| 选择数据与股票 | `ResearchData`、manifest、质量与来源审计、`stock_codes` | 数据集目录索引、配置表单、预检、异步数据构建 |
| 开始训练 | `src.training.train`、`make_model`、配置与步数预算 | 持久任务队列、结构化进度事件、安全停止 |
| 展示训练信息 | `training_updates.csv`、`training_audit.json`、`logs/progress.csv`、选模记录 | 事件流、实时图表、阶段状态、错误与断连恢复 |
| 保存/选择模型 | `PPOAgent.save/load`、checkpoint 元数据与哈希 | 模型目录、可信来源注册、名称/备注、兼容性预检 |
| 回测 | `evaluate_agent`、`run_policy`、基线与报告 | 异步评估、报告浏览、结果比较、测试曝光记录 |
| 冻结测试 | `freeze_selection`、`validate_frozen` | 冻结确认流程、冲突说明和显式测试任务 |
| 选择股票预测动作 | `PPOAgent.inspect_action`、`act`、`MarketDataProvider`、`Portfolio` | 截至指定日期的观测构造、账户快照验证、意图输出及研究用途标记 |

当前没有 Web API、HTTP 任务系统、模型数据库、账户快照导入接口或任意日期单次推理入口。不得把现有类可组合调用等同于这些产品功能已经完成。

## 3. 页面与导航

左侧固定导航：**数据、训练、模型、回测、动作预测、任务记录**。默认打开训练任务列表，直接展示已有实验与“新建训练”操作，不做宣传落地页。系统环境、数据口径、活动任务显示在紧凑顶部状态栏。

| 页面 | 主区域 | 关键操作与结果 |
| --- | --- | --- |
| 数据 | 数据版本表、日期划分、股票明细和质量表 | 选择版本、筛选股票、预检、从本地原始文件构建新版本 |
| 训练 | 任务列表；新建表单；训练详情页 | 检查配置、开始训练、请求停止、查看候选模型 |
| 模型 | 可排序模型表及详情侧栏 | 选择已有模型、查看契约、设置显示名称、用于回测或预测 |
| 回测 | 新建评估、曲线、指标表、持仓与订单 | 验证评估、冻结测试、同口径比较、导出报告 |
| 动作预测 | 模型/日期/账户选择，组合汇总和股票动作表 | 计算确定性动作、筛选关注股票、导出结果 |
| 任务记录 | 所有构建/训练/回测/预测任务及事件 | 查看日志、失败原因、产物；以原配置创建新任务 |

页面路由保存任务 ID、模型 ID 和筛选条件。训练结束后可直接跳到选中模型；从模型进入回测或预测时自动带入其股票池、特征、scaler 和成本契约，避免反复填写。

## 4. 训练数据选择

### 4.1 使用已有版本

数据版本列表显示版本号、价格口径、覆盖日期、股票数、特征数、训练/验证/测试边界、校验状态和来源。初始应能识别 `research_v3`，但不硬编码只有一个数据版本。

进入版本详情后用带搜索和复选框的股票表选择训练股票，显示有效训练行数、首个有效日期、缺失比例与排除原因。提供“全部”“当前轻量 32 只”“清空”选择操作；用户自己的选择保存为有序股票集合。预览抽样只显示真实存在的数据，不伪造股票名称、行业或交易状态。

已有版本的标准化边界不可直接编辑。界面分别显示：

- **模型训练股票池**：本次 `stock_codes`，决定环境维度。
- **scaler 拟合股票池**：数据版本已有的 `train_codes`，不因缩小训练股票池而变化。
- **训练日期与预热范围**：由数据契约决定，显示扣除预热后的实际起始日期。

两套股票池不同不一律禁止运行，但不能将结果标记为“未见股票泛化”。所有选择最终由后端校验；前端不得仅以股票数等于模型维度判断兼容。

### 4.2 修改日期或构建新版本

用户修改训练截止、验证截止、总体研究日期、特征定义或 scaler 拟合股票时，转入“构建新版本”，不覆盖原版本，不直接拿原 scaler 配合新日期声称无泄漏。

构建表单选择后端登记的本地原始数据集合、输出版本名、日期划分和拟合股票池；服务端复用预处理流程。原始文件缺失时明确报错，不自动下载。不接受浏览器提交任意文件系统路径。

构建期间版本不可用于训练，成功后校验 manifest、scaler、价格、特征和哈希，再登记为可用。失败产物标记未完成，不伪装成有效版本；重试创建新任务，不能覆盖成功版本。输出目录名由服务端安全生成。

首版回测日期同样优先使用版本固定的 `val`/`test` 切分，不提供表面上可编辑、实际不生效的任意日期输入。自定义研究区间通过新版本与新实验协议处理。

## 5. 训练配置与监控

### 5.1 新建训练

表单分为数据、模型、训练预算、执行假设、存储五组，可从默认或轻量配置创建草稿。默认选择本地 CPU；只有后端检测到受支持设备时才提供其他选项。

| 配置 | 控件与规则 |
| --- | --- |
| 数据版本与股票池 | 版本选择器、股票多选表 |
| 网络和窗口 | 数字输入；默认 MLP 128/64、lookback=1 |
| 总训练步数、种子 | 必填正整数预算、非负整数种子；不隐式训练 |
| rollout、batch、epochs | 数字输入；batch 至少 2 且整除单环境 rollout |
| 学习率、gamma、GAE、clip、KL | 数字输入及后端范围校验，不用文字按钮模拟参数选择 |
| 验证频率 | 以 rollout 为单位的整数 |
| 成本、初始资金、单票上限 | 默认继承研究配置；修改后形成新的独立配置快照 |
| 保存位置与名称 | 选择已登记的存储区；输入显示名称和备注，不能改写模型文件路径 |

提交前先生成预检摘要：实际股票数、特征/动作形状、有效训练日期、数据完整性、价格口径、内存估计和按 rollout 补足后的步数。内存和耗时估计标记为估算；无历史测速时不显示精确完成时间。

“检查配置”只执行无训练检查；“开始训练”单独提交带预算的任务。点击前显示最终配置摘要，避免把检查误当成训练。检查通过不能保证训练收敛。

### 5.2 实时训练详情

顶部使用紧凑指标带：任务状态、当前阶段、实际步数/有效预算、更新次数、耗时、速度、最新验证 Sharpe 和当前候选 checkpoint。时间戳区分 UTC 存储时间与本地展示时间。

主区域为三组标签页：

- **训练曲线**：策略/价值损失、近似 KL、裁剪比例、explained variance、单步奖励统计、目标与实际现金、换手及费用。
- **验证记录**：每次评估的 checkpoint、收益、风险、成本和是否被选中；训练 reward 不与回测累计收益混为一个指标。
- **日志与产物**：结构化事件、原始日志、错误堆栈、参数变化审计、保存加载结果及模型链接。

训练步数达到 100% 后，若还在验证、保存或生成报告，仍显示对应阶段，不直接宣布任务成功。ETA 排除无法估计的剩余评估成本或标注不确定性。缺失指标显示空值及状态，不填零，不连接虚假的连续曲线；NaN/Inf 单独标记异常。

刷新浏览器或切换页面不会启动第二个训练，也不会终止后台任务。默认每 1 秒推送汇总更新，日志分批输出；历史图表按需降采样，原始记录保留。

### 5.3 停止与恢复边界

第一版支持“请求停止”，不提供尚未实现的“暂停/精确续训”。停止信号由工作进程在安全边界处理，停止后只登记已经完整写入的 checkpoint，状态为已取消，不伪装成正常训练完成。

现有训练代码收到 callback 停止后仍可能进入 `_on_training_end`、验证和保存流程，必须新增明确的取消分支：跳过最终选模/比较，记录取消原因与最后有效产物。未完成 PPO 更新的 rollout 不能标成已训练 checkpoint。

超时强制终止只针对该任务拥有的进程及其子进程，保留日志并标记中断。不得终止系统全部 Python/Conda 进程。“重新运行”创建新任务和新目录，不表示从上次停止处精确续训。

## 6. 已存模型选择与管理

模型表读取受管实验目录下的 `model.zip`、`metadata.json`、选模记录和审计，不扫描整个电脑。首先支持现有 `reports/runs/ppo_lightweight/train_8192_20260925/best_7680` 等产物的登记。

每行展示：显示名称、来源实验、checkpoint 步数、数据版本、股票数、网络/窗口、价格口径、验证指标、保存时间、哈希校验和可用状态。初始化模型、最终模型、验证最优模型、迁移模型和中断任务产物必须分别标记。

- 选择模型时展示兼容性明细：特征及顺序、scaler、股票及顺序、lookback、成本/本金、动作映射版本、网络结构、数据指纹。
- 默认自动保存初始、候选和最终模型；用户选择的是保存到哪个受管存储区以及给哪个 checkpoint 命名，不依赖在浏览器中手动下载才能保留模型。
- 名称、备注与收藏放在工作台数据库，不修改原始模型元数据或冻结记录，不移动/重命名 checkpoint 目录。
- “最优”只表示该次验证规则选出的 checkpoint，不等于跨实验或实盘最优；不能按最终测试收益提供自动选模按钮。
- 初始未训练模型可以用于显式标记的接口检查，默认不能作为正式回测候选。
- 首版不接收任意上传的 PyTorch/ZIP 权重；只加载用户可信的本地产物。校验哈希不等于可安全加载陌生模型。
- 从其他股票池迁移必须走独立操作和预检，生成新实例、新来源记录，不能绕过普通 `load()` 的严格契约校验。

模型删除不放入首版主流程；先提供隐藏/归档元数据，保留已被报告、冻结记录或运行任务引用的文件。

## 7. 回测与结果比较

### 7.1 验证回测

选中模型后自动带入其训练时的配置，默认 split 为验证。用户选择共同基线后提交后台任务，复用 `evaluate_agent`、`run_policy` 和 `performance`。界面不能只改手续费显示值而仍用原配置计算。

当前模型契约同时绑定成本和初始资金。首版将这些字段锁定为只读；费用压力测试属于新的显式研究模式，不能静默忽略契约不匹配。不同版本、股票池或成本口径的报告可以分别查看，但默认不并排排名，先提示比较条件不同。

结果页包含净值/回撤/成本曲线、收益风险指标表、现金与持仓数量、每日持仓、订单状态和拒绝原因。用户可点选曲线日期联动当日账户与订单，查看完整报告或下载 CSV/Markdown/PNG。

训练中的确定性验证收益与随机探索 episode reward 使用不同图表和标签。现金策略 Sharpe 无定义时显示空值，不当作零或无穷大参与排序。

### 7.2 冻结测试

测试流程为“选择验证选出的模型 -> 检查模型/配置/数据/源码 -> 写入冻结记录 -> 确认测试区间与曝光状态 -> 执行测试”。默认不自动连带测试；普通模型表任意选中的 checkpoint 不能冒充验证最优。

复用 `freeze_selection` 和 `validate_frozen`，不删除源码检查或自动改写旧冻结文件。当前冻结记录覆盖 `src` 下所有 Python 文件，因此未来新增 Web 模块也可能使历史记录与当前源码不匹配：历史报告仍可查看，但重新测试应使用对应可信代码版本或另行说明的新实验，不能悄悄重新冻结并声称从未看过测试结果。

工作台记录测试运行及人工查看历史：首次绩效评价、重复复现、观察测试日期动作分别记账。已有轻量实验的 2023-10-23 至 2024-12-31 区间登记为已查看，不能因新建任务、删除页面筛选或换模型而恢复成“未见”。记录按数据谱系和日期区间关联，不只按任务 ID。

重复测试可作为明确标记的复现操作，但不是新的独立样本外证据。前端不提供“根据测试结果继续优化”的自动流程。

## 8. 选择股票预测动作

### 8.1 必需输入

| 输入 | 默认与限制 |
| --- | --- |
| 模型 | 已存的可信、契约匹配模型；显示原股票池与 scaler |
| 数据与日期 | 默认该模型数据版本；只能选择本地有数据的交易日，显式显示 as-of 日期 |
| 账户 | 明确选择“全现金假设账户”“已保存的研究账户快照”或“手工录入假设账户” |
| 关注股票 | 默认只筛选展示原模型池中的股票，不改变网络输入池 |
| 推理方式 | 默认确定性，不调用 `learn()`，不改账户或模型 |

手工账户输入现金、各股持仓股数、可卖股数、必要的锁定/应收信息，后台统一验证日期、非负性、整数股数和账户对齐，再通过现有 `Portfolio` 计算权重。全现金模式使用模型配置本金，不在不知情时把已有持仓当成零。

当前 `positions.parquet` 只有股数，不能恢复完整现金、成本、应收和 T+1 锁定状态。需要新增版本化账户快照格式及导入验证，不能直接从这个文件声称精确恢复账户。模型池外的已有持仓必须拒绝或先走显式股票池迁移，不能静默丢弃其市值。

### 8.2 单股查看与改变股票池的区别

如果模型在 32 只股票上运行，用户勾选其中 1 只股票，后台仍构造完整 32 只股票的观测、组合上下文和现金动作，只筛选结果行。

例如“查看 000001”不等于将模型变成单股票策略。若用户确实要在 1 只或新的 N 只股票上重新配置资金，必须选择“更换推理股票池”，显式调用共享参数迁移，重新创建对应空间，记录为迁移推理实验。softmax 分配会改变，不保证原股票权重不变或新池上有相同效果。

首版不接受任意代码后自动下载；新股票必须已有足够本地历史、相同特征定义和训练 scaler，且通过迁移契约检查。新增行情版本的 manifest 哈希通常与旧模型不同，不能把它冒充原版本；新版本推理需单独设计并验证数据兼容适配，不放宽默认加载规则。

### 8.3 只使用截至 t 的信息

新增只读 `ObservationBuilder`，输入模型契约、日期 t 和账户快照。先将行情/特征裁到 t，按模型顺序和历史窗口构造观测，复用行情与账户计算，不调用 `TradingEnv.step()` 来获取下一日信息。

必须支持在数据最后一个交易日生成动作，不要求存在 t+1 行。现有 provider 初始化至少需要两个日期，适配层须保留足够历史或对历史不足明确报错，不能通过添加虚构下一日来满足接口。

按日期 t 的收盘信息调用 `inspect_action`，返回原始/裁剪分数、有效性、目标权重和现金比例。对缺失特征、缺少持仓估值或溢出分别给出具体原因；不能用任意零价继续估值。

若选择的 t 位于曾经或尚未评估的测试区间，记录“测试日期观测/动作已查看”，但不把它误标为已经完成绩效回测。查看后再据此调参同样影响研究独立性。

### 8.4 输出与买卖意图

页面顶部展示模型、日期、账户净值、目标现金与当前现金，主体为可排序股票表：

| 列 | 语义 |
| --- | --- |
| 股票代码、数据状态 | 真实代码、有效/预热不足/缺数据等 |
| 当前仓位、目标仓位、差额 | 模型目标，不是成交结果 |
| 买入 / 卖出 / 清仓 / 仓位基本不变 | 从权重差和持仓推导的展示标签，不是额外离散模型动作 |
| 当前已知买卖限制 | 根据 t 日信息；不预告 t+1 状态 |
| 收盘参考调整金额 | 仅以 t 日净值估算的方向和量级，不承诺成交 |
| 原始分数、掩码与映射原因 | 可展开诊断，不包装成收益因果解释或上涨概率 |

展示标签使用明确、版本化的小容差避免浮点噪声，不能借此修改模型输出或交易规则。接近零但非零的目标显示减仓，不随意标为精确清仓。“仓位基本不变”也不代表明天不下单，因为开盘价变化可能触发再平衡。

第一版不输出“确定可成交股数”。若后续增加参考订单预览，必须在复制账户上复用 broker，并标明假设价格、时点、费用和约束；绝不能偷看 t+1 开盘价来包装成 t 日预测。真正下一日成交只属于回测执行。

当前 `hfq_research` 下，所有参考金额/股数仍为研究口径，不能作为现实报单指令。页面不提供真实交易按钮。结果导出保存模型哈希、输入日期、账户快照、数据契约、完整股票池与展示筛选条件，便于重复核对。

## 9. 技术架构

拟采用 React + TypeScript + Vite 前端，FastAPI 后端，SQLite 存储任务/模型索引，SSE 推送状态和日志，图表采用 Apache ECharts，图标采用 Lucide。版本在实际实现时核验并锁定，本次不安装或声称已完成兼容验证。

React 官方文档描述了组件与状态驱动界面，Vite 官方指南提供前端开发/构建入口；此处选择它们是为了表单、长任务状态与交互图表，不改变 Python 算法实现。[React](https://react.dev/learn)、[Vite](https://vite.dev/guide/)

训练放在独立 Python 工作进程，而非 HTTP 请求或轻量后台回调中。FastAPI 官方文档也区分响应后的轻任务与重计算任务；本项目首版用本地进程管理，不引入 Redis/Celery。[FastAPI Background Tasks](https://fastapi.tiangolo.com/tutorial/background-tasks/)

```text
浏览器：React 页面、表单、图表、任务状态
    | REST 请求 + SSE 事件
本地 API：校验、目录索引、任务提交、报告读取
    | SQLite 持久状态 + 参数化子进程启动
任务管理器：队列、进程所有权、停止请求、事件归档
    | 固定 Graduate 解释器 / 参数列表 / 独立配置快照
Python worker：复用数据、训练、冻结、评估和推理服务
    | 原子提交产物与结构化事件
现有 data/、reports/runs/ 和新增工作台状态目录
```

首版训练/数据构建/回测共用一个重任务执行槽，其余排队。短推理也在受控进程执行，默认排队或受独立小额度限制，不阻塞 API 主线程；不在同一个 PPO 对象上并发训练和推理。所有资源上限由后端执行。

开发时前后端分进程；打包后由本地服务托管静态资源，优先同源运行。端口占用时选其他端口并打印实际 URL。默认绑定 `127.0.0.1`，不暴露到局域网或公网。

## 10. 任务、事件与存储契约

### 10.1 状态机

```text
queued -> validating -> running -> succeeded
                    |          -> failed
                    |          -> stop_requested -> cancelled
                    -> failed
服务/进程异常退出 -> interrupted
```

`phase` 另行表示预检、准备数据、采样、优化、验证、保存或报告生成，不能仅根据日志文本推断状态。取消排队任务立即取消；运行中的停止先确认已收到请求，再在安全边界生效。

任务至少记录 ID、类型、状态/阶段、父实验、不可变配置及哈希、数据/模型 ID、请求预算、实际步数、创建/开始/结束时间、进程 ID 与启动标识、心跳、退出码、错误、产物和事件序号。

开始任务使用幂等键，双击或网络重试不会重复训练。新配置必须产生新任务。后台启动时核对原任务进程归属和心跳；失去可确认的进程标记中断，不自动重新训练，不因 PID 重用误杀其他程序。

### 10.2 结构化事件

新增轻量事件输出接口，CLI 仍保留现有 CSV/JSON。worker 写追加式 JSONL，任务管理器持久化状态并通过 SSE 推送；不靠正则解析 SB3 控制台表格。已有 CSV 可能整表重写，历史兼容读取必须处理暂时不完整，不能将读取失败当成训练失败。

```json
{
  "sequence": 101,
  "job_id": "job_id",
  "timestamp": "UTC ISO-8601",
  "type": "training_update",
  "phase": "optimizing",
  "timesteps": 2560,
  "effective_budget": 8192,
  "metrics": {"value_loss": 0.0002, "approx_kl": 0.02}
}
```

事件区分阶段变化、指标、checkpoint 保存、验证完成、日志与错误。SSE 使用序号和 Last-Event-ID 恢复；断线显示断开状态，重连先取状态快照再补事件。归档过期或序号缺口必须明确提示，不伪造完整曲线。

图表按任务/模型/数据分组，禁止跨任务接续步数。日志保存原文但展示为纯文本；时间窗口与容量有上限，原始文件可按权限下载。不可序列化的 NumPy 类型转换到 JSON 标准类型，非有限数字不默默变成 0。

### 10.3 产物与数据库

SQLite 只存任务、配置快照、模型索引、标签、事件游标和测试查看记录，行情及权重仍在原版本目录。API 使用资源 ID，路径在后端解析。为新增任务创建独立运行目录，使用临时文件/目录和完成标记原子发布；写到一半的 ZIP 或 JSON 不登记为可用模型。

工作台展示 `training_audit`、冻结文件与 `completion.json` 时按生成阶段解释状态。例如冻结文件里的 `test_evaluated=false` 是冻结时快照，不能覆盖之后 completion 中的已测试状态，也不能改写冻结文件来同步 UI。

服务端重启后只扫描受管根目录并核验已有产物，可重建索引；丢失数据库不应丢失模型文件或改动数据。首版不保证进程崩溃后的精确训练续跑。

## 12. 本地安全与界面规范

### 安全边界

- 仅监听 loopback，使用本地随机会话凭据与同源请求校验；不能因为服务在 localhost 就允许任意网站发起训练或读文件。
- 若开发前后端端口不同，只允许明确的 Origin；SSE 用同源会话方案，不把长期凭据放入 URL。
- 子进程使用固定模块与参数数组、`shell=False`，不执行用户输入的命令；Windows 后台进程不弹出终端窗口。
- 数据/模型/产物 ID 映射到已登记根目录，解析真实路径并拒绝 `..`、符号链接或 junction 越界、任意绝对路径和任意程序加载。
- 不读取或展示 `.codex`、API 密钥、系统环境秘密；错误日志做敏感字段过滤。Markdown/日志按不可信文本渲染，避免脚本执行。
- 对上传/导出大小、股票数、窗口、预算与并发设后端上限；用户可在明确的本地设置中调整，不在浏览器中绕过。
- 第一版不提供任意模型上传、远程执行、自动下载、券商连接或一键实盘功能。

### 界面风格

采用紧凑研究工具布局：中性浅色、清晰表格、稳定工具栏、有限强调色。以真实净值/损失图表作为主要视觉内容，不加宣传大标题、装饰图片、渐变背景或嵌套卡片。

常用工具使用 Lucide 图标并提供悬浮提示；开始训练等重要命令使用图标加文字。股票使用复选框，多模式使用分段控件，参数使用数字输入，视图使用标签页。状态与涨跌同时提供文字/正负号，不能只靠颜色区分。

桌面以表格和图表并排/上下分区；窄屏折叠导航、表单单列，明细表保留横向滚动和固定关键列，不通过缩小全部字体强行塞入。按钮、图表和表格行使用稳定尺寸，避免加载和动态标签导致跳动。

页面只显示必要字段、状态、校验和研究口径，不放大段“如何使用本系统”或功能宣传文案。错误定位到字段并保留表单；加载、无数据、损坏模型、缺少依赖、无有效股票、后台断开、任务取消等均有明确状态。

## 14. 实施顺序与验收边界

进度勾选统一维护在 [实施进度的前端工作台配套任务](implementation_plan.md#前端工作台配套任务)，本文只定义顺序和完成标准。前端工作不是阶段五稳健性研究的完成证明。

1. 建立只读数据/模型/报告目录和 API，导入现有轻量实验；先确认资源定位、损坏识别和契约说明。
2. 建立配置预检、持久任务、独立 worker、SSE 和安全停止；验证重试幂等、刷新重连及故障恢复。
3. 完成数据构建、训练表单和实时详情，将已存模型串联到验证回测与报告浏览。
4. 接入冻结测试和测试查看记录，明确历史冻结源码不兼容与重复复现的处理。
5. 完成截至 t 的观测与账户快照、完整股票池推理、单股筛选与显式迁移。
6. 做端到端、契约/因果性、安全与桌面/窄屏界面验收，补齐启动与运行文档。

主要验收要求：

- 原 CLI 和既有离线测试保持通过；Web 默认检查不调用训练，显式训练仅启动一次工作进程。
- 合成数据的 API 与 CLI 产生相同确定性动作、账户和回测指标；轻量实测不重新使用已查看测试结果调参。
- 训练时可观察真实事件和完整状态；断开页面后任务继续，重连恢复；取消不产生伪成功记录或损坏的可选模型。
- 模型初始化/已训练、验证最优/最终、契约匹配/不匹配均可区分；任何未通过校验的模型不能进入正式评估。
- 修改 t 之后的数据不改变 t 的预测；只筛选展示股票不改变完整组合输出；更换股票池必须走显式迁移。
- 手工账户的现金、市值、应收、可卖股数和日期校验可手算核对；不能丢弃池外持仓或使用下一日价格预览订单。
- 页面清晰区分目标仓位、意图、参考量级和实际成交；缺数据不伪造当前动作或价格。
- 路径穿越、跨源提交、重复请求、越界预算、陌生模型和非有限输入被拒绝；日志、文件和模型权限受控。
- 使用 Playwright 检查桌面和窄屏的完整流程、键盘焦点、空/错/忙状态、图表真实数据和截图，不出现遮挡或越界。详细表允许受控横向滚动，页面本身不失控溢出。
