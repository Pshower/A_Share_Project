## 2. 怎么算的（只有一个自由度）

```
缓冲垫        = 净值 − 0.90 × 峰值
风险腿目标    = 6 × 缓冲垫 / 净值            （夹在 0% ~ 100%）
风险腿内部    = 25% 沪深300 + 25% 中证500 + 50% 标普500（人民币）
安全腿        = 100% 中短国债；--cash-safe 时改为 50% 国债 + 50% 货币 ETF
是否调仓      = |风险腿目标 − 当前风险腿| ≥ 5% 才动，否则持有
```

这就是 [统一策略最终规格](unified_strategy_final_20261115.md) 的第 2 节，没有第二套逻辑。

## 4. 怎么落到账本

```bash
python -B -m tools.daily_allocation --book=paper            # 只读：打印建议
python -B -m tools.daily_allocation --book=paper --apply    # 落账
python -B -m tools.daily_allocation --book=live  --apply    # 实盘账
```

- `--apply` 只在**触发带宽**时产生成交；否则只重记当日快照并写一条决策日志
  `reports/runs/daily_allocation/decisions.jsonl`。
- **过期保护（两道）**：① 若今天是交易日、但报价还停在前一天，`--apply` 直接报错——
  21:30 跑的时候新浪若还没发布当日收盘，缓存里就是昨天的价，绝不能用它记账；
  ② 报价距今天超过 **4 天**同样拒绝。日历读不到时降级为只做第 ② 道，并在决策日志里留痕。
- 写入走账本自己的校验（`record_trade` 拒绝超卖、超现金买单、非整手）。
- 页面接口只读：`GET /api/recommend/unified?book=paper|live` 只返回建议，不下单。

## 4.1 每日定时任务（2026-11-15 合并为一条）

| 项 | 值 |
| --- | --- |
| 任务 | `schedule-b05741a4`「每日执行层检查与全资产落账（paper 与 live）」 |
| 时间 | **周一至周五 21:30（Asia/Shanghai）** |
| 动作 | 交易日闸门 → 刷新行情 → 两本账分红/记账/检查 → 落账 → 每月首日补月报 → 汇报 |
| 硬约束（写进任务提示） | 行情过期时**只报告不落账**；`safe_to_send` 为 false 就不落账；不改策略参数；不手工编辑账本；结果不符就停下报告 |

**合并记录**：原来的 21:00「账户每日检查」已并入本条并删除。
合并的理由是重复：21:00 的 `check` 只出信号，21:30 的落账会把同一套 CPPI 判断再算一遍；
而且**分红同步只存在于 21:00**，一旦它失败，21:30 会在"分红未入账"的状态下算净值。
现在顺序固定为 刷新行情 → `sync-dividends` → `mark` → `check` → `apply`，不会颠倒。

每日任务因此只剩 **1 条**（另有 20:00 的 S2 研究管线与周六 18:00 的资金流归档，频率与用途都不同）。

首次按新口径运行：**2026-11-16（周一）21:30**。
