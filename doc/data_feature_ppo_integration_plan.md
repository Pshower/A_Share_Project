# 数据获取、特征管理与 PPO 一体化方案

日期：2026-09-26。基于当前代码与提交 `ab78ca5` 分析。本文是下一步集成设计，不表示已实现自动编排、扩展数据入模或新训练实验；本次仅更新文档。

## 1. 核心结论

三部分不应只是互相增加跳转按钮，而应围绕一份可冻结的“实验配置”协作：

```text
股票池 + 时间划分 + 特征方案 + PPO 参数
                    |
              数据需求与缺口检查
                    |
        已存快照复用 / 用户授权下载缺项
                    |
        数据质量、口径、时点与覆盖准入
                    |
        原始特征计算 -> 训练期 scaler
                    |
             不可变训练数据版本
                    |
       多股日期交集 + 模型契约 + 资源检查
                    |
              PPO 无训练检查
                    |
         用户明确启动训练 -> 验证选模
                    |
       冻结 -> 单独授权最终测试 -> 报告
```

每个结果都必须能回答：来自哪些原始文件、使用哪套特征和标准化参数、实际训练了哪些股票和日期、采用哪个模型及执行假设。完成下载不等于数据可训练，构建成功也不等于策略有效。

## 2. 已有能力与缺口

| 环节 | 当前已有 | 本方案待补 |
| --- | --- | --- |
| 数据获取 | 日线批量下载、分口径快照、失败重试；五类扩展数据独立归档 | 按实验需求检查缺项；跨批次来源组合与冲突处理 |
| 数据管理 | 基础 20 列 + 最多 12 个参数化追加指标；预览、独立版本及 scaler | 可复用特征方案、依赖描述、数据可用性预检 |
| 日期校验 | 多股和 lookback 的共同连续区间；不自动移动原训练分界 | 在下载和构建前解释范围是否可行、给出明确调整路径 |
| PPO | 动态特征维度、CPU/CUDA 选择、配置检查、训练与验证、显式冻结 | 将任务与同一份实验配置和数据来源绑定；统一状态视图 |
| 扩展数据 | 资料、资金流、分钟、指数、分红下载与预览 | 分类标准化、时点校验、特征或账户适配器 |
| 审计 | 文件哈希、版本 manifest、模型契约、任务事件 | 跨下载 / 构建 / 训练的完整关联与失败恢复 |

首个版本应先打通现有日线链路，不同时实现全部扩展数据入模或更换 PPO 网络。

## 3. 统一实验配置

建议新增 ExperimentRecipe，先保存在本地数据库，执行时冻结 JSON 快照。草稿可以修改，已执行版本只能派生新修订，不能原地改写。

| 配置组 | 应记录的内容 |
| --- | --- |
| 数据需求 | 股票代码与市场、目标频率、价格口径、研究区间、数据类型 |
| 来源绑定 | 明确的快照 ID、逐股票文件映射及哈希、采集与修订信息 |
| 特征方案 | 基础定义版本、追加名称 / 类型 / 窗口、列顺序、依赖及实现哈希 |
| 时间政策 | 训练 / 验证 / 测试分界、决策时刻、预热、缺失与跨频率规则 |
| 拟合与泛化 | scaler 拟合股票池、实际训练股票池、开发 / 保留股票池 |
| 环境 | 资金、手续费、滑点、T+1、仓位和成交限制、研究价格口径 |
| PPO | 网络、lookback、步数、随机种子、超参数、请求及实际设备 |
| 运行授权 | 网络范围、是否允许正式训练、测试曝光授权及资源预算 |
| 结果关联 | 数据版本、检查任务、训练任务、选定模型、冻结和报告 ID |

“使用最新数据”只能作为草稿中的选择条件。执行前必须解析为具体快照和文件，之后即使出现新下载也不能改变正在执行的实验。

同一实验可有多次运行，例如多个随机种子；每次有独立 run_id。UI 标签、说明文字可以修改，不能因此改变数据版本或模型权重。

## 4. 从特征反推数据需求

特征方案不仅保存名称和窗口，还应声明所需字段、频率、口径、预热和可得时间。系统据此产生下载清单，而不是先下载所有接口再尝试拼表。

| 特征 / 用途 | 必需数据 | 缺失时的处理 |
| --- | --- | --- |
| 现有收益、波动、均线、ATR 等 | 同口径日线 OHLCV；部分指标需成交额 / 换手率 | 阻止构建或显式更换特征，不自动填零 |
| 相对指数表现、市场状态 | 对齐的股票和指数历史 | 未有指数适配器时不能勾选为已支持的训练特征 |
| 资金流比例 | 股票资金流与对应时点的金额等字段 | 标记可用区间及缺失，不能用当前近段历史回填多年 |
| 基本面特征 | 有历史版本和可得时间的资料 / 财务数据 | 当前资料快照只展示，不用于过去训练 |
| 分钟聚合特征 | 覆盖决策日前所需时间段的分钟记录 | 不足历史则不可构建长期日线特征 |
| 分红、送转记账 | 未复权价格及完整事件参数 | 保留研究模式，不凭分红表自动启用真实账户 |

下载区间要覆盖特征预热，不能只从用户输入的“首个训练日”开始。有限窗口可推导最少历史条数，但条数不等于自然日；EMA 等有历史种子的指标沿用完整来源锚点，不能用任意短窗口假装与旧模型一致。

预检应分开显示：原始覆盖、特征有效覆盖、lookback 后的共同区间、各时间分段实际记录数。不能只比较文件名或请求起止日期。

### 下载计划与复用

生成计划后列出每个股票 / 数据类别的已有、缺失、陈旧、冲突状态，以及预计调用数和上限。默认只准备计划，不联网。

本地复用必须匹配代码、口径、频率、来源政策与文件哈希，且覆盖预热和目标日期。跨批次组合属于待实现能力：重叠记录相同可去重，内容冲突必须展示差异并由用户明确选择来源，不默认用“较新文件覆盖较旧文件”。

组合完成后发布新的来源 manifest，保留所有原始快照，不修改旧批次。合并成功仍要做共同日期和特征质量检查。

## 5. 扩展数据如何进入模型

增加一个“标准化与准入”层，位于补充归档和特征计算之间。现有 supplements 保留原始字段的做法继续保留，不直接作为训练输入。

每类适配器声明：主键、时间列、单位、缺失值语义、修订处理、允许连接方式及有效期。供应商字段变化时拒绝或隔离该批次，不根据列位置猜测。

### 接入优先级

| 优先级 | 数据 | 建议路径 |
| --- | --- | --- |
| 首先 | 股票日线和现有技术指标 | 完成统一实验流程；不增加新外部依赖 |
| 其次 | 指数日线 | 先做独立基准对照，再评估少量相对表现 / 市场状态特征 |
| 条件成熟后 | 个股资金流 | 审核单位和收盘可得性；仅在有真实覆盖的区间做消融实验 |
| 单独研究 | 分钟行情 | 先建立完整性和频率规则，不能直接替换现有日线环境 |
| 仅展示起步 | 个股资料 | 名称行业辅助筛选；时点型市值 / 股本不能倒填历史 |
| 独立账户工程 | 分红记录 | 补齐事件和未复权价格后再适配撮合与记账，不对 HFQ 重复加分红 |

未来财报还需要区分报告期、首次公告、修订公告和该版本数值何时可得。今天下载到的历史报告值，即使附有公告日期，也不自动证明该值当时已公开。

### 时间连接规则

建议记录 `event_time`、`available_at`、`captured_at` 和 `revision_id`。模型在决策时刻只能连接 `available_at <= decision_time` 的记录；不得使用“最近日期”双向匹配。

按日特征必须定义收盘数据何时可使用。当前是收盘决策、下一开盘执行；若真实采集要到收盘后一段时间才能完整，就应将研究决策时点明确为收盘数据确认后，而不是宣称收盘瞬间已经获取。

分钟数据向日线聚合时，未完成柱不能当完整日线。跨频率连接只能使用当时已完成且已可得的高周期结果，不能提前使用整周或整月最终值。

不是所有字段都可以向前填充。行业归属、财务指标等应有有效期与修订规则；流量、成交量、日收益不能因缺失自动复制上一日。需要缺失指示特征时也要显式加入新特征契约，而不是在推理阶段临时塞列。

## 6. 构建与标准化

拟分成来源审核、未标准化特征计算、训练期拟合和版本发布四步，但首版编排可继续调用现有整体构建器，不急于拆成多个服务。

发布的数据版本应绑定来源组合、特征定义、日历、列顺序、价格表、掩码、时间分界、scaler 和拟合样本审计。初期保持当前一个版本绑定一套 scaler，不创建无法解释的“同一版本多个可变 scaler”。

若将来缓存未标准化特征，应新增明确命名的产物；现有 `all_stocks_features.parquet` 已包含标准化结果，不能误当作原始指标缓存。

更改训练截止、拟合股票池、特征定义、缺失政策或源文件，都要生成新版本。仅改变 PPO 学习率、种子或训练步数时，可以复用完全相同的数据版本。

训练股票池和 scaler 拟合池必须同时显示。严格未见股票实验中，保留股票不能进入拟合池；当前旧版 scaler 的范围不能被重新描述为已经满足这种隔离。

多股交集继续保持连续性：不要删除中间无效日期后把两个相隔的日子当作相邻交易日。若用户需要修改截止以适应数据，返回构建步骤重新确定分界和 scaler；不能在训练页悄悄缩短截止却复用更晚数据拟合的统计。

## 7. PPO 训练衔接

训练页接收已经发布的数据版本和冻结的实验配置，不接受“一个原始下载目录”直接训练。

启动前检查：来源与产物哈希、特征定义及列顺序、scaler、股票池、lookback、共同连续区间、各分段长度、账户约束、设备和资源预算。输出实际可训练日期数与 PPO rollout 步数；重复采样同一历史并不会增加独立市场日期。

新输入维度创建新模型。旧 checkpoint 仅在既有迁移规则允许、特征 / scaler / 架构契约匹配时显式迁移；新增两列指标不能直接扩展旧权重后称为继续训练。

先运行不更新参数的配置检查，验证观察空间、动作、一步环境执行和保存加载。检查通过后才允许正式训练。AShareGPU 使用现有单研究任务槽，不因实验编排而新增并发 GPU 训练，也不承诺 GPU 对小模型必然更快。

实验页面同时展示训练损失、验证表现、换手、费用、仓位及成交拒绝原因。特征有效性要通过固定对照、多个种子和消融实验评估，不能仅根据某条指标曲线好看就认定它能提升 PPO。

## 8. 交互与任务编排

建议增加“实验配置”视图，现有下载、数据管理、训练和任务页仍保留为可独立使用的详细操作页。

| 步骤 | 用户操作 | 系统输出 |
| --- | --- | --- |
| 定义实验 | 选股票、分界、特征方案及训练参数 | 可修改草稿与预计依赖 |
| 检查数据 | 查看来源、实际覆盖与缺项 | 不联网的准备报告 |
| 准备数据 | 明确批准缺项下载和新版本构建 | 来源快照、构建任务与质量报告 |
| 检查训练 | 确认最终版本与实际区间 | 无训练检查结果及资源信息 |
| 开始实验 | 明确确认训练预算 | PPO 训练和验证结果 |
| 评估模型 | 选定模型并冻结，单独确认测试曝光 | 回测报告与审计记录 |

第一版不做默认“一键下载后立即训练”。未来若提供组合执行，也必须让用户明确批准每一类动作及固定预算；最终测试始终单独确认。输入被修改后，旧批准不能无条件用于新来源或新训练预算。

任务关系可用本地 SQLite 的父运行 ID、依赖 ID 和结果引用实现，复用现有 JobManager，不引入外部消息队列。下载继续占下载槽，构建 / 检查 / 训练占现有研究槽。

拟定状态为：草稿、待数据、数据准备中、待质量确认、可训练、检查中、可启动、训练中、待评估、完成 / 失败 / 已取消。每个状态显示具体阻塞项，不把已排队显示成正在训练。

## 9. 恢复、复用与审计

- 某股票下载失败：保留成功项，阻止依赖完整股票池的构建；用户可重试或修改草稿股票池，不能后台静默剔除。
- 构建失败：不发布 ready 版本；调整参数后派生新修订。旧模型和旧版本仍可读取。
- 训练中断：保留已有完整 checkpoint，继续遵循当前不保证精确续训的边界，不用编排器伪装恢复了优化器和环境状态。
- 服务重启：按已持久任务和产物哈希恢复状态，不能看到旧任务未完成就自动重新下载或重训。
- 复用判断：来源哈希、股票池、日历、口径、特征定义、实现版本、分界和拟合池均一致才可复用构建结果；模型还需绑定训练参数和种子。
- 局部修改：只重新执行受影响的下游步骤，不重新获取未变化的原始数据；任何重跑都生成可追踪的新运行记录。

建议在报告中给出可展开的来源路径：原始快照 -> 特征方案 -> 数据 / scaler 版本 -> 检查任务 -> 训练 -> 模型 -> 冻结 -> 回测。失败原因也附在对应环节，而不是只显示一个总失败状态。

现有冻结机制校验较广的源码范围。未来可以研究区分计算核心和界面代码的版本范围，但在专门修改并验证冻结协议前，不放宽现有校验，也不重写历史冻结记录。

## 10. 两个典型流程

### 对比新增指标

复用同一日线来源、股票池与时间分界，建立基础 20 列版本 A，以及追加 ATR 比例 / 回撤的版本 B。分别使用各自训练期 scaler，按相同预算和种子运行。只在开发验证区间比较风险、费用和稳定性，选定方案后再冻结。

A 与 B 因预热造成有效日期不同，应报告差异，并在公平对照中采用共同有效评估日期。不能把验证区间不同导致的收益变化归功于特征。

### 扩池或延长历史

修改草稿股票池或研究末日，先检查现有来源及缺项，再由用户批准下载。组合源数据后重新计算交集与时间分界，构建新版本；是否可迁移旧模型必须通过显式契约检查。扩池并不自动证明共享网络已经泛化。

若新增的是资金流等短历史数据，先检查它是否使全体股票共同区间过短。可选择暂时不使用该特征，或设计独立短区间研究；不能用零填充多年历史来维持原训练长度。

## 11. 建议落地顺序

| 工作包 | 范围 | 完成标准 |
| --- | --- | --- |
| A：现有链路串联 | 实验草稿、固定来源引用、构建后带版本进入训练检查 | 一个两股实验可从已存日线走完无训练检查，全程可追溯 |
| B：需求与缺口检查 | 特征依赖、预热、覆盖、下载计划和批准 | 只对缺项请求网络；修改配置后旧批准失效 |
| C：来源组合与恢复 | 跨批次合并、重复冲突、依赖任务和恢复 | 冲突不被静默覆盖，失败不启动下游，重启不重复任务 |
| D：一类扩展数据入模 | 优先指数日线，先基准再少量特征 | 时点 / 单位对齐测试、固定对照及独立特征版本 |
| E：实验比较 | 多种子、消融、成本诊断和统一报告 | 不混淆验证与测试，不宣称单次收益即策略优势 |

这些是本方案工作包，不替代项目阶段一至五；均为待实施建议。优先 A，其次 B/C，不能因扩展下载已存在就直接跳到 D。

## 12. 验收与结论

除已有单元测试外，应增加跨环节验收：来源冲突、缺历史、缺预热、无共同区间、变更特征、变更 scaler、预算超限、取消和重启，以及无授权网络 / 训练 / 最终测试被阻止。用固定合成数据检查时间连接不引用未来，再以本地小股票池完成真实构建和无训练检查。

本设计不新增训练结果。旧测试区间已经查看，后续调参不能继续称其为未见测试；新的保留区间需要在看结果前登记，并披露来源修订和固定股票名单偏差。

结论：先把“获取什么、为什么获取、如何变成特征、最终训练用了什么”连接起来，再增加指标与外部数据。统一实验配置和明确准入规则，比把三个页面简单合并成一个页面更重要。
