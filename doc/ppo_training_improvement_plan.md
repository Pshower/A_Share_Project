# PPO 训练、监控与评价改进规划

日期：2026-09-26。一体化方案已提交为 `ee4d59d`。本文件记录设计和可选研究方向；后续工程实现、正式训练授权及结果见下方更新，不改写已有实验或已暴露测试集的结论。

后续实现更新：高级参数、线性学习率、选模风险门槛、组合诊断、多种子编排及配对评价已实现，见 [运行说明](experiment_workbench_runbook.md)。用户随后明确批准正式多种子训练，另行登记 [协议](ppo_multiseed_protocol_20260926.md)。时序网络、多环境、新奖励等仍是待研究选项，不能将本设计全文视作已完成功能。

## 1. 设计时判断（2026-09-26）

当前共享股票网络、训练期标准化、独立价格表、GPU 配置和数据契约已具备运行基础。主要不足是实验可信度与训练过程的可解释性，而不是模型规模不足。

已有轻量报告显示：最终测试 PPO 收益 29.71%，20 日等权 29.30%，但 Sharpe 为 1.464 对 1.640，最大回撤幅度为 7.77% 对 5.85%；手续费加滑点约 2.43 万元对 0.22 万元，日收益相关约 0.983。因此尚不能认为 PPO 更好。67.95% 是模拟订单记录的拒绝比例，不是真实交易所拒单率。来源：[已有实验摘要](reports/ppo_lightweight_20260925_summary.md)。

建议优先顺序：行为与日志诊断 -> 公平对照与选模 -> 小范围参数研究 -> 时间信息与样本覆盖 -> 更复杂模型。先分清模型是否真正学到有效的仓位变化，再谈增加网络和训练预算。

## 2. 超参数管理

界面应区分训练参数、模型结构和交易环境参数。手续费、仓位上限、股票池、特征及 scaler 的改变，不应伪装成普通学习率调整。

保留“基础设置”和“高级设置”，记录完整解析后的参数快照。运行中的参数不可原地修改；修改生成新实验修订。明确展示请求预算、按完整 rollout 对齐的预算和实际完成步数。

### 参数与小规模候选

下表当前值来自 `configs/ppo.json`；候选值是本项目的待验证实验建议，不是适用于所有市场的最优参数。

| 参数 | 当前值 | 首轮研究建议 |
| --- | --- | --- |
| learning_rate | 3e-4 | 先比较 1e-4 / 3e-4；衰减日程另作实验 |
| n_steps | 256 | 比较 256 / 512，固定股票池与总交互预算 |
| batch_size | 64 | 首轮保持；随后比较 64 / 128 并检查整除与内存 |
| n_epochs | 10 | 对照 5 / 10，观察样本重复优化和 KL |
| gamma | 0.99 | 暂时保持；后续单独评估 0.95 / 0.99 / 0.995 |
| gae_lambda | 0.95 | 暂时保持；方差问题明显后再比较 0.90 / 0.95 / 0.98 |
| clip_range | 0.2 | 更新过大时对照 0.1 / 0.2，不追求裁剪率为零 |
| target_kl | 0.03 | 对照 0.01 / 0.03；它限制一次更新，不是整场训练早停 |
| ent_coef | 0 | 行为诊断后才评估 1e-4 / 1e-3；需控制动作维度影响 |
| vf_coef | 0.5 | 先保持，价值估计异常时连同奖励尺度检查 |
| max_grad_norm | 0.5 | 先保持，先新增裁剪前后梯度日志 |
| lookback | 1 | 优先独立比较 1 / 5；有效后再研究 20 |
| hidden_sizes | 128 / 64 | 先不扩网络，保留容量相近的对照 |
| logit_bound | 8 | 先记录潜在动作饱和及权重变化，不直接提高上限 |
| 验证间隔 | 10 个 rollout | 固定验证次数或按交互步数统一，避免不同配置选模机会不等 |

参数含义及 rollout、KL 和日程支持参考 [SB3 2.7.1 PPO 文档](https://stable-baselines3.readthedocs.io/en/v2.7.1/modules/ppo.html)。本项目的候选数值不是该文档给出的金融任务推荐值。

### 约束与容易误解的地方

- 多环境时 rollout 大小是 `n_steps * n_envs`，预算、batch 和验证频率要一起调整；现有单环境校验不能直接照搬。
- `gamma` 的折扣时间尺度不等于持仓天数，lookback 也不等于策略持仓期限。
- 当前 N+1 维高斯潜在动作再映射为权重，PPO 概率计算必须继续使用原始潜在动作，不能替换成裁剪后的权重。
- 高斯熵通常随维度变化；共享股票 log_std 扩展到更多股票后，同一 ent_coef 的总作用可能改变。应同时报告总熵、每维熵和有效股票数，不能跨股票池机械复用调参结论。
- 现有训练输入已经标准化。不直接叠加动态观测标准化；若研究奖励缩放，保存缩放配置，评价仍返回实际净值和费用。
- 现有共享策略未实现 gSDE，不能仅增加界面开关就宣称支持。

不做上述参数的全排列。按预先登记的假设一次改变一个主要因素，先修正数值或行为异常，再扩大搜索空间。

## 3. 训练过程怎样展示

### 总览

顶部显示阶段、请求 / 实际步数、唯一市场日期数、股票数、特征数、实际设备、耗时和吞吐；将采样、优化、验证和保存耗时分开。验证较慢不能显示为训练卡死，剩余时间只能给估计值。

保留任务日志和配置页，新增“优化诊断”“组合行为”“验证对照”三个视图。曲线支持原始值与平滑值，异常点必须保留；平滑窗口和指标单位可检查。

| 视图 | 指标 | 回答的问题 |
| --- | --- | --- |
| 优化诊断 | policy loss、value loss、approx KL、clip fraction、熵、explained variance、学习率、梯度范数 | 是否在学习，更新是否过大，价值估计是否异常 |
| 组合行为 | 目标 / 实际现金、目标 / 成交后持仓、权重变化、上限触发率、潜在动作饱和 | 动作是否经过映射后几乎不变，是否常年接近现金或等权 |
| 成交约束 | 实际换手、费用、滑点、成交 / 拒绝原因 | 收益是否被频繁小额调仓和整手限制消耗 |
| 验证对照 | 固定区间净值、回撤、Sharpe、基线差异、成本 | 模型效果是否改善，而不仅是训练 loss 下降 |
| 数据覆盖 | 实际训练日期、缺失情况、有效股票数、mask 比例 | 模型实际见到了哪些市场状态 |
| 资源 | 采样 / 优化时间、CPU、进程内存、CUDA 已分配 / 峰值显存 | 当前瓶颈是否真在神经网络 |

SB3 日志字段语义参考 [Logger 文档](https://stable-baselines3.readthedocs.io/en/v2.7.1/common/logger.html)。这些视图是设计目标；组合、梯度、分阶段耗时等核心采集随后已接入，具体字段以[实验工作区运行说明](experiment_workbench_runbook.md)为准，并非 SB3 日志自动提供的全部内容。

### 必须纠正的展示语义

设计时回调已记录 portfolio 指标，但 `record_update()` 向前端发布的 metrics 主要筛选 `train/` 字段，因此当时需要逐项检查采集、聚合、持久化和展示链路。后续已补充组合统计独立汇总；这里保留原问题背景，不再表示当前仍未采集。

设计时 `_n_updates` 不能直接当成真实优化器 step 数，因此要求分别显示 rollout 次数、优化轮数和实际 `optimizer.step` 计数，尤其 KL 提前停止时不能混淆。实际优化器 step 诊断随后已接入。

当前奖励为单步净值简单收益。一个 episode 的奖励求和不等于复合累计收益；训练 reward 与评价净值应分开显示，累计收益来自实际净值路径。

潜在高斯熵高，不代表映射后的组合探索充分；潜在分数不同也可能经 softmax、仓位上限、整手和费用处理后产生相同持仓。新增目标权重熵与实际成交变化诊断，但不将它们冒充 PPO 分布熵。

undefined Sharpe、无成交、explained variance 无定义等应显示“不可计算 / 证据不足”并注明原因，不能填 0 或直接判定软件故障。

### 异常与停止

非有限参数、非有限损失、错误账户状态和数据契约失败是硬停止条件。KL 偏大、价值解释度低、长期不成交、高换手等先告警，再结合持续时间判断；不为所有股票池硬编码一组“健康阈值”。

数值安全停止、验证停滞早停和用户取消必须是不同状态。验证早停的 patience、最小改善幅度、检查频率和保留 checkpoint 规则需事先登记；不得根据最终测试表现决定何时停。

## 4. 怎样评价模型好坏

### 四层评价

1. 工程正确：参数确实更新、保存加载一致、日期无泄漏、费用和现金记账正确。
2. 经济表现：成本后收益、风险、换手和资金占用优于或合理区别于可行基线。
3. 稳健性：多个种子、时间窗口、股票组及成本情景下，不依赖某一个幸运案例。
4. 可执行性：真实价格、交易状态、公司行动和账户约束有足够证据。当前 HFQ 研究模式不能跳过这一层宣称实盘可用。

第一层通过是后三层的前提，不是策略有效性的证明。

### 指标面板

| 维度 | 已有或拟补指标 | 注意事项 |
| --- | --- | --- |
| 收益 | 累计收益、年化收益、相对等权 / 动量 / 现金的收益差 | 短区间年化会放大波动，不单独用于排名 |
| 风险 | 最大回撤幅度、年化波动、Sharpe；Sortino / Calmar / 最长水下记录随后已实现，尾部损失仍属候选 | 无风险利率、年化和分母为零处理必须明确 |
| 成本 | 手续费、滑点、总 / 日均换手、成本前后差异 | 净值已扣费，不重复扣除；严格的无成本对照需重新模拟 |
| 行为 | 现金、集中度、持仓时间、目标到实际权重误差、拒单原因 | 当前拒单比例是模拟记录统计，需公开分母定义 |
| 稳定性 | 多种子分布、各开发窗口、最差窗口、主要股票贡献 | 不只展示最佳 seed，也不能把相关窗口当独立重复样本 |
| 基准关系 | 与基准收益相关、主动收益波动、条件相对表现 | 未接入且未对齐指数时不得自动称为指数 alpha |

金额换手采用现有“成交绝对金额 / 前日净值”的总换手口径，不与单边换手混用。代码中的 max_drawdown 是负值，界面和风险门槛统一用其正幅度，避免比较方向写反。

### 基线公平性

保持相同股票池、可用日期、初始资金、价格口径、费用、仓位上限和成交条件。既比较原有周期基线，也比较每日调仓基线；不能把换手频率差异全归为模型能力。

5% 单股上限意味着股票数少时最高总仓位受限：例如两股最多约 10% 股票敞口，其余为现金。两股功能验收不能与 32 股策略收益直接比较，也不能为了让曲线更好看而只给 PPO 放宽约束。

扩大 lookback 或新增长窗口指标后，要在共同有效区间做主对照，并报告各自完整可用区间的结果。股票池筛选不得参考未来收益。

## 5. 选模与研究协议

设计时 `selection_score()` 先比较验证 Sharpe，再比较累计收益，尚未显式约束回撤或换手。随后已增加可选验证回撤幅度、日均总换手和最低记录数门槛；通过门槛后仍按 Sharpe、累计收益排序。历史实验的旧规则与旧选模记录不回改。

建议采用“资格门槛 + 主指标 + 明确平局规则”，避免把多项指标随意加权成一个看似客观的分数：

- 资格门槛：数据有效、无记账错误、足够的独立日期及风险暴露，预先确定的风险 / 成本约束。
- 主指标：在开发期确定一种，例如成本后验证 Sharpe，或约束风险下的基准相对表现。
- 平局规则：可优先较低换手或更早 checkpoint，但必须事前固定。
- 样本或风险暴露不足时单列“无法可靠比较”；现金策略有效但 Sharpe 可无定义，不能强行赋值排名。

模型选择不能只挑最高收益的 seed。先按多个种子的分布选择配置，再按预定规则选择部署候选 seed 或研究组合；组合多个模型同样属于新策略，需要重新回测费用与约束。

验证频率决定可选 checkpoint 数量，不同实验应保持相同或可比的选择机会。过多超参数 / checkpoint 搜索也会过拟合验证集，需要登记总尝试数，而不是只展示最后一次成功。

### 时间与股票两条隔离线

使用滚动或扩展窗口开发验证，每个窗口的 scaler 仅使用此前训练范围。旧冻结测试区间已查看，只能作为已暴露研究数据；新的保留区间须在看结果前确定。

未见股票测试中，保留股票也不能参与 scaler 拟合或特征选择。训练阶段的池内排名等截面特征需明确定义池，不能利用未来名单。日期交集规则、幸存者偏差及今日复权历史修订仍需披露。

统计报告先给每种子原始结果和范围。三种子范围不是置信区间；如进一步使用 bootstrap，金融日收益的时间相关性要求考虑块抽样，不能直接把每日收益当作独立同分布样本。多次搜索的偏差也不会因画出误差条自动消失。可靠 RL 评价的动机参考 [Agarwal 等的研究](https://arxiv.org/abs/2108.13264)，具体金融统计方案需另行验证。

## 6. 训练方法的改进空间

### 第一优先：保持 PPO，改进实验条件

先分析频繁调仓、整手舍入和现金保留。可研究最小权重变化阈值、固定调仓间隔等执行政策，但需创建新的环境 / 动作映射版本，让训练和评价一致；不能只在回测后处理阶段减少订单以美化结果。

先维持当前净值奖励。若要研究额外换手正则，应说明它是行为惩罚，现有手续费和滑点已在净值中体现。不要用技术指标“买对卖对”的标签代替组合回报奖励。

log 净值收益、奖励常数缩放及回撤惩罚都作为独立候选。log 奖励要处理非正净值；路径依赖惩罚要检查状态是否包含所需信息；不在同一次实验同时修改奖励、网络和特征。

### 第二优先：时间信息与样本覆盖

先比较 lookback=1 / 5 的现有窗口输入，再考虑显式时序编码。随机 episode 起点只能从训练范围选择，必须提供预热、明确账户初始化，并避免跨入验证期；窗口末端的真实终止和时间截断要正确区分。

不能随机打乱原始日期后运行交易环境。PPO 对已收集 rollout 做 minibatch 随机化是另一回事；也不能把旧策略的大量历史 rollout 当作普通 replay buffer 反复混入当前 PPO 更新。

多环境应采样不同训练窗口或不同合规场景，不能只复制同一条确定性路径并称为更多独立数据。现有回调只有一个 previous_equity 和全局原因计数，扩到多环境前必须改成逐环境记账，并同步验证预算、频率和种子分配。

### 第三优先：结构与算法研究

若短窗口输入确有价值，再比较轻量时序编码或 RecurrentPPO；后者需要管理 episode_start、隐状态、序列采样、保存加载及推理状态，不能把当前自定义共享策略直接当标准 LSTM 插件使用。

Attention / Transformer 可以研究股票间关系，但需要股票顺序等变性、缺失掩码、池大小变化和显存测试。更复杂结构不自动解决日期或价格口径问题。

监督预训练随后已在独立因果动作价值研究中实际检验，开发准入但确认未合格，见[运行记录](reports/ppo_counterfactual_learning_20261017_runlog.md)；这不证明所有监督预热无效。后续标签仍须限定于训练区间并防止边界泄漏，预训练后分别评估初始化与 PPO 增量。离线 RL、SAC/TD3 等不是替换类名即可使用，须另立协议。

SB3 官方建议先考虑较简单的历史观察堆叠，并提醒非 CNN PPO 不一定从 GPU 获益。这里保留 CPU 与 RTX 3050 的实测对照，不把“CUDA 可运行”当作“训练更快”的证据。[PPO 官方说明](https://stable-baselines3.readthedocs.io/en/v2.7.1/modules/ppo.html)

## 7. 建议的首轮实验

以下是待批准协议草案，不是本次执行任务。先确定一个在严格交集下可训练的固定股票池；原默认轻量池中的晚出现股票需要显式调整或重建日期划分，不能悄悄沿用旧 masked 协议。

先做 512 步烟雾检查和同预算 CPU / GPU 计时，再开展有限候选比较。建议顺序而非全排列：

| 组别 | 唯一主要变化 |
| --- | --- |
| B0 | 现有特征和 PPO 默认设置 |
| H1 | 学习率改为 1e-4 |
| H2 | n_epochs 改为 5 |
| T1 | lookback 改为 5 |

探索性预算可从每组 3 个固定种子、每次 8,192 步起步，即 98,304 个训练交互步，不含烟雾检查和验证开销。这不是充分训练或收敛保证；只有确认有效日期、优化行为与预算合理后才扩大。

新增特征消融随后单独开展，沿用 [指标与训练建议](market_information_indicator_plan.md) 的基础版、ATR 比例、回撤对照，不与首轮所有超参数一起混合搜索。

统一训练 / 验证日期、验证频率、选模规则与交易约束，记录实际优化器更新次数和墙钟时间。由于 n_epochs 不同，不仅比较交互步数，也报告计算量差异。

多种子、独立评价和归一化原则参考 [SB3 训练建议](https://stable-baselines3.readthedocs.io/en/v2.7.1/guide/rl_tips.html)。候选晋级条件由开发协议预先确定，不从已查看测试结果倒推阈值。

## 8. 落地安排

| 工作包 | 内容 | 验收标准 |
| --- | --- | --- |
| A | 日志字段审计、真实 optimizer step、组合行为与耗时事件 | 前端数值可回查日志，缺失指标不造值 |
| B | 高级参数面板、参数快照、资源预算和配置比较 | 非法组合被阻止，运行参数与界面一致 |
| C | 基线对照、风险 / 成本面板、可版本化选模规则 | 同条件比较，历史规则不被改写 |
| D | 多种子和时间窗口实验编排 | scaler 隔离、预算受控、所有尝试可追踪 |
| E | 时间窗口、执行政策或奖励的单因素研究 | 训练与回测一致，不自动评估保留测试集 |
| F | 多环境或时序策略 | 逐环境账户统计、截断、隐藏状态及资源检查通过 |

这是 2026-09-26 的原落地顺序，不再表示全部待实施。A/B/C 的核心工程及 D 的多种子编排随后已接入；E/F 及自动滚动窗口仍需独立协议和验收。当前状态见[实验工作区](experiment_workbench_runbook.md)与[实施进度](implementation_plan.md)。

与 [数据—特征—PPO 一体化方案](data_feature_ppo_integration_plan.md) 的关系：实验配置保存这些参数、评价规则和预算，编排器执行已批准的任务；监控和评价不应成为绕过数据准入或测试曝光约束的另一条路径。
