# 执行层：账户账本与盘前闸门

日期：2026-11-11
状态：**可用**。`plan_orders` 回答"该持有什么"，这个回答"我现在持有什么、值多少、这单能不能发"。
工具 `tools/account_ledger.py`

---

## 1. 为什么需要一个账本

`plan_orders` 的输入里有 **峰值**，而峰值错一格，风险腿就全错（净值 300 万、峰值 310 万 → 42%；
峰值填成 300 万 → 60%）。这是整套东西唯一一个"输入错就全错"的地方，所以峰值不能靠人记。

账本把两件事分开：

- **真相**是 `reports/account/trades.jsonl`（只追加的成交流水）和 `snapshots.jsonl`（每日净值快照）。
- **持仓、现金、净值、峰值全部由它们推出来**，不另存一份。存一份会和流水对不上，这是记账工具翻车的标准方式。

```
reports/account/
  account.json     初始本金与起始日（init 写一次，永不覆盖）
  trades.jsonl     每笔成交：日期、代码、方向、份数、价格、费用、决策价
  snapshots.jsonl  每个标记日：净值、现金、持仓、价格
```

## 2. 命令

```powershell
# 开账（只做一次；已有账户会拒绝）
python -B -m tools.account_ledger init --capital 3000000 --date 2026-11-11

# 下单前：算目标 + 过闸门（价格默认取最新收盘）
python -B -m tools.account_ledger check --date 2026-11-12

# 成交后回填（decision-price 用来算滑点）
python -B -m tools.account_ledger trade --date 2026-11-12 `
  --code 510300 --action buy --shares 75900 --price 4.15 --decision-price 4.14

# 每日标记净值
python -B -m tools.account_ledger mark --date 2026-11-12

# 现状（净值、峰值、回撤、未标记成交数）
python -B -m tools.account_ledger status

# 月末报表
python -B -m tools.account_ledger report --month 2026-11
```

## 3. 盘前闸门拦住什么

`check` 会先按账本里的净值与峰值算出目标权重，再逐条检查：

| 检查 | 为什么 |
| --- | --- |
| **价格日期 ≠ 决策日** | 今天已经踩过：东财快照连不上只能取收盘价，取到哪天的必须核对 |
| **净值 ≤ 0.90 × 峰值时禁止买入风险腿** | 跌破楼层时目标暴露应当是 0，而不是按公式算出一个正数 |
| 份数必须是 100 的整数倍 | 整手 |
| 现金不足（含费用） | 佣金万三/最低 5 元、卖出印花税千五 |
| 卖出超过持仓 | 不允许出现负持仓 |

任何一条不过就打印问题清单并把 `safe_to_send` 置 false。**它不替你下单**，只是不让明显错的单子出门。

## 4. 滑点

`trade` 时带上 `--decision-price`（决策时看到的价格），报表会把"成交 − 决策"按方向折算成**逆向为正**的 bp：
买单成交更高、卖单成交更低都算不利。累计的 `mean_bps` 直接用来检验方案假设的双边 10bp 够不够。

## 5. 月末报表与再平衡信号

`check` 现在同时输出**当前权重、目标权重、差额（drift）**和 `band_triggered`——也就是"这个月要不要动手"。
`report --month 2026-11` 给出：期初/期末净值、当月收益、峰值、回撤、四条腿的**市值变化**、
成交笔数与费用合计、当月滑点统计。

四条腿的"变化"是**市值变化**（持仓变化 + 价格变化），不是纯收益贡献——这条必须记住，
否则会把它当成归因。

**已排定每月 1 日 20:00 自动执行**（schedule `schedule-08fde740`）：非交易日顺延；
顺序是 `mark` → `check` → `report <上月>`；只出信号、不下单；账户未开账时只提示、不创建。
`check` 的 `safe_to_send` 为 false 时逐条列出问题，不许绕过。

## 6. 已知缺口（写在这里，别装作没有）

- **不接券商**。成交要人手回填；工具不读账户、不下单。
- **ETF 分红没有建模**。场内 ETF 分红会让现金跳变，目前的账本会把它算成净值下降。
  真出现分红，正确做法是记一笔 `trade --action buy ... --shares 0`？不行——需要补一个
  `dividend` 类型的流水，这是**下一个要补的东西**。
- **价格取最新收盘**，不是实时成交价；日内下单请自己在 `trade` 里填成交价。
- **T+1 未建模**：境内 ETF 是 T+0 回转交易，所以这一天不成立；如果将来换成股票，这条必须补。
