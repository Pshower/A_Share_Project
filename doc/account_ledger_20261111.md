## 0. 三本账：实盘、模拟盘、回测

```
reports/account/live/     实盘：只记真实成交（source = manual）
reports/account/paper/    模拟盘：从 2026-11-12 起按真实开盘价成交（source = model_open）
reports/account/backtest/ 回测：2019-01-02 起的历史模拟（source = backtest）
```

三本账**没有任何共享文件**，各自的 `account.json` / `trades.jsonl` / `snapshots.jsonl` 独立。
`--account` 可以写在子命令前或后：

```powershell
python -B -m tools.account_ledger curve --account paper
python -B -m tools.account_ledger --account live check --date 2026-11-12
```

**回测账由 `plan_backtest.export_account()` 生成，与 129 起点扫描用的是同一个引擎**，
所以它的数字可以逐位对回去（2019-01-02 起：两边都是 **1,687,442.92**，最差回撤 −7.91%）。
重新生成：

```powershell
python -B -c "from tools import plan_backtest as pb; print(pb.export_account('2019-01-02', name='backtest'))"
```

**为什么必须分开**：一笔模型成交如果落进实盘账本，账本会报告一个没人持有的仓位。
三本账的净值曲线可能长得像，含义完全不同——实盘是你赚了多少，模拟盘是规则从今天起会赚多少，
回测是规则在过去会赚多少。

## 1. 为什么需要一个账本

`plan_orders` 的输入里有 **峰值**，而峰值错一格，风险腿就全错（净值 300 万、峰值 310 万 → 42%；
峰值填成 300 万 → 60%）。这是整套东西唯一一个"输入错就全错"的地方，所以峰值不能靠人记。

账本把两件事分开：

- **真相**是 `reports/account/trades.jsonl`（只追加的成交流水）和 `snapshots.jsonl`（每日净值快照）。
- **持仓、现金、净值、峰值全部由它们推出来**，不另存一份。存一份会和流水对不上，这是记账工具翻车的标准方式。

```
reports/account/
  account.json     初始本金与起始日（init 写一次，永不覆盖）
  trades.jsonl     每笔成交：日期、代码、方向、份数、价格、费用、决策价
  snapshots.jsonl  每个标记日：净值、现金、持仓、价格
```

## 2. 命令

```powershell
# 开账（只做一次；已有账户会拒绝）
python -B -m tools.account_ledger init --capital 3000000 --date 2026-11-11

# 下单前：算目标 + 过闸门（价格默认取最新收盘）
python -B -m tools.account_ledger check --date 2026-11-12

# 成交后回填（decision-price 用来算滑点）
python -B -m tools.account_ledger trade --date 2026-11-12 `
  --code 510300 --action buy --shares 75900 --price 4.15 --decision-price 4.14

# 每日标记净值
python -B -m tools.account_ledger mark --date 2026-11-12

# 现状（净值、峰值、回撤、未标记成交数）
python -B -m tools.account_ledger status

# 月末报表
python -B -m tools.account_ledger report --month 2026-11
```

## 3. 盘前闸门拦住什么

`check` 会先按账本里的净值与峰值算出目标权重，再逐条检查：

| 检查 | 为什么 |
| --- | --- |
| **价格日期 ≠ 决策日** | 今天已经踩过：东财快照连不上只能取收盘价，取到哪天的必须核对 |
| **净值 ≤ 0.90 × 峰值时禁止买入风险腿** | 跌破楼层时目标暴露应当是 0，而不是按公式算出一个正数 |
| 份数必须是 100 的整数倍 | 整手 |
| 现金不足（含费用） | 佣金万三/最低 5 元、卖出印花税千五 |
| 卖出超过持仓 | 不允许出现负持仓 |

任何一条不过就打印问题清单并把 `safe_to_send` 置 false。**它不替你下单**，只是不让明显错的单子出门。

## 4. 滑点

`trade` 时带上 `--decision-price`（决策时看到的价格），报表会把"成交 − 决策"按方向折算成**逆向为正**的 bp：
买单成交更高、卖单成交更低都算不利。累计的 `mean_bps` 直接用来检验方案假设的双边 10bp 够不够。

## 5. 月末报表与再平衡信号

`check` 现在同时输出**当前权重、目标权重、差额（drift）**和 `band_triggered`——也就是"这个月要不要动手"。
`report --month 2026-11` 给出：期初/期末净值、当月收益、峰值、回撤、四条腿的**市值变化**、
成交笔数与费用合计、当月滑点统计。

四条腿的"变化"是**市值变化**（持仓变化 + 价格变化），不是纯收益贡献——这条必须记住，
否则会把它当成归因。

**已排定每交易日 21:00 自动执行**（schedule `schedule-08fde740`；2026-11-13 由 20:15 推后，因为新浪基金历史约在 20:30 才落地当日收盘价）：非交易日顺延；
顺序是 `sync-dividends` → `mark` → `check`，**两本账各跑一遍**；只出信号、不下单；账户未开账时只提示、不创建。

> `python -B -m tools.daily_ops`。它先做 `sync-dividends → mark`（事实），再做两本账预检，
> **全部通过后才落账**（决策），任一步失败整体失败、退出码 2。`check` 的输出与脚本判定
> 现在共用 `account_ledger.check()` 同一个函数，不再有两套口径。
`check` 的 `safe_to_send` 为 false 时逐条列出问题，不许绕过。若 `mark` 报 `quotes are not from <今天>` 说明报价未发布，
**不要用 `--allow-stale` 硬写**（那会造出一天假平盘），改用 `tools.mark_when_ready` 等报价发布再补写。
每隔一段时间用 `tools.audit_marks --account <acct> [--repair]` 把每一行按当日真实收盘价重算一遍——快照与成交都查，
漂移的会说明"这个价其实是哪一天的"，并只盖日期、不动净值地把老行补上 `price_dates`。

## 6. 分红：不是价格波动，是现金

除息日基金价格按每份分红金额下跳。如果不把现金记进来，**每个除息日都会变成一次假亏损**，
而且权重最大的那条腿受伤最重——511010 是**按季度**分红的。

实测（`fund_etf_dividend_sina`，字段是**累计**分红，差分得到每次每份）：

| 代码 | 频率 | 最近的每份分红 | 占除息日收盘价 |
| --- | --- | --- | ---: |
| 510300 | 每年 1 月 | 0.1230（2026-01-19） | 2.60% |
| 510500 | 不定期 | 0.1490（2026-07-15） | 1.83% |
| **511010** | **季度** | 0.62 / 0.81 / 0.57 / 0.65 | 每季 **0.41–0.58%** |
| 513500 | 无记录 | — | — |

511010 的季度分红年化约 **2%**，而方案里安全腿的 carry 假设就是 **1.6%**——**国债腿的收益几乎全部以分红形式发放**。

用法：

```powershell
python -B -m tools.account_ledger sync-dividends                      # 从开账日补到今天
python -B -m tools.account_ledger sync-dividends --start 2026-01-01 --end 2026-09-30
```

规则写死在里面：**除息日当天及之后买入的不参与本次分红**（`shares_held_at` 只数严格早于除息日的成交），
同一个 `(日期, 代码)` **只记一次**（重复执行是幂等的），没有持仓的名字跳过。
分红记录不带费用，也不改变持仓，只加现金。月末报表把分红和费用分开列（`dividends` / `fees`）。

## 7. 成交价从哪来：不用你手填

`trade` **不给 `--price`** 时，用当天**真实开盘价**（`--field close` 换成收盘价）——那正是回测里假设的执行价：

```powershell
python -B -m tools.account_ledger trade --date 2026-11-12 --code 510300 --action buy --shares 36100
# 会打印 price 4.145、source model_open
```

每条流水都带 `source`：

| source | 含义 |
| --- | --- |
| `model_open` / `model_close` | 用当日真实开/收盘价记账，假设全部成交 |
| `manual` | 你报的真实成交价（带 `--price`） |

**`book --date` 一条命令把整个目标分配记进账本**（先卖后买，保证现金够）：

```powershell
python -B -m tools.account_ledger book --date 2026-11-12
```

### 必须说清楚的边界

模型成交假设"**开盘价能拿到全部量、没有排队、没有部分成交**"。如果你**没有真的下单**却跑了 `book`，
这个账户就从"账户"变成了"模拟盘"——两者的净值曲线看起来一样，含义完全不同。所以 `source` 必须留着，
报表里也要分开看。

真实成交与模型的差就是**你自己的执行滑点**；月末报表的 `slippage` 只有 `manual` 的行才说明这件事。

## 8. 已知缺口（写在这里，别装作没有）

- **不接券商**。成交要人手回填；工具不读账户、不下单。
- **分红的到账日按除息日记**。实际现金到账通常晚几个交易日（T+2/T+3）。这对月度净值影响很小，
  但如果哪天要对现金精确对账，必须按券商流水调整。
- **价格取最新收盘**，不是实时成交价；日内下单请自己在 `trade` 里填成交价。
- **T+1 未建模**：境内 ETF 是 T+0 回转交易，所以这一天不成立；如果将来换成股票，这条必须补。
