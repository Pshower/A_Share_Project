# 联网数据与实时交易行为判断接入方案

日期：2026-09-26。

状态：**仅完成设计，尚未接入新功能、执行联网下载或实时任务。** 按最新要求先写文档；现有工作台功能的提交与后续实现另行执行。本文不修改已有模型、数据、冻结记录或交易规则。

关联：[工作台运行说明](workbench_runbook.md)、[Pipeline](../pipeline.md)、[实施进度](implementation_plan.md)。

## 1. 目标与首版行为

在现有工作台上增加两个入口：

1. **联网数据**：选择股票、日期和明确的复权口径，下载历史日线及最新报价，保存为新的、可审计的数据快照。
2. **最新行情判断**：选择已存模型和账户，生成最新完整日线的目标仓位，再结合当前报价、数据时效和账户约束，展示买入、减仓、清仓、维持或等待的参考判断。

不接券商、不自动下单、不保存交易账户密码，也不将买卖意图描述为可成交订单。自动刷新只刷新行情和判断，不自动训练、切换模型、改变策略参数或清空账户。

首版核心路径：

```text
用户明确同意联网
  -> 下载模型完整股票池的日线和独立未复权报价
  -> 数据校验与新版本/快照登记
  -> 沿用模型训练期 scaler 处理最新完整日线
  -> 模型生成带日期和账户来源的目标计划
  -> 获取当前报价、检查时效和已知限制
  -> 展示参考买卖意图 / 仓位偏离 / 等待原因
```

## 2. “实时”具体指什么

| 模式 | 使用的数据 | 输出 | 是否属于当前模型的训练范式 |
| --- | --- | --- | --- |
| 最新完整日线决策 | 最近一个已确认完成交易日及此前历史 | 目标股票/现金比例、策略方向 | 延续日频范式，但新数据仍需契约与分布检查 |
| 当前行情下的参考判断 | 已生成的日线目标计划、当前报价、当前账户 | 仓位偏离、限制、等待/复核提示 | 独立执行前检查，不冒充盘中新策略 |
| 盘中重新计算 PPO 策略 | 未完成日线、分钟或逐笔行情 | 盘中新模型动作 | **首版不提供，需要独立数据、环境、训练和回测** |

现有 PPO 在 t 日收盘观察、t+1 日开盘执行。不能把盘中累计成交量当成完整日成交量，或用当前价替换当日最终收盘价后继续沿用原训练结论。

网页刷新时间不等于行情发生时间，供应商接口也不等于交易所直连。界面分别显示“特征截至日期”“策略生成时间”“供应商行情时间（若有）”“接收时间”“缓存年龄”。无法取得供应商时间时显示未知，不用本机抓取时间伪造行情时间。

## 3. 可以复用和必须新增的能力

| 能力 | 当前基础 | 必须新增或核验 |
| --- | --- | --- |
| 历史行情 | `DataFetcher.get_stock_hist`，已有复权参数 | 工作台显式联网入口、超时/限流、来源记录、分口径快照 |
| 最新报价 | `DataFetcher.get_all_a_spot` 等现有封装 | 字段/单位/时间核验、股票过滤、缓存时效与缺失状态 |
| 下载任务 | 现有独立 worker、事件、停止与任务列表 | 网络任务类型、请求预算、部分失败状态和断点重试 |
| 特征与 scaler | `DataPreprocessor`、`transform_new_data` | 新数据推理绑定、历史起点一致性、数据修订检查 |
| 已存模型推理 | `PPOAgent`、`predict_action` | 保留严格历史契约，另建明确的新数据兼容路径 |
| 当前账户判断 | 研究账户、权重及 broker 规则 | 真实报价估值边界、时效检查、参考意图与不可交易原因 |

现有 `download_stocks()` 只处理后复权批次，可能覆盖同名文件；不能原样作为新的在线存储层。现有行情缓存也不能直接承担“不可变快照”的职责。

具体供应商字段、时间戳、频率与服务限制在实现前核验公开文档及实际响应。不能因现有封装函数存在，就声称网络可用、报价无延迟或已经拿到权威交易状态。

## 4. 联网数据页面

在“数据管理”中增加“本地版本 / 联网采集”标签页。

### 4.1 历史下载表单

- 股票来源：当前模型完整股票池、已有股票清单、手工输入的合法股票代码。
- 日期：开始与结束日期，预检是否有足够历史预热。
- 口径：明确选择后复权、未复权，或同时下载两者；首版不混入前复权。
- 目的：归档、构建新训练版本、为指定模型准备最新推理数据。不同目的使用不同校验流程。
- 网络授权：显示供应商、预计请求次数、股票数和日期范围，用户主动点击开始才联网。
- 缓存策略：显示命中、缓存生成时间及来源；“强制更新”也是显式操作。

进度展示每只股票、每种口径的等待/下载/校验/完成/失败状态。部分失败可查看具体原因，只重试失败项，不重复下载已经成功的相同请求。

成功下载不等于已经能训练或推理。发布可用版本前还需完成模式对应的校验。用户可以保存不完整下载批次用于排查，但不能将其登记成完整可用的模型输入。

### 4.2 实时报价快照

允许针对关注股票抓取报价，但为组合估值和模型判断服务时，以完整模型股票池及账户所持资产为校验范围，不能只取画面上显示的一只股票。

展示最新价、昨收/参考价、可用的成交量/成交额、行情时间、接收时间、来源和时效状态。只展示真实返回且已核验含义的字段，不从普通报价推断未提供的停牌、ST 或涨跌停限制。

首版优先提供手动刷新；自动刷新由用户显式开启，拟默认每 60 秒一次，具体下限服从供应商限制。去重同一股票池的并发请求，不按每个页面组件分别抓取。

自动监控采用有限时长会话和租约：关闭页面或租约过期后停止后续网络轮询，用户能查看并停止仍在运行的会话。一次性历史下载任务可在页面关闭后继续，二者状态和行为必须区别显示。

## 5. 存储、修订和发布

拟新增独立目录，保留现有文件不变：

```text
data/online/history/<batch_id>/
  hfq/<code>.parquet
  unadjusted/<code>.parquet
  requests.jsonl
  manifest.json

data/online/quotes/<snapshot_id>/
  quotes.parquet
  manifest.json

data/online/inference/<binding_id>/
  features.parquet
  masks.parquet
  binding.json
```

缓存可以更新，但发布快照不可覆盖。构建中的文件使用临时目录，完整校验后再原子发布。清理失败批次不能删除已被模型、报告或计划引用的快照。

每个批次记录：供应商/接口、股票及口径、请求日期、实际覆盖日期、抓取时间、供应商时间可用性、单位、行数、唯一键、缺失与错误、文件哈希和接口版本信息。后复权与未复权文件不得同名混存，也不直接追加到原 `research_v3`。

历史数据可能被供应商修订。增量下载应有重叠区间校验；若发现历史修订，记录差异并重新生成新的推理或研究版本，不能只拼接最新一天导致前后口径不一致。必要时重取完整锚定历史，而不是静默修改旧产物。

下载的新数据用于训练时，仍经过既有新版本预处理、训练期拟合及时间切分流程。用于推理时，严格复用原模型 scaler，禁止重新拟合后伪装成同一个模型。

## 6. 数据质量与“完整日线”判定

至少检查：股票与日期唯一、代码一致、日期排序、数值有限、价格为正、基本 OHLC 关系、量额单位、缺失日期和实际覆盖范围。无复权价格与后复权价格只按键对齐，不在同一价格字段混合。

最近完整交易日需要结合明确的交易日历和供应商日线完成状态判断。不能只凭本机时间已过某个时刻，就认定当天数据已经完整；也不能把休市日请求返回的上一次报价当成当天成交。

特征预热不能简单理解为“取 60 根日线就完全等价”。MACD 等递推指标还受历史起点影响；需保存原模型的特征历史锚点，验证相同历史输入的转换一致性。仅有缩短窗口时，不能无提示宣称与原模型输入一致。

构建模型输入时：

- 使用统一确认的特征截至日，不把部分股票的昨天和其他股票的今天拼成同一决策截面。
- 缺失特征仍保留掩码，不后向填充，不用实时报价补齐未完成的技术指标。
- 下载失败、数据修订不明或关键覆盖不全时，默认阻止发布新的可用决策输入。
- 无法估值的持仓资产会使组合净值不可信，必须阻止当前账户判断，不能以零价或零持仓代替。
- 股票停牌、退市等特殊状态只有在来源明确时才能据此处理，不能仅凭接口为空就自行认定。

## 7. 新数据与旧模型的兼容性

现有模型契约包含原数据 manifest、产物哈希、scaler、特征/股票顺序、窗口、价格及执行口径。新下载文件的哈希必然不同，不能直接放宽 `PPOAgent.load()` 或把新文件登记为旧数据版本。

新增独立的 `InferenceBinding`，明确绑定：

| 字段 | 含义 |
| --- | --- |
| `model_sha256`、`policy_sha256` | 原始已存模型与参数身份，不修改模型 |
| `training_contract` | 原训练数据/特征/scaler/价格口径 |
| `source_snapshot_ids` | 本次历史与行情来源 |
| `feature_definition`、`history_origin` | 特征实现版本、历史起点与窗口 |
| `feature_as_of` | 最后一个完整特征交易日 |
| `stock_codes`、`feature_cols` | 明确有序的模型输入 |
| `scaler_sha256` | 必须与原模型相同 |
| `account_basis`、`execution_basis` | 账户估值与参考判断的价格口径 |
| `compatibility_status` | 仅行情、研究推理、实验性账户适配、拒绝 |
| `limitations` | 数据分布变化、未覆盖交易约束等 |

绑定只授权指定模式，不将原模型重新标记为在新数据上训练过。保存加载仍用原始训练契约验证权重；新数据观测另行通过绑定校验，不能用相同 shape 代替语义兼容性检查。

对新股票或不同股票数，仍走显式股票池迁移；共享网络参数不代表可以随意改变维度。预测页面筛选显示股票不改变完整模型输入。

## 8. 后复权模型与真实账户的价格边界

**不能把真实持仓股数乘以后复权价格来计算现实账户市值。逆标准化也不能取消复权。**

新功能区分三个等级：

1. **行情查看**：可以展示新抓取的未复权报价，但不因报价可用就生成模型交易判断。
2. **日线研究计划**：现有 HFQ 模型在已校验的新日线特征和明确的研究账户下输出目标权重，标记研究/分布外风险，不声称实盘适配完成。
3. **真实报价账户参考**：需要独立、明确授权的账户口径适配，使用未复权报价与真实股数估值，并经过对应历史/纸面验证；在适配未验收前，不向现有 HFQ 模型开放成交通道或真实股数建议。

真实账户比例虽然是无量纲输入，但现有模型是在 HFQ 报价、整手和费用假设下学习的，账户/执行分布仍可能改变。不能仅因为输入是比例就宣布兼容。`transfer_to()` 当前禁止价格口径变化，新适配不能通过覆盖旧契约绕过这个限制。

首轮实现可以先完成“新报价查看 + 最新日线研究目标”，再启用经过校验的当前账户偏离提示。页面对尚未通过真实账户适配的模型显示明确状态，不用填零、假设成交或把参考股数当真实数量来凑齐结果。

## 9. 当前行情下如何判断交易行为

### 9.1 固定计划与时价检查分离

模型产生不可变的 `plan_id`：记录模型、完整股票池、特征截至日、账户来源、目标权重、生成时间和有效性。盘中自动刷新不悄悄改变这个日线计划。

在计划及账户适配已经允许的情况下，用当前有效报价计算账户估值和仓位偏离：

```text
当前净值 = 可用现金 + 有效持仓市值 + 已确认应收
目标市值_i = 目标权重_i × 当前净值
参考调整金额_i = 目标市值_i - 当前持仓市值_i
```

这是“按当前报价检查既定目标”的结果，不是重新运行盘中 PPO，也不是日频回测已经验证的盘中执行策略。实际成交价仍未知。

### 9.2 输出状态

| 状态 | 条件与说明 |
| --- | --- |
| 买入参考 | 合法计划的目标高于当前持仓，且关键数据和已知检查通过 |
| 卖出/减仓参考 | 目标低于当前持仓；同时显示可卖数量、受限部分 |
| 清仓参考 | 计划确实为零目标且存在持仓，不把很小的非零值随意当成零 |
| 维持/无需调整 | 在版本化的展示/参考阈值内，不承诺下一时刻仍无需交易 |
| 等待更新 | 报价过期、缺失、跨日不一致、断网或队列等待导致超时 |
| 受限/待核验 | 可卖不足、整手、资金、权威状态缺失或其他已知约束 |
| 模型不兼容 | 新数据、账户或价格口径未通过相应绑定校验 |

当资料不足时应输出“等待/待核验”，而不是全现金目标或强制清仓。行情陈旧时可以保留上一次有效计划供只读查看，但必须带原时间，不继续显示为新的可行动判断。

首版不宣称可靠估计可成交股数。若增加数量参考，必须在复制账户上复用 broker 的费用、资金、整手等规则，并单独注明报价、时点与未覆盖限制。没有盘口、权威状态或公司行为时，不能给出“可执行”保证。

## 10. 最新判断页面

在“动作预测”中增加“历史推理 / 最新行情”模式，保留原历史功能。最新模式包含：

- 模型、原训练口径、新数据绑定、完整股票池和账户来源。
- “准备最新日线”“刷新报价”“生成日线计划”“开启/停止监控”四个不同操作，不合成一个不透明按钮。
- 计划生成只在显式请求或预先授权的完整日线更新后发生，不能因每次刷新价格自动重训或重新选模。
- 顶部同时展示特征日、计划时间、报价时间、接收时间、市场状态及兼容等级。
- 股票表展示现有/目标仓位、参考调整金额、持仓/可卖、判断状态、数据时效和阻止原因。
- 原始报价、研究模型目标与真实账户参考量级使用明确列名，不共用含糊的“价格”“动作”字段。
- 数据失败时展示最近成功快照和失败原因，旧结果降级为历史查看；输入或绑定变更后立即清除不匹配结果。

模型池外的持仓不得被忽略；需要补足账户范围或先完成显式迁移。当前页面仅显示部分股票时，组合净值和目标现金仍按完整账户计算。

## 11. 任务、限流与故障处理

拟新增历史下载、报价抓取、推理绑定构建、日线计划生成和行情监控任务类型。训练重任务与网络刷新不能无限竞争一个队列，需分别设定小额并发上限；不与训练共享同一可变 PPO 对象。

每类任务明确：连接/读取超时（接口支持时）、总墙钟上限、有限重试、退避、最小刷新间隔、请求计数和取消机制。供应商 SDK 未暴露可靠超时时，用受管工作进程总时限兜底，不全局 monkeypatch HTTP，也不关闭证书验证。

请求失败不触发无限重试，不改用未经确认的其他口径/供应商。遇到限流、认证、验证码等问题明确停止并提示，不绕过访问控制。网络错误不能退回模拟报价后继续标为实时。

监控使用幂等会话 ID、心跳和有限租约。模型推理排队时间也计入新鲜度；执行前再次检查快照是否过期，过期则取消本次判断。停止任务只操作自己拥有的进程，不终止其他训练或系统进程。

## 12. 拟新增接口与模块

以下为设计接口，尚不可调用：

| `GET /api/market/providers` | 可用来源、支持口径及能力/时间字段说明 |

所有写操作继续使用本地会话校验、幂等键和后端 schema。请求只接受登记的来源、股票和参数，不接受任意 URL、脚本或文件系统路径。

| 拟新增/调整位置 | 职责 |

| `src/inference/binding.py` | 新数据与旧模型的显式兼容路径，不修改默认加载契约 |
| `src/inference/live.py` | 计划与时价检查分离、时效门控、参考意图 |
| `src/web/worker.py`、任务存储与 schema | 新任务、网络限流、监控租约和取消 |
| `web/src/` | 联网采集表单、最新模式、时间/状态展示和阻止提示 |
| `tests/test_online_*.py`、`test_live_*.py` | 模拟网络、价格口径、泄漏、陈旧数据和监控生命周期 |

现有 `DataFetcher` 和核心类优先复用，网络调用参数须按实际签名传递，不能再次引入不支持的关键字。旧数据与模型路径不改名，不删除原有离线能力。

## 13. 实施顺序与验收

任务勾选集中维护在 [实施进度](implementation_plan.md)。拟按以下顺序执行：

1. 提交现有工作台功能和验收记录，建立清晰基线；本次依用户最新要求先写方案，尚未执行该提交。
2. 核验来源接口及时间/单位含义，接入独立历史/报价快照、限流、取消与审计。
3. 实现新日线的模型推理绑定和研究目标计划，保留原 scaler 与加载契约。
4. 接入页面手动联网和报价查看，再增加有时效门控的有限监控会话。
5. 完成独立真实账户口径适配及历史/纸面验证后，启用相应仓位偏离参考；未通过的模型继续仅允许行情/研究模式。
6. 进行少量真实连通验收、完整离线回归和浏览器测试，记录失败与限制后更新文档。

### 离线测试

- 后复权与未复权字段/文件不能混用，重复日期、单位异常、部分失败和历史修订可追踪。
- 新数据推理不拟合 scaler，历史重放满足特征和动作一致性；改变未来数据不改变截至 t 的结果。
- 不完整当日日线不进入原 PPO；没有行情时间不能伪造；陈旧或缺失关键持仓报价阻止当前判断。
- 网络故障不覆盖上次有效快照，不自动清仓，不产生模拟的“实时”结果。
- 同一快照/账户/计划的确定性结果一致，显示单股不改变完整池推理。
- 不支持的价格/账户口径被拒绝，真实股数绝不乘以后复权价估算现实账户。
- 自动刷新只在有效租约与用户授权范围内运行，取消和超时不影响其他任务。

### 联网与浏览器验收

联网用例单独标记，不并入默认离线测试。先以极小股票集合检查真实下载、字段、口径和报价时间，再按所选模型的完整池验证；不因为少量接口通了就宣称整个实时链路可靠。

浏览器验收包含：下载提交/取消/重试、原始数据不变、缓存/陈旧标记、行情与策略日期区分、完整池校验、断网后的等待状态、停止监控、输入变化清除旧判断，以及现有训练/历史回测不回归。

真实供应商不可用、缺少时间字段或数据不完整时，报告如实记录阻塞项，离线 mock 通过不能替代真实连通证据。验收不提交真实订单，不用新判断的收益挑选策略。
