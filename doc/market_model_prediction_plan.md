# 联网行情与多模型预测整合设计

日期：2026-09-27。状态：首版已实施，包含新浪默认日线、历史图表与最多三模型单日研究意图、已有验证报告；连续账户回放、自动结果缓存和真实账户建议仍未完成。验收见 [本轮报告](reports/market_model_integration_20260927.md)。

## 已实现与使用

审查后修复：未持有股票的缺失特征复用训练观察器掩码，不再因任意一只缺特征阻断全池；已有缺失持仓、全池无效或缺指定收盘日线仍阻断。真实300股单日目标与原预测接口已一致，详见 [修复验收](repository_audit_fixes.md)。

入口为“联网行情 → 行情与模型”。先选择本地快照或关联快照的数据版本，再选择最多三个已保存模型、收盘日、明确的全现金/持仓比例情景及研究确认。点击“检查输入”只做来源、股票覆盖和指定日期预检；点击“生成多模型研究意图”才逐模型排队推理，特征完整性和历史修订由任务最终校验。

点击 K 线、成交量柱或收盘曲线可以选取日期，不会自动生成预测。成功结果在该收盘日显示目标权重标记，下方展示当前→目标、买入/减仓/退出意图、完整股票池与现金。标记的价格仅为图示收盘参考，非成交价。切换显示股票不改变模型全池决策。

已有验证表现仅按实际加载模型的 SHA256 匹配 `val` 报告，保留报告中的 PPO 与基线指标和净值图，不自动评估，不把不同账户/区间报告合成排行榜。页面离开后可在任务记录找到已保存结果；自动跨会话恢复图层尚未实现。

默认从新浪下载日线；失败只在同源内有限重试，不自动退到东方财富。采用模型股票池同时采用其已认证来源并清除下载授权。重试旧批次保留原来源。东方财富报价/监控需独立授权，且不得绑定新浪模型；新浪实时适配尚未实现。扩展资料仍按各接口的真实来源提供，默认选新浪分红记录。

新接口：`POST /api/market/model-comparison/preflight`、`POST /api/market/model-comparison`、`GET /api/market/model-performance/{model_id}`。状态接口提供 `default_history_source`、`sources`、`quote_source` 和 `market_ui_version`。任务保存模型/快照/scaler 哈希、假设仓位、收盘日与不可执行标记；工人再次核对来源和哈希。

## 目标

在同一行情工作区选择股票、历史区间、收盘决策日期和模型，将K线/收盘曲线、模型目标仓位、买卖意图与已验证的历史表现放在一起。用户可以比较不同模型，但不得把研究信号包装成现实可成交订单，或把事后回放当成当时可获得的预测。

## 页面安排

保留“行情 / 下载管理 / 扩展资料”的清晰分工，以实际行情和研究信号为主体，不增加介绍式首页。

- 顶部筛选：股票、数据供应商、不可变批次/数据版本、HFQ或未复权展示口径、历史范围、收盘日期。
- 模型区：默认一个模型，最多三个；显示模型ID/简称、策略类型、训练截止、验证范围、训练来源、价格口径和研究资格。旧PPO、R1及以后新增类型按真实契约展示，不能只写“模型1/2”。
- 主图：现有K线/曲线，允许勾选各模型信号图层；共同时间轴，下方为成交量与目标/实际仓位曲线。不把多个模型的标记无区别地叠在同一个点上。
- 侧栏或下方：选中日期的各模型结果、当前与目标权重、变化量、研究方向、有效数据日期、阻断原因。
- 全池配置表：每个模型完整股票池的目标权重和现金，不仅展示当前这只股票。筛选显示股票不能偷偷变更模型决策股票池。
- 历史表现页签：使用独立净值副图和指标表；原始股价与策略净值单位不同，不共用同一纵轴。标记回测区间与费用假设。

移动端上下排列，日期游标与模型选择共享状态；工具按钮使用已有图标，图例可折叠，表格允许横向滚动。研究属性、来源与截止日期必须可见，不藏在提示框中。

## 预测和建议的含义

PPO 输出目标配置，不是未来股价，也不提供经过校准的上涨概率。页面不画臆造的未来价格线，不把潜在分数/不同种子一致性当成置信度。

| 条件 | 可展示的方向 | 限制 |
| --- | --- | --- |
| 目标权重大于当前 | 买入/加仓意图 | 不等于一定成交 |
| 目标权重小于当前且仍大于零 | 卖出/减仓意图 | 区分意图与可卖股数 |
| 有持仓且目标为零 | 退出意图 | 停牌、跌停等可能阻止执行 |
| 权重变化很小 | 目标基本不变 | 不称“完全不下单”；当前PPO仍可能再平衡 |
| 没有持仓、目标为零 | 不配置 | 不应显示卖出建议 |
| 输入缺失、不兼容或过期 | 暂不生成建议 | 不能伪装成模型建议空仓或清仓 |

未输入账户时，只展示目标权重与排名；或者由用户明确选择“假设全现金”，并持续显示该假设。不能凭空推断用户已有持仓并显示卖出。

现有 `hfq_research` 模型只输出“研究买入/减仓/退出意图”和假设资金下的参考金额，不提供真实股数、现实买卖价或可执行订单。真实股数建议须等同源未复权价格、公司行为、可用现金/可卖数量、交易状态及真实账户适配通过验证；届时也只是参考数量，下一开盘价格、手续费和滑点仍可能改变成交。

## 图表时间与回放口径

1. `t` 日收盘信号标在 `t` 日，含义为下一交易时段配置意图。不得把次日成交价写成当天模型已经知道的买价。
2. 真实回测成交另设标记，使用实际模拟成交日期/价格；颜色、图例与模型意图区分。HFQ模拟成交只能标在同口径图上。
3. “单日预测”按所选日期构造观察，不推进到次日，不计算未来收益。
4. “历史策略回放”从用户确认的初始账户出发，每个模型独立维护账户，逐日收盘决策、次期开盘执行。不能每天把账户重置为全现金后串成一条所谓回测。
5. 事后加载的模型在历史日期发出信号，应标为“回溯推理”；展示其训练截止及是否使用该区间选模。训练期内的信号不标作样本外预测。
6. 最新计划沿用指定收盘日期、逐股完整性及采集时间闸门。16:00是本系统保守缓冲，不是数据终稿或交易日历认证。
7. 已知保留区间不因拖动图表或勾选模型自动启动绩效评估。回放跨越受保护区间时阻断，走现有冻结与显式确认流程；历史价格展示与一次单日研究推理不等于授权执行最终测试。

## 多模型比较

- 同一决策日期、同一价格/费用与初始账户场景，才提供可直接比较的绩效。默认复用已有相符报告；没有相符报告时显示“未评估”，而非套用其他区间收益。
- 每个模型使用自己的训练 scaler、特征顺序和窗口，禁止为了“对齐”而重拟合或互换 scaler。
- 全池不同、训练来源不同或真实/HFQ账户不同的模型可分栏查看，但不自动合并曲线排行、平均目标权重或投票生成交易指令。扩池/缩池必须显式迁移并重新评估。
- 多种子不是独立市场证据。同源同先验的模型结果相近，不构成高置信度。
- R1要同时显示较强的20日动量基线，并保留初始化先验对照；不能只与较弱旧PPO比较后宣布最优。
- 建议来源可解释到配置规则和数据：例如R1的20日动量排名、最多20股与5%上限。没有归因方法时，不生成“因为机构买入/即将上涨”等叙述。

## 数据源能力模型

拟以统一的供应商能力表替代顶层单一 `provider` 字段，例如每个来源记录 `history_bases`、`quotes`、`supplement_types`、时间语义、单位和适配版本。现阶段只声明真实已实现的能力：新浪日线、东方财富日线/报价及逐项扩展资料；腾讯不得因探测连通就标成完整训练源。

选择模型后，根据 `contract.data_source` 推荐并绑定其日线源，同时显示不可用能力。旧模型来源未知时显示“来源未认证”，不能从文件名猜成东方财富或新浪。来源切换清除未提交的联网许可，并重新执行兼容检查。

批次、下载任务、图表、模型卡片与信号结果都显示实际供应商；日线源和报价源分开标注。读取本地批次、换模型、拖动图表不能自动下载。缺数据时给出所需代码/口径/历史锚点的清单，由用户确认下载。

## 拟新增服务契约

以下保留完整目标契约；首版可用接口和边界见本文开头，未列出的历史回放与自动缓存仍待实施：

- 来源能力接口：替代/扩展 `/api/market/status`，保留旧字段兼容期，但不再用其描述全部来源。
- 多模型预检：接收模型ID列表、历史批次、收盘日、显示股票及账户模式，返回逐模型兼容性和具体缺项。
- 预测任务：显式提交后生成不可变结果，包含 `model_id/model_hash`、来源/批次哈希、scaler/特征契约、决策日、账户快照哈希、逐股权重、方向和 `actionable`。首版所有HFQ结果均为false。
- 历史回放任务：额外要求区间、初始账户和评估许可，沿用现有任务队列、取消与预算；逐模型隔离状态。一个模型失败不能丢失其他已完成结果。
- 信号查询：按不可变结果ID读取图层；绘图请求不触发训练、下载或回测。缓存键包含模型/数据/账户/日期/特征与实现版本，不能只按股票和日期缓存。

后端最终校验所有兼容条件，前端预检不能替代安全约束；用户输入的ID必须解析到已登记可信目录，保留本地CSRF防护。
