# 对齐基准超额的 PPO 小模型试验

日期：2026-11-06
状态：**机件完成并通过自检；奖励改动在小样本上没有产生预期效果。**
关联：[alpha 度量](alpha_measure_20261106.md)、[alpha 计划](alpha_program_20261106.md)

这一轮做了三件用户指定的事：把奖励改成**对基准超额**、先用**小模型**试验、**每个 checkpoint 都做一次回测**。
结论：前两件按设计完成了，但结果是一个诚实的零。

---

## 1. 改了什么

### 1.1 奖励

`src/envs/trading.py` 新增 `reward_mode`：

| 模式 | 奖励 |
| --- | --- |
| `return`（原样，默认） | `equity_t / equity_{t-1} - 1` |
| `excess_pool` | 上一项 − **同区间等权全池收益** |

基准的定义写死在 `TradingEnv.benchmark_return`：用决策日的 `valid` 掩码（智能体当天真正能买的名单）、
在同一 ffilled 估值序列上、按 `close_t → close_{t+1}` 计等权平均收益。停牌股按上一个收盘计入，
贡献 0 收益，与真实持有该股的结果一致。

`info` 同时暴露 `raw_return`、`benchmark_return`、`excess_return`，所以日志里能随时拆开看，
不必猜奖励到底是什么。

> **先读第 8 节。** 这一节的两次运行后来被发现受"整手不可分"混淆：1,000,000 本金下连等权参考
> 自己都只能投出 71%、持有 28.8% 现金。第 8 节把本金提到 300 万重做了 A/B，并给出最终结论。

### 1.2 每个 checkpoint 一次完整回测

`src/training/train.py` 新增 `CheckpointBacktest`：每 `checkpoint_every` 步

1. 把当前权重存到 `checkpoints/step_XXXXX/`
2. 在**验证切分**上跑一次完整回测（`run_policy`，含整手、佣金、印花税、滑点）
3. 与参考组合 `equal_weight_daily` 比较，追加一行到 `checkpoints.csv`

参考组合每个 run 独立重算一次并缓存，所以它是同一把尺子，不是每步重估。

`tools/checkpoint_compare.py` 把多个 run 的检查点并排成表与图。

### 1.3 试验设置

| 项 | 值 |
| --- | --- |
| 股票池 | 32 只（轻量档） |
| 模型 | `SharedStockNetwork` 128/64，`lookback=1`，无动量先验 |
| PPO | `n_steps=256`，10 epochs，4 seeds 固定 42 |
| 步数 | **8,192**（32 个 rollout） |
| 检查点 | 每 256 步一次，**每个 run 32 个** |
| 训练切分 | 2017-01-02 ~ 2022-08-05 |
| 验证切分 | 2022-08-05 ~ 2023-10-20，**291 个决策日** |
| 参考组合 | `equal_weight_daily`，同期 **+12.83%** |

两个 run 只有奖励不同，其他完全一致：`excess_8192_01`（超额）对 `return_8192_01`（原始收益）。
**没有对照就不能把差异归给奖励**，所以对照必须跑。

## 2. 结果

| | 超额奖励 | 原始收益（对照） |
| --- | ---: | ---: |
| 最终组合收益 | +10.15% | +11.29% |
| 参考（等权日频） | +12.83% | +12.83% |
| **最终超额** | **−2.68%** | **−1.53%** |
| 32 个检查点的超额均值 | −1.66% | −2.23% |
| 检查点间标准差 | 0.66% | 0.88% |
| 最好 / 最差 | −0.08% @512 / −2.98% @6912 | −0.28% @7168 / −3.62% @2816 |
| 平均现金比例（首→末） | 32.4% → **27.6%** | 32.1% → **26.0%** |
| 最终跟踪误差（日） | 1.73% | 2.27% |
| 期间费用 | 1.60% | 1.62% |

两个 run **都没跑赢等权池**。这就是全部。

---

## 3. 为什么没跑赢：拆开看

把最终收益拆成三块（参考 +12.83%，期间 291 个交易日）：

| 分解 | 超额奖励 | 原始收益 |
| --- | ---: | ---: |
| 按同样现金比例复制等权池 `(1−c)·12.83%` | +9.28% | +9.49% |
| 策略实际收益 | +10.15% | +11.29% |
| **超出「同比例复制」** | **+0.86%** | **+1.81%** |
| 其中费用 | −1.60% | −1.62% |
| 现金拖累（相对满仓池） | ≈ −3.3% | ≈ −3.3% |

所以那 −1.5% 到 −2.7% 的差额**主要来自约 26% 的现金和 1.6% 的费用**，不是选股选错了。
投资部分相对「同比例复制」是**正的**，但 +0.9% / +1.8% 在 291 天、跟踪误差 1–2%（日）的量级上
只是噪声——检查点之间的标准差本身就有 0.7–0.9%。

曲线图在 `reports/runs/ppo_checkpoints_20261106/checkpoints.png`（`reports/runs/` 不入 Git，需按第 6 节重跑生成）。
看曲线比看终值更清楚：**两条超额曲线在 32 个检查点里都没有抬升趋势**，全程在 −0.1% 到 −3.6% 之间来回，
而现金比例的中位路径两者几乎重合。超额奖励的均值确实略好（−1.66% 对 −2.23%），
但 0.57 个百分点的差距小于检查点自身的标准差，且两条曲线多次交叉——**不能算效果**。
唯一稳定分化的是一条：跟踪误差，超额奖励全程更低。

## 4. 三件必须说清楚的事

### 4.1 奖励没有产生它应该产生的行为

`excess_pool` 的梯度很明确：持现金而池子上涨就是必然的负超额，所以**现金应该被压到 0**。
实测：超额奖励把现金从 32.4% 压到 27.6%，而**原始收益对照压到了 26.0%**——对照反而更满仓。
也就是说，这个改动没有做到它唯一该做的事。

唯一看得见的效果是**跟踪误差降了约 40%**（1.73% 对 2.27%）。这是可预期的：以「对池子超额」为奖励，
最大值就在池子本身，所以它把策略往**复制指数**的方向拉。对一个要找 alpha 的模型，这是反向的。

### 4.2 现金 27% 主要是初始化，不是学出来的

第一个检查点（256 步）现金就已经是 32%。原因：本次配置**没有动量先验**，`stock_head` / `cash_head`
是随机初始化的，所以初始 softmax 并不是均匀分布。之后 8,192 步只把现金挪动了 5 个百分点。
**训练量太小，不足以把初始化推走。**

### 4.3 8,192 步不构成对这个假设的检验

32 个 rollout × 10 epochs = 320 次梯度更新。这个量级下任何结论都读不出来。
再加上本轮前面已经测到的事实：输入的 20 个价格特征在长样本上 `|IC| ≤ 0.035`，
**模型没有东西可学**。所以这次试验检验的是**机件**，不是**假设**。

## 5. 这个奖励设计本身有个缺陷

`excess_pool` 把两个不同的问题混进了一个标量：

```
奖励 = 组合收益 − 全池收益 = [敞口决策] + [选股决策] − 满仓池收益
```

后果是它给出一个**「只要满仓就对了」**的梯度，而选股部分被淹没。两条更干净的替代：

| 方案 | 基准 | 优点 | 缺点 |
| --- | --- | --- | --- |
| (a) 敞口中性 | `(1−现金比例) × 池收益` | 只度量选股，现金不奖惩 | 全现金时奖励恒为 0，存在退化解 |
| (b) **强制满仓** | 池收益 | 超额**就是**选股，无退化解 | 必须去掉现金动作 |

我倾向 **(b)**：把 `softmax` 的现金维去掉、权重归一化到 1，再对池子取超额。
这样「超额」与「选股」是同一件事，不会再有现金拖累混进来。这需要改动 `action_mapping`，是一次结构改动，
所以先提出来而不擅自做。

## 8. 后续：按决策实现「强制满仓」（影子 (b)）

用户选定 (b)。实现如下，并在此记录结果。

### 8.1 改了什么

`action_full_invest: true` 打开后：

- 动作变成 **N 个潜分数，没有现金维**；`cash_head` 不再构建（不留死参数）
- `cap_to_one`：softmax 归一化到 1，超过单只上限的名字冻结在上限，剩余预算按比例再分配，
  循环到没有超限为止
- **不可行时如实上报**：可买只数 × 上限 < 1 时，缺口留在现金里并标 `feasible=False`，
  由 `cash_weight` 暴露，不假装投满
- 映射版本 `masked_softmax_cap_full_invest_v3`，契约里同时记 `cash_semantics`
- `initial_capital` 支持配置覆盖（原因见 8.2）

### 8.2 先撞上一个更重要的问题：账户买不满，不是策略不想买

第一次跑（100 万本金、30 只可买）目标权重合计 **1.0000**、`cash_weight = 0`、`feasible=True`，
但回测里实际现金始终是 **32%**。查下去发现：

- 该数据集用的是 **HFQ 研究价格**，不是真实成交价。HFQ 价格中位 128.8、最高 **1697.5**
- 30 只里 **7 只**的一手（100 股）成本超过单只的 1/30 资金（33,333）
- 于是 7 笔直接被整手约束拒单，只剩 67% 能投出去

**关键点：参考组合 `equal_weight_daily` 在同样本金下自己也持有 28.8% 现金、只买了 23.9 只。**
所以这不是策略的问题——**整手不可分性先于策略发生**，两侧被同一个约束卡住。
这也意味着上一轮"现金拖累约 3.3%"的归因**有一部分是错的**：那不是策略选择持币，是买不了一手。

修法是把本金提到 **300 万**（此前手数研究本来就建议的可用资金量），现金比例随即从 28% 降到 11%。

### 8.3 结果（同为 300 万本金、同一参考 +9.98%）

| | 强制满仓 | 现金模式（对照） |
| --- | ---: | ---: |
| 最终组合 | +6.91% | +8.19% |
| 现金比例 | **10.9%** | 13.0% |
| 按同比例复制池子 | +8.89% | +8.68% |
| **超出同比例复制** | **−1.98%** | **−0.05%** |
| 期间费用（占本金） | **1.91%** | 0.87% |
| 最终跟踪误差（日） | 2.73% | 1.40% |

把费用加回去看毛额：强制满仓 **−1.98% + 1.91% = −0.07%**，也就是**毛额上它正好等于同比例复制池子**；
现金模式 **−0.05% + 0.87% = +0.38%**，略正。

**结论：强制满仓确实把现金从 28% 压到 11%、把部署率提到 89%，但它买到的东西是零，代价是费用翻倍。**
满仓迫使每天都把权重拉回 1，换手和费用随之上去；在没有选股能力的前提下，
偏离池子只是把噪声和成本加上去。

### 8.4 这个结果支持什么、不支持什么

- **支持**：现金模式在 3M 上基本就等于复制池子（−0.05%），说明策略确实没学到东西——与前面
  "输入特征 |IC| ≤ 0.035" 一致。
- **支持**：`excess_pool` 在强制满仓下确实更接近"纯选股"了（现金 10.9% 对参考的整手底线同一量级），
  口径问题解决了。
- **不支持**：不能说"强制满仓更好"。它更干净，但在这批特征上更贵。
- 仍受限：**HFQ 价格不是成交价**，"一手"在这里没有真实含义；真实资金下的整手约束要重算。
