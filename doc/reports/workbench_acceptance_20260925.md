# 本地研究工作台实施与验收记录

日期：2026-09-25。设计提交：`039e04c`。运行入口与功能边界见 [工作台运行说明](../workbench_runbook.md)。

## 实现范围

已接通本地数据版本/股票选择、独立进程训练、实时事件和日志、模型保存/选择/命名、共同基线回测、持仓订单查看、冻结、股票池迁移、历史动作预测和账户快照复用。页面提供桌面与窄屏布局，没有引入实盘、自动行情下载或外部任务队列。

后端复用原训练、账户、成交及指标实现，补充 FastAPI、SQLite 队列、SSE、可取消 worker 和只读观测构造。所有任务使用服务所在的 Graduate 解释器，重任务执行槽通过事务认领。

## 已发现并修复的问题

| 检查阶段 | 问题 | 修复 |
| --- | --- | --- |
| 初次构建 | 新版 TypeScript 找不到 CSS 副作用导入声明 | 增加 Vite 类型声明，构建通过 |
| Python API 测试 | Windows asyncio 的内部回环连接被全网络拦截器误拒绝 | 仅对标记的本机 IPC 测试开放数值 loopback，新增外部地址仍被拒绝的检查 |
| 首轮浏览器 | 账户来源选择器的标签定位不明确 | 表单控件统一提供显式可访问名称，保留可见标签 |
| 截图复核 | 打开历史预测时，上方表单仍显示默认日期/账户 | 恢复对应快照、关注股票与日期；修改输入清除旧结果 |
| 推理展示 | 市场卖出允许容易被理解为账户可以立即卖出 | 单独展示持仓/可卖股数，并把方向掩码标为市场状态 |
| 进程恢复检查 | worker 导入期间尚无心跳，重启可能误判任务已死 | 添加启动宽限期；无可确认进程的任务中断，不自动重训 |
| 并发检查 | 多个本地服务实例可能争抢同一排队任务 | 使用 SQLite 即时事务认领，整个工作区保持单重任务槽 |
| 连接恢复 | 服务重启后旧本地会话 token 可能失效 | 只对 token 失效刷新会话并重试一次，保留原幂等键 |

## 已完成的优化

- 只加载折线图实际使用的 ECharts 模块，图表拆成按需分块；首屏 JS 从约 1,393 KB 降至约 279 KB，gzip 约 86 KB。
- 保留图表实例，只在数据改变时更新，避免轮询导致画布重建与交互闪烁。
- 回测/推理 worker 沿用配置中的 CPU 线程数，数据构建不提前导入整套 PPO。
- 数据构建增加取消边界，成功前不发布新版本；训练取消不会继续伪装成成功保存和最终比较。
- 补充保存账户复用、持仓明细、日志下载及真实参数更新审计展示。
- 新增前端格式化规则与锁文件，保留 CLI 入口和直接预处理脚本兼容性。

## 已知限制

当前是单机研究工作台。精确续训、多用户权限、任意存储区、全部超参数编辑、完整账本导入与超长日志分段读取尚未实现。手工账户表单只编辑一笔应收，多笔已存快照可只读复用。图表惰性分块仍有 500 KB 阈值提示，保留为后续体积优化项。

本轮 UI 验收产生的短训练模型、重复验证报告及 `web_check_*` 数据版本只用于功能测试，不取代已有轻量研究报告，也不是新的策略有效性结论。
