# PPO 网络容量与 CPU/GPU 对照（2026-09-27）

## 结论摘要

- 已实际训练原网络 `128 -> 64`（40,901 参数）及大网络 `1024 -> 512`（2,391,557 参数，约 58.5 倍），不是仅运行前向传播。
- CPU 不是普遍更快。大网络固定 40 次优化器更新时，seed 42 的 CPU/GPU 训练分别为 27.95/8.38 秒；参数更新分别为 20.17/1.04 秒。
- 单个串行 CPU 环境的逐步采样限制端到端加速。小网络两个种子的总耗时排名相反，不能据此确定设备优劣。
- 扩大网络没有证明策略效果改善。保留 KL 阈值的大网络每次仅完成 4 次更新；原学习率不适合直接照搬。固定更新量实验放宽 KL 约束仅用于测速，不是建议的生产训练配置。
- 不下载数据，不使用最终测试集，不替换生产默认参数或已有模型。所有结果均为短训验证，不能作为实盘能力证明。

## 数据与方法

沿用 `research_multiseed_20260926` 的 19 股、20 特征、lookback=1、训练期独立拟合 scaler。训练交集为 2018-10-18 至 2022-08-05，验证交易期为 2022-08-08 至 2023-10-20。数据、价格口径及交易约束均未修改。

环境为 AShareGPU，PyTorch 2.7.1+cu126，RTX 3050 Laptop 4 GB，驱动 566.36。CPU 设置 `torch_threads=1`，并非尝试所有线程数后得到的最优 CPU 成绩。

每个计时样本训练 2048 步，n_steps=512，batch_size=256，n_epochs=5，学习率 3e-4，种子 42/123。相同种子下先后运行 CPU/GPU，并在第二个种子反转设备顺序。每次使用独立新模型与环境；先用丢弃的模型完成一轮 rollout 和 PPO 更新预热。

计时边界执行 CUDA synchronize。分别计量 `collect_rollouts` 与 `train`，总训练计时不包含数据加载、模型初始化、预热、保存和验证。不使用生产 ValidationCallback，因此也不包含生产工作台的完整诊断开销。验证单独执行，仅评价最终模型，不通过验证挑选 checkpoint。

仍有限制：只有两个种子、共享机器负载、未控制电源/温度/时钟，没有同一 seed 多次统计重复；CPU/GPU 浮点与采样轨迹不保证相同。训练初始环境总从历史开头开始，2048 步不是充分训练预算。

## 第二轮：固定大网络更新工作量

仅此计算实验设置 `target_kl=1e6` 为实际不触发的阈值，并断言每次恰好完成 40 次优化器更新。其余设置不变。该设置不用于选择生产模型。

| Seed | 设备 | 训练总秒 | 采样秒 | 更新秒 | 更新次数 |
| --- | --- | ---: | ---: | ---: | ---: |
| 42 | CPU | 27.95 | 7.78 | 20.17 | 40 |
| 42 | CUDA | 8.38 | 7.32 | 1.04 | 40 |
| 123 | CUDA | 9.64 | 8.31 | 1.31 | 40 |
| 123 | CPU（单独重跑） | 84.18 | 18.38 | 65.79 | 40 |

seed 123 的原始 CPU 样本（35.24 秒）与离线回归测试短暂重叠，不用于速度结论；另行单独重跑，保留原始记录而非覆盖。

单独重跑反而更慢，且同一轮的更新阶段从约 5 秒变为约 20 秒；本次未测定原因，不能断言是温度、系统负载或调度中的哪一种。其验证结果与原始 CPU seed 123 完全相同。该现象意味着不能宣称稳定的硬件加速倍数，更不能把较慢重跑结果用于夸大 GPU 优势。较可解释的 seed 42 配对约为 3.34 倍端到端、19.33 倍更新阶段加速，也只代表本次样本。

重跑记录：[独立 CPU seed 123 审计](../../reports/runs/capacity_fixed_20260927/h1024_512_cpu_123_repeat/audit.json)。固定更新量各模型的验证收益为 13.52% 至 14.95%，仍没有证明大网络优于第一轮小网络；此处同时改动了 KL 条件，不能作为纯模型容量的效果实验。

GPU 大网络峰值 PyTorch allocated 显存约 163.4 MiB，不是整机或驱动总占用。当前并未接近 4 GB 显存容量上限，但增加股票数、窗口和 batch 后需要重新测量。

原始记录：[固定工作量汇总](../../reports/runs/capacity_fixed_20260927/summary.json)。注意该汇总保留含干扰的原始 CPU seed 123 样本，重跑另存。

## 当前 Agent 的行为

1. 输入逐股标准化行情特征、当前持仓/现金比例、待结算比例、有效/可买/可卖标记。
2. 共享 MLP 为每只股票与现金生成连续分数。训练时使用高斯随机采样，通常推理时取确定性动作。
3. 动作经截断、有效且可买掩码、softmax、逐股仓位上限转换成目标比例。上限截出的资金留作现金，不再次分配。19 股各最多 5%，所以理论股票总权重不超过 95%。
4. 当日收盘观察后提交目标比例，下一交易日开盘由 broker 按资金、价格和持仓计算股数，先卖后买；下一收盘资产变化形成奖励，费用和滑点计入资产。
5. 可表现为买入/加仓、卖出/减仓、实际清仓、提高现金或不成交。但没有独立离散的 BUY/SELL/HOLD/CLEAR 动作，没有显式“今天完全不下单”的策略输出。保持目标权重也可能因价格变化触发交易。softmax 对合格股票一般产生正权重，因此清仓常依赖极小权重折算股数为零，而非明确的清仓开关。
6. 实际成交受 T+1、100 股买入单位、可交易/涨跌停条件、现金和成交量上限影响。目标动作不等于已成交订单。

不支持做空、杠杆、限价挂单、撤单、日内择时或实盘自动下单。当前研究数据仍用 HFQ 价格执行模拟，复权价与一手约束的现实偏差没有被扩大模型解决。

## 后续方向

- 大网络训练优先继续验证 CUDA，但不要把这次倍数外推到所有 batch、股票池或工作台完整流程。
- 保留 KL 保护，先降低大网络学习率，观察实际更新量、KL、clip fraction 和验证成本；不以关闭保护作为提升策略效果的方案。
- 分开设计明确不交易/清仓机制与调仓阈值，先验证是否减少无意义的小额调仓。此轮未改变动作空间。
- 先解决未复权成交价、公司行为与购买力输入，再研究时序网络或更长窗口；宽 MLP 仍只看一天特征，没有因此获得长期记忆。
